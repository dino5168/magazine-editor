對應原始檔 src/lib/editor/types.ts（2026-10-01 型別重構，檔案格式 schemaVersion 3；本頁和 types.ts 在同一個 commit 更新，用 git log -1 -- docs-website/types.html 查編號）· 本頁更新於 2026-10-01

這一頁說明型別的結構與關係；「為什麼這樣設計」（例如為什麼用 pt、為什麼不存 scale）會寫在 docs/03-document-model.md（撰寫中）。

重點摘要

  • 長度單位一律是 pt（1/72 inch，和 Typst 相同），座標原點是頁面左上角。
  • types.ts 裡沒有任何 class，只有 interface 和 type。它們只描述資料的形狀，編譯成 JavaScript 後會完全消失。
  • 所有欄位都是 readonly：修改資料時會產生新的物件，舊版本保留下來給「復原」使用。
  • 物件種類靠 type 欄位區分（"text"、"shape"、"image"），不是靠繼承。
  • 所有圖形（矩形、橢圓、多邊形、星形）都是同一種 ShapeElement：共用外框、填色、邊框、圖形內文字，差別只在 geometry（再用 kind 欄位區分）。
  • 每種物件的 x / y 都是外框的左上角，旋轉也繞這一點。
  • 文件的結構是一棵樹：EditorDocument → Page → CanvasElement。

型別關係圖

點擊方框可以跳到該型別的說明。方框裡只列出該型別自己宣告的欄位：三種 Element 都 extends BaseElement（id / x / y / rotation），TextElement 與 ShapeLabel 另外 extends TextStyle（字型欄位），這些都不重複列出。

  • 文件資料：會進入復原歷史
  • UI 狀態：不進入復原歷史（虛線框 = 定義在其他檔案）
  • 別名與衍生型別：由其他型別計算出來
  • 計算用的值：函式參數與回傳值，不存在文件裡
  • 組合：菱形那一端「擁有」另一端
  • · extends Xextends（寫在方框的標題列）：把 X 的欄位複製進來
  • union 成員：CanvasElement 是這幾種之一
  • 依賴：箭頭起點由終點推導出來
  • type: "text"區分物件種類的欄位（discriminant）
  • 1..* / 0..*數量：至少 1 個 / 可以是 0 個

x / y 的定位點

每一種物件的 x / y 都是外框（旋轉前）的左上角，旋轉也繞著這一點轉。圖形的大小一律用 width / height 描述：橢圓、多邊形、星形都畫在這個外框裡，多邊形與星形的頂點會拉伸到碰到外框四邊。

2026-10-01 之前（檔案格式 v1 / v2），橢圓、多邊形、星形以中心點定位、用半徑描述大小。開啟舊檔時由 Rust 自動換算成外框，旋轉過的圖形也會留在原位。

CanvasElementunion type

「畫布上的任何一個物件」，是三種 Element 其中之一：

ElementPatchtype

type ElementPatch = Partial<DistributiveOmit<CanvasElement, "id" | "type">>;

修改物件時傳入的「只包含要改的欄位」的物件，例如 { fontSize: 24 } 或 { x: 10, y: 20 }。id 和 type 不能改。以下行為都用 tsc 驗證過：

寫法結果
{ fontSize: 12 }✅ 通過
{ id: "x" }❌ 報錯：id 不能修改
{ fontSize: 12, height: 3 }⚠️ 也會通過（fontSize 屬於文字、height 屬於圖形）。patch 不檢查欄位是否屬於同一種物件，要靠 UI 只送出正確的欄位
{ stroke: { …, width: 0 } }✅ 編譯通過，但 reducer 會忽略這次修改：fill、stroke、label、geometry 與數字欄位在執行時另外驗證（validation.ts，規則和 Rust 讀檔時相同）

stroke、label、geometry 是物件，patch 會整個取代，不會合併。要改邊框顏色時寫 { stroke: { ...shape.stroke, color } }。

DistributiveOmit<T, K>type · 未 export

type DistributiveOmit<T, K extends PropertyKey> = T extends unknown ? Omit<T, K> : never;

只給 ElementPatch 使用的工具型別。為什麼不直接用 TypeScript 內建的 Omit？

  • 內建 Omit<CanvasElement, "id">：把三種物件當成一個整體處理，只會留下三種共有的欄位（x、y、rotation、width）。結果 { fontSize: 12 } 會報錯。
  • DistributiveOmit：T extends unknown ? … : never 這種寫法會讓 TypeScript 對 union 的每一個成員分別套用 Omit，再合併回 union，所以每種物件各自的欄位都會保留。

使用位置：只在 types.ts 內使用

常見誤解

Q：這是 class diagram，那 class 在哪裡？
types.ts 沒有 class，只有描述資料形狀的 interface / type，編譯後完全消失。這張圖借用 UML class diagram 的畫法，但每個方框只有「欄位」，沒有「方法」。這是刻意的設計，因為資料和邏輯是分開的：修改資料的邏輯在 editor-reducer.ts，計算在 geometry.ts，建立物件在 element-factory.ts，全部都是函式。
Q：TextElement extends BaseElement，所以 TextElement 是 BaseElement 的子類別？
不是。interface 的 extends 只是「把欄位複製進來」，沒有父類別的實體，也沒有覆寫。程式真正用來區分物件種類的是 CanvasElement 這個 union 和 type 欄位。新增一種物件時，所有 switch (el.type) 如果漏寫這一種，就會編譯失敗，這是這個設計的主要好處。
Q：x / y 都是物件的左上角？
是，2026-10-01 起一律是外框（旋轉前）的左上角。舊版檔案裡的橢圓、多邊形、星形是中心點，開檔時會自動換算。見 x / y 的定位點。
Q：矩形、橢圓、星形是不同的 Element？
不是，它們都是 ShapeElement（type: "shape"），只有 geometry.kind 不同。所以判斷「是不是矩形」要寫 el.type === "shape" && el.geometry.kind === "rect"。
Q：圖形內文字是另一個 TextElement？
不是，它是 ShapeElement.label，跟著圖形一起移動、旋轉、刪除、複製。匯出時 Rust 才把它轉成一個普通的文字元素（render.rs 的 shape_label），換行位置仍然由畫布量測（textLayouts 的 key 是 <id>#label）。
Q：要改物件位置，寫 element.x = 10 就好？
不行，所有欄位都是 readonly，編譯會失敗。修改一律透過 dispatch({ type: "element/update", id, patch: { x: 10 } })，由 reducer 建立新的物件。舊物件保持不變，復原時才拿得回來。
Q：ElementId 和 PageId 是不同型別，傳錯會被擋下來？
不會。兩者都只是 string 的別名，把 PageId 傳給需要 ElementId 的參數可以通過編譯（已用 tsc 驗證）。名稱只是用來提示用途。
Q：ElementPatch 會確保我只改到該物件有的欄位？
不會。{ fontSize: 12, height: 3 } 也可以通過編譯。它只保證欄位名稱屬於某一種 Element，而且不包含 id / type。
Q：types.ts 就是編輯器的全部狀態？
不是。types.ts 定義的是「文件」本身。選取了哪個物件、目前在哪一頁、縮放倍率、上傳面板的圖片清單，這些都放在 editor-reducer.ts 的 EditorState，而且不會被復原 / 重做影響。

自我檢查題

先自己回答，再展開看答案。

1. 為什麼 TextElement 沒有 height 欄位？

文字的高度由內容、換行寬度（width）和字級決定，存起來反而可能和實際內容不一致。需要高度時，由 geometry.ts 的 estimateTextHeight() 估算。

2. 用控制點把矩形拉大成兩倍，模型裡會多存一個 scale: 2 嗎？

不會，模型沒有 scale 欄位。縮放結束時，bakeTransform() 把倍率乘進 width / height，再把 Konva 節點的 scale 重設為 1。

3. 上傳一張圖片（還沒放到頁面上），接著按 Ctrl+Z，圖片會從上傳面板消失嗎？

不會。AssetInfo 存在 EditorState.assets，不在 EditorDocument 裡，所以不會進入復原歷史（但會跟著專案存檔）。

4. Page.elements 裡有 A、B、C 三個物件（依序），畫面上哪一個會蓋在最上面？

C。index 0（A）在最底層，陣列最後一個在最上層。圖層面板則是反過來顯示，最上層排在最前面。

5. 想新增「六角箭頭」和「自由繪圖的筆畫」，各要改 types.ts 的哪裡？

六角箭頭是框型圖形：在 ShapeGeometry 加一個成員（例如 { kind: "arrow"; headRatio: number }）。它自動擁有外框、填色、邊框、圖形內文字；GeometryKind 自動多一個值，各處的 switch (geometry.kind) 會編譯失敗提醒你補畫法。

筆畫不是一個框，而是一串點：要新增 PathElement extends BaseElement（含 type: "path"），加進 CanvasElement 的 union。ElementType 和 ElementPatch 會自動更新，其他檔案的 exhaustive switch 會編譯失敗，清單寫在 CLAUDE.md「新增物件類型時要改的地方」。

6. 把一個 100 × 60 的三角形的邊數改成 6，外框會變嗎？

不會。width / height 不變，六邊形的頂點會重新拉伸到碰到外框四邊，所以形狀可能被壓扁，和 draw.io 的行為相同。
