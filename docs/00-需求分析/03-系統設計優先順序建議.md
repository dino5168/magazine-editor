# 系統設計優先順序建議

> 對應：`03-設計優先順序討論.md`（2026-10-12 討論）。本次只討論開發順序，沒有改程式。
> 延續 `docs/01-Plans-2026-10/08-設計方式總結.md`（2026-10-10）的順序：樣式 → 欄格線 → 範本 → 內容系統。

## 1. 現況盤點（2026-10-12）

目前**樣式表管理**與**版式管理**都只有部分功能；**網格管理**只有輔助線；**範本管理**還沒有。

| 領域 | 已有 | 缺少 |
|---|---|---|
| 樣式表管理 | **文字樣式**（2026-10-10）：整個文字框一種樣式，物件存實際值 + `styleId`，覆寫由比對得出；內建標題 / 副標題 / 內文；「樣式」面板、屬性面板的連結 / 覆寫 / 以目前設定更新；欄位含字型、字級、粗斜體、底線、刪除線、陰影、對齊（含首尾置中）、行距、字距 | **字元樣式**（要先有富文字）、**物件樣式**（圖形的填色 / 邊框 / 圓角 / 圖形內文字）、**文件色票**（顏色只能從固定的 Tailwind 色票選，沒有自訂色）、樣式繼承（based on）、段落屬性（段前 / 段後、首行縮排）、從其他專案匯入樣式 |
| 版式管理 | 主頁（可階層、刪除時接到父主頁）、單頁 / 雙頁跨頁、跨書背物件、頁碼規則、動態變數、邊界、對齊內容區 | 文字框串接與溢排、圖文繞排、左右頁不同主頁、主頁物件在頁面上覆寫（Detach）、圖片框（裁切 / 填滿方式） |
| 網格管理 | 方格格線（只用來吸附）、內容區 1/4・1/2・3/4 對齊線、邊界參考線、尺規（mm） | **欄格線**（欄數 / 欄距）、**基線網格**、從尺規拉出參考線、吸附到欄 / 參考線 / 其他物件 |
| 範本管理 | 無（新增文件只選紙張與邊界） | 全部：紙張 + 邊界 + 主頁 + 樣式 + 色票的組合，跨專案存放 |

## 2. 討論結果（使用者 2026-10-12 決定）

| 問題 | 決定 |
|---|---|
| 這一輪「補強樣式」的範圍 | **文件色票 + 物件樣式**（都不需要富文字）。段落屬性、字元樣式之後再做 |
| 色票能不能自訂顏色 | **可以**：雜誌常有品牌色、指定色；可輸入 hex 或從 Tailwind 色票選，並命名 |
| 欄格線放在哪一層 | **每個主頁各自設定**（InDesign / Affinity 的做法）；沒套主頁的頁面用文件預設 |
| 基線網格什麼時候做 | **欄格線之後另一步**（要和文字樣式的行距綁定，範圍較大） |

## 3. 建議的開發順序

### 第一階段：樣式補強

1. **文件色票（Swatches）**
   - 文件層級的具名顏色清單（存進專案檔、可復原），可自訂 hex（含不透明度）或從 Tailwind 色票加入。
   - 調色板（`ColorPalette`）多一區「文件色票」；文字樣式、物件、頁面背景、頁碼都可以選色票。
   - 改色票 = 所有用到它的地方一起變。
2. **物件樣式（Object Styles）**
   - 圖形的填色、邊框（顏色 / 粗細 / 線型）、圓角、圖形內文字（連到某個文字樣式）。
   - 操作沿用文字樣式：「樣式」面板多一區、屬性面板的連結 / 覆寫提示 / 清除覆寫 / 以目前設定更新 / 建立新樣式。
   - 圖片的物件樣式（外框、圓角裁切）等「圖片框」做了再加。
3. **（可選）樣式繼承 based on**：文字樣式與物件樣式都可「以某樣式為基礎」，改父樣式時子樣式沒覆寫的欄位跟著變。看第 1、2 步完成後的使用情況再決定要不要做。

### 第二階段：網格管理

4. **欄格線（Column Grid）**
   - 主頁上設定欄數、欄距（可選列數、列距）；畫在內容區（邊界以內），沒套主頁的頁面用文件預設。
   - 拖曳、縮放、建立物件可以吸附到欄邊；屬性面板的「對齊內容區」加「填滿欄」。
   - 取代現在只能吸附的方格（方格保留，當成另一種輔助）。
5. **參考線**：從尺規拉出水平 / 垂直參考線（頁面或主頁上），可吸附、可鎖定、可刪除。
6. **基線網格（Baseline Grid）**
   - 文件（或主頁）設定起點與間距；文字樣式加「對齊基線網格」，開啟時每行基線落在網格上（行距取網格間距的整數倍）。
   - 畫布、PDF、EPUB 都要跟著改（行的位置由量測結果決定，見「匯出 PDF」的所見即所得原則）。

### 第三階段以後（沿用 10-10 的順序）

7. **範本**：紙張 + 邊界 + 主頁（含欄格線）+ 文字 / 物件樣式 + 色票，新增文件時選擇；跨專案存放（和跨專案素材庫一起規劃）。
8. **內容系統**：富文字（一個文字框多種樣式）→ **字元樣式** → 段落屬性 → 文字框串接與溢排 → 圖文繞排 → 文章匯入（`.md` 自動套樣式）。

## 4. 為什麼是這個順序

- **色票排在物件樣式前**：物件樣式、文字樣式都要引用顏色；先有色票，物件樣式一開始就引用色票，不用之後再遷移一次。
- **物件樣式排在網格前**：兩者都是檔案格式變更，但樣式會被範本、MCP、EPUB 引用，越早定下來後面越少改；網格主要影響編輯操作與畫面。
- **字元樣式、段落屬性往後**：都要先有富文字（Konva 一個 `Text` 只有一種樣式，要逐段量測與繪製，匯出端也要全改），是全專案技術風險最高的一塊，放在內容系統一起做。
- **範本最後**：範本是「設計系統的打包」，色票、物件樣式、欄格線都齊了才有內容可存；太早做只是複製檔案。
- **基線網格在欄格線後**：欄格線只影響物件位置（吸附），基線網格會改變文字的行位置，牽動樣式、量測與三種輸出。

## 5. 設計建議

- **色票沿用文字樣式的模式**：物件照存實際的 hex，另外記 `swatchId`（例如 `fill` + `fillSwatch`）。畫布、量測、匯出（含 Rust）都**不讀色票表**，改色票時由 reducer 一次改寫所有引用處（同 `restyleDocument`）。這樣匯出端不用改，舊檔也不用升級成「只存引用」。
- **物件樣式也照文字樣式**：物件存完整實際值 + `objectStyleId`，覆寫由比對得出，不另存覆寫清單（`style-sheet.ts` 的做法可以抽成共用的比對 / 套用函式）。
- **欄格線存在主頁上**（`MasterPage` 加 `columns`），頁面用 `masterChain` 往上找第一個有設定的主頁，都沒有就用文件預設；和「背景不繼承」不同，欄格線**要繼承**（子主頁沒設定時用父主頁的）。這點實作時再確認。
- **每一步都是檔案格式變更**：要提升 `SCHEMA_VERSION`、同步 `types.ts` / `format.rs` / fixture / `docs-website/types.html`，舊檔讀成「沒有色票 / 沒有物件樣式 / 沒有欄格線」，不需要升級步驟。
- **MCP 一起做**：每一步都加對應的工具（`list_swatches`、`add_object_style`…），沿用文字樣式的模式（以名稱或 id 指定）。
- **EPUB 重構（`plan-epubv2` 階段 1 起）**：仍待確認先後（10-10 的待確認項目）。傾向在物件樣式之後、範本之前對照一次：EPUB 的 CSS class 可以直接由文字 / 物件樣式產生。
