> 需求來源：[01-素材管理需求分析.md](01-素材管理需求分析.md)（參考 Eagle 的左側資料夾樹與中間的素材格狀列表）

## 1. 結論

**可行**，不需要更換技術，也不需要新增前端套件。現有系統已經具備大部分基礎：

| 已有的基礎 | 位置 | 在素材管理裡的用途 |
|---|---|---|
| 以內容 hash 命名、驗證檔頭的圖片匯入 | `src-tauri/src/project/assets.rs` | 素材檔案存進專案資料夾，同一個檔案只存一份 |
| 專案資料夾的原子寫入（`.tmp` → rename） | `src-tauri/src/project/io.rs` | 立即寫入 `library.json` |
| 「專案圖片」清單（`assets`） | `project.magproj`、上傳面板 | 現在就是一個沒有分類的專案素材庫，直接升級成新的素材庫 |
| pointer 拖曳框架（4 px 門檻、Esc 取消、拖曳標籤） | `components/pointer-drag.ts`、`drag-ghost.tsx` | 素材拖進資料夾、資料夾互相拖曳、素材拖到畫布 |
| 插入位置計算（`insertionSlot`） | `lib/dock` | 資料夾排序時的插入線 |
| HTML5 檔案拖放（`dragDropEnabled: false`） | `tauri.conf.json`、上傳面板 | 從檔案總管把檔案拖進素材庫 |
| 停靠面板、對話框外框 | `lib/dock`、`SettingsDialog` | 精簡面板與大型管理視窗 |

**需要誠實說明的限制**：

1. **Markdown 格式不會保留**。文字物件（`TextElement`）只有一種整段樣式，沒有富文字。`.md` 放到頁面時依使用者決定**原樣保留**符號（`#`、`**` 都會照貼），效果和 `.txt` 相同。之後如果要保留格式，要先做富文字或「拆成多個文字物件」，那是另外一個任務。
2. **素材很多時要注意效能**。圖片單檔可達 20 MB，格狀列表直接用原圖當縮圖，素材上百張時捲動和開啟可能變慢。第一版先用 `loading="lazy"` 與 `decoding="async"`，實測後如果還是慢，再由 Rust 產生縮圖快取（需要新增 `image` crate）。這一點**做了才知道**，先列為風險。
3. **整理素材不能用 Ctrl+Z 復原**（使用者決定：立即存、不進復原）。刪除改用垃圾桶補足：誤刪可以從垃圾桶還原。
4. **素材庫是每個專案各自一個**（使用者決定）。換專案就看不到另一個專案的素材；跨專案共用要等之後的「系統素材庫」（檔案系統第三階段，目前暫緩）。

## 2. 使用者已確認的決定

| # | 問題 | 決定 |
|---|---|---|
| 1 | 素材庫範圍 | **每個專案各自一個**，跟著專案資料夾走 |
| 2 | 畫面 | **大型管理視窗＋精簡停靠面板**：大視窗負責整理（左：資料夾樹，中：素材格狀列表，右：素材資訊），停靠面板負責把素材放到頁面上 |
| 3 | 素材與資料夾 | **一個素材只屬於一個資料夾**（Obsidian 式）：拖到另一個資料夾就是搬過去；不在任何資料夾 = 未分類 |
| 4 | 文字素材 | **文字檔（`.txt` / `.md`）** |
| 5 | 儲存方式 | **立即存、不進復原**：每次整理立刻寫入專案資料夾的 `library.json`；畫布的 Ctrl+Z 不管素材庫 |
| 6 | 現有的「專案圖片」 | **併入素材庫**：舊專案的專案圖片開檔時變成「未分類」素材；「上傳」面板改成「素材」精簡面板 |
| 7 | `.md` 放到頁面 | **原樣保留**符號，當純文字 |
| 8 | 刪除資料夾 | 資料夾（含子資料夾）刪除，**裡面的素材移到垃圾桶**並記住原資料夾名稱；刪除前確認 |
| 9 | 音訊 | **可以匯入、分類，但不能放到頁面**，也不做試聽 |

## 3. 範圍

### 第一版要做

- 素材種類：圖片（PNG / JPEG / WebP / GIF，沿用現有的 20 MB 上限與解碼檢查）、文字檔（`.txt` / `.md`）、音訊（MP3 / WAV / M4A / OGG，只能匯入與分類）。
- 左側系統項目：**全部**、**未分類**、**垃圾桶**，每一項顯示數量（參考 Eagle 左側）。
- 自建資料夾：新增、改名、刪除、多層巢狀、顯示數量、展開 / 收合。
- 拖曳：
  - 素材（可多選）拖到資料夾 = 移動；拖到「未分類」= 移出資料夾。
  - 資料夾拖到另一個資料夾上 = 變成它的子資料夾；拖到兩個資料夾之間 = 調整順序（插入線）。
  - 不能把資料夾拖進自己或自己的子資料夾。
- 匯入：大視窗與精簡面板都可以「選擇檔案」或從檔案總管拖放。在某個資料夾裡匯入就放進該資料夾，其他情況進「未分類」（見第 7 節）。
- 中間格狀列表：瀑布流（依原圖比例）、點選 / Ctrl+點選 / Shift+點選、框選可以之後再加。
- 右側資訊欄：縮圖、名稱（可改）、種類、尺寸 / 檔案大小、所在資料夾、匯入日期。
- 放到頁面：圖片 → 圖片物件；文字檔 → 文字物件（預設樣式，內容是檔案全文）。點選 = 放在頁面中央（同現在的上傳面板）；拖到畫布 = 放在放下的位置。
- 垃圾桶：還原、永久刪除、清空。

### 第一版不做（之後可以另排）

- Eagle 的標籤、智慧型資料夾、依顏色搜尋、評分、瀏覽器擴充。
- 一個素材同時在多個資料夾。
- 跨專案共用的素材庫（系統素材庫）。
- 音訊試聽、音訊放到頁面（EPUB 音訊）。
- Markdown 格式保留、富文字。
- 搜尋與排序選項（第一版固定依匯入時間，新的在前；搜尋可以視情況加在步驟 6）。

## 4. 設計建議

### 4.1 專案資料夾裡的檔案

```
<專案資料夾>/
  project.magproj          # 不變（v7）；素材庫不放這裡
  project.magproj.bak
  library.json             # 新增：資料夾樹、素材清單、垃圾桶（立即寫入）
  library.json.bak         # 新增：上一次寫入的版本
  assets/
    images/<hash>.<ext>    # 不變
    texts/<hash>.txt|.md   # 新增
    audio/<hash>.<ext>     # 新增
```

- **為什麼不放進 `project.magproj`**：使用者要的是「立即存、不進復原」，而 `project.magproj` 只在按「儲存」時寫入。另外開一個檔，就不會打亂現有的存檔、未存檔判斷（`selectIsDirty`）與當機復原流程，`schemaVersion` 也不用升級。
- **代價**：選「不儲存」關閉時，頁面的修改會丟掉，但素材庫的整理會留下來（和 Eagle 一樣）。這是「立即存」本來就有的結果。

### 4.2 `library.json` 的資料模型（草案）

```jsonc
{
  "libraryVersion": 1,
  "folders": [
    { "id": "<uuid>", "name": "靈感收集", "parentId": null, "order": 0 },
    { "id": "<uuid>", "name": "插畫", "parentId": "<上一個 id>", "order": 0 }
  ],
  "items": [
    {
      "id": "<uuid>",
      "kind": "image",                 // "image" | "text" | "audio"
      "src": "assets/images/<hash>.png",
      "name": "cat.png",               // 原始檔名，可改
      "folderId": null,                // null = 未分類
      "width": 1200, "height": 800,    // 只有圖片有
      "bytes": 345678,
      "importedAt": "2026-10-08T10:00:00Z",
      "trashed": null                  // 在垃圾桶時：{ "at": "...", "fromFolder": "插畫" }
    }
  ]
}
```

- 資料夾規則：名稱不可空白、同一層不可同名（建議，見第 7 節）、`parentId` 不可循環、最多 8 層（同主頁的 `MASTER_DEPTH_MAX` 做法）。**TS 與 Rust 用同一套規則**，和其他格式驗證一樣由兩邊的測試守著。
- 數量（Eagle 左側的數字）不存檔，由清單即時算出。資料夾的數量是否包含子資料夾的素材，見第 7 節。
- 同一個檔案（hash 相同）重複匯入：檔案只存一份。素材清單是否也只留一筆，見第 7 節（建議只留一筆，並提示「已在素材庫」）。

### 4.3 Rust 端

| 項目 | 內容 |
|---|---|
| 新模組 | `src-tauri/src/project/library.rs`：serde 型別、驗證（資料夾圖、`src` 路徑、名稱）、讀寫（沿用原子寫入與 `.bak`） |
| 匯入 | `assets.rs` 擴充成依種類存到 `images/` / `texts/` / `audio/`；文字檔檢查是 UTF-8、限制大小（200 KB，2026-10-08 實作計畫確認）；音訊用檔頭判斷格式 |
| 路徑驗證 | `validate_asset_path` 目前只接受 `assets/images/<檔名>`，要擴充成三個資料夾。**`ImageElement.src` 仍只接受 `assets/images/`**（頁面上的圖片不能指向文字或音訊） |
| 開檔清理 | `remove_orphan_assets` 的保留清單要加上 `library.json` 的所有素材（含垃圾桶），否則還沒放到頁面上的素材會在下次開檔時被刪掉 |
| 另存新檔 | `copy_assets` 目前只複製被引用的圖片，要改成連 `library.json` 與它的所有素材一起複製 |
| 舊專案升級 | 開檔時沒有 `library.json`：用 `project.magproj` 的 `assets` 建立一份（全部「未分類」）並寫入。之後 `assets` 的保存方式見第 7 節 |
| commands | `library_load`、`library_write`（前端送整份，Rust 驗證後寫入，同 `project_save` 的做法）、`library_import`（raw binary body，同 `asset_import`）。都寫成 `async fn` |
| 未命名專案 | `library.json` 寫在暫存資料夾，另存時一起複製；捨棄復原時跟著暫存資料夾刪除 |

### 4.4 前端

| 項目 | 內容 |
|---|---|
| 純邏輯 | `src/lib/library/`：型別、移動素材、移動資料夾（防循環與深度）、刪除資料夾（素材進垃圾桶）、還原、數量計算、驗證。補 vitest |
| 狀態 | `LibraryProvider`（獨立於 `EditorProvider`，因為不進復原歷史）：每次變更後送 `library_write`（短暫 debounce，例如 300 ms，關閉視窗前要送出） |
| 大型管理視窗 | 「檔案 → 素材管理...」（快捷鍵另議）與精簡面板上的按鈕開啟；三欄：資料夾樹｜瀑布流｜資訊欄；外框用接近全螢幕的 Dialog |
| 精簡面板 | 取代「上傳」面板：上方資料夾下拉選單（或小型樹）＋匯入按鈕，下方縮圖格；點選放到頁面中央、拖到畫布放在指定位置 |
| 拖到畫布 | 拖曳中只移動標籤（不 setState），放下時用畫布現有的座標換算（`screenToPt` 與頁面位移）決定頁面與位置，再走既有的 `element/add`（一筆復原） |
| 瀏覽器模式 | 素材庫只存在記憶體（重新整理就消失），功能都能操作（2026-10-08 實作計畫確認；原本寫「僅在桌面版可用」） |

### 4.5 和現有功能的關係

- **「上傳」面板 → 「素材」面板**：面板 id 建議沿用 `upload`、只改名稱與內容，使用者記住的停靠版面不會失效。如果改成新 id，要在 `parseDockLayout` 把舊 id 換成新 id。
- **「相片」面板（內建範例相片）**：不變。點選時照舊複製進專案；是否同時加入素材庫，見第 7 節。
- **匯出 PDF / EPUB**：不受影響。匯出只看頁面上的物件，不讀 `library.json`。
- **當機復原**：不受影響。`library.json` 本來就是立即寫入，當機時已經在磁碟上。

## 5. 風險

| 風險 | 影響 | 對策 |
|---|---|---|
| 素材多時格狀列表變慢 | 開啟管理視窗、捲動卡頓 | 先用 lazy loading＋虛擬捲動；不夠再由 Rust 產生縮圖快取（新增 `image` crate，會讓 exe 變大） |
| `library.json` 和頁面不同步（立即存 vs 手動存） | 「不儲存」關閉後，頁面回到舊版，但素材庫是新的 | 設計上接受（同 Eagle）。檔案以 hash 命名、只增不改，頁面引用的圖片不會因為素材庫的操作而消失 |
| 永久刪除素材時，頁面還在用 | 圖片變成灰框 | 永久刪除只移除清單項目，**不立刻刪檔**；檔案在下次開檔清理時，才依「頁面＋素材庫都沒引用」刪除（和現在的規則相同，復原歷史也不會失效） |
| 拖曳到畫布和現有的畫布事件衝突 | 誤觸框選或選取 | 拖曳是面板發起的 pointer 流程，放下前不碰 Konva 事件；放下時只做座標換算 |
| `.md` 使用者期待保留格式 | 放到頁面後格式消失 | 第一版在介面提示「以純文字放入」；格式保留另排任務 |

每一步做完都可以單獨驗證，等使用者確認後再做下一步。

| 步驟 | 內容 | 畫面變化 |
|---|---|---|
| 1 | Rust：`library.rs`（型別、驗證、讀寫、`.bak`）、舊專案從 `assets` 建立 `library.json`、開檔清理與另存新檔納入素材庫；`library_load` / `library_write`。`cargo test` | 無 |

| 5 | 垃圾桶：刪除素材 / 資料夾進垃圾桶、還原、永久刪除、清空 | 垃圾桶可用 |
| 6 | 精簡面板取代「上傳」面板：資料夾選擇、縮圖、點選放到頁面；文字檔放成文字物件；（視情況）名稱搜尋 | 面板改版 |
| 7 | 從精簡面板（與管理視窗）拖曳素材到畫布的指定位置與頁面 | 可拖到畫布 |
| 8 | 效能實測（數百張圖片）；不夠時加縮圖快取 | 視結果 |
| 9 | 文件：`CLAUDE.md`、`docs/`、`docs-website/`（如有需要） | 無 |

## 7. 細節決定（2026-10-08 使用者確認：全部照建議）

1. **在某個資料夾裡匯入**（按「匯入」或拖放檔案）：新素材直接放進該資料夾。在「全部」或「未分類」匯入時才進「未分類」。這一條修正了需求檔「先進未分類」的寫法。
2. **同一個檔案重複匯入**：清單只留一筆，並提示「已在素材庫」（hash 相同就算同一個檔案）。
3. **資料夾的數量**：包含子資料夾的素材（Eagle 的做法）。
4. **資料夾名稱**：同一層不可同名（TS 與 Rust 驗證同規則）。
5. **內建範例相片**：從「相片」面板放到頁面時，也加入素材庫的「未分類」。
6. **`project.magproj` 的 `assets` 欄位**：繼續和素材庫同步寫入圖片清單，讓舊版 App 開檔時仍看得到專案圖片。素材庫（`library.json`）是正式的來源，`assets` 只是相容用的副本。
7. **管理視窗的快捷鍵**：先不加，等使用習慣確定再說。
