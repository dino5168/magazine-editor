# 字型管理問題：評估計畫

> 任務檔：`02-字型管理問題.md`（同目錄）。日期：2026-10-21。
> 狀態：**評估，等使用者確認**。確認後才寫實作計畫，這份文件不改程式。
> 前一份：`01-專案字型-實作.md`（專案字型：使用者匯入 TTF / OTF，v13）。

---

## 1. 結論（先講）

| 問題 | 原因 | 建議 |
|---|---|---|
| 要先把 `C:\Windows\Fonts` 的檔案複製出來再匯入 | 「字型」對話框只能用選檔對話框選檔案；Windows 的字型資料夾在選檔對話框裡是特殊資料夾，不好選 | **「從系統字型加入...」**：App（Rust）直接列出這台電腦安裝的字型（含使用者自己安裝的），搜尋、預覽、勾選就加入專案，不用碰檔案 |
| 可以用的字型偏少 | 內建只有四套；而且**最常用的中文系統字型根本匯入不了**（見 §2：微軟正黑體、新細明體都是 `.ttc` 字型集合，目前會被拒絕） | 支援字型集合：匯入時**把集合裡的一個字型拆成單一的 `.ttf`** 存進專案；之後使用者在 Windows 安裝的任何字型都能直接選 |
| 跨專案共用 | — | **不另做「我的字型庫」**：Windows 已經是跨專案的字型庫（使用者照平常的方式安裝字型），App 只要能從系統直接選就好 |

建議順序：**① 字型集合拆成單一字型 → ② 系統字型清單與「從系統字型加入」→ ③ 一次匯入多個檔案 / 拖放（小改善）**。內建字型維持四套，不增加（理由見 §4.3）。

## 2. 現況調查（這台電腦，2026-10-21）

用腳本掃 `C:\Windows\Fonts` 與使用者字型資料夾 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`：

| 項目 | 數量 |
|---|---|
| `.ttf` / `.otf` 檔 | 340（系統）＋ 11（使用者安裝） |
| `.ttc` 字型集合 | 16 個檔、內含 42 個字型 |
| `.fon` 點陣字型 | 192（不能用，直接略過） |
| 可變字型（目前拒絕） | 10 |
| 授權 `fsType` | 可編輯 349、可安裝 41、預覽與列印 3、禁止嵌入 0 |

**含中文字的字型**（重點）：

| 字型 | 檔案 | 目前能不能匯入 |
|---|---|---|
| 微軟正黑體（一般 / 粗體 / 細） | `msjh.ttc` / `msjhbd.ttc` / `msjhl.ttc` | ❌ 字型集合 |
| 新細明體 / 細明體 | `mingliu.ttc` | ❌ 字型集合 |
| 微軟雅黑、SimSun、Yu Gothic、MS Gothic | `.ttc` | ❌ 字型集合 |
| 標楷體 | `kaiu.ttf` | ✅（要先複製出來） |
| ㄅ源流注音明體、ㄅ源泉注音圓體（使用者安裝） | `.ttf` | ✅（要先複製出來） |
| 華文系列（STKaiti、STSong…）、方正舒體、隸書、幼圓 | `.ttf` | ✅（要先複製出來） |
| Noto Sans / Serif TC、HK | `*-VF.ttf` | ❌ 可變字型（內建已有靜態版的 Noto Sans / Serif TC） |

所以使用者「複製出來再匯入」這條路，對台灣最常用的微軟正黑體、新細明體**根本走不通**。這是比「步驟麻煩」更大的問題。

## 3. 技術評估

### 3.1 字型集合（`.ttc`）：拆成單一字型

- `.ttc` = 一個檔案放好幾個字型，字型之間**共用**部分表格（字形資料）。每個字型在檔頭有自己的表格目錄。
- **不能直接存 `.ttc`**：畫布用瀏覽器的 `FontFace` 載入，CSS 沒有辦法指定「集合裡的第幾個」，只會拿第一個（`msjh.ttc` 第一個是「微軟正黑體」還是「Microsoft JhengHei UI」不一定）；EPUB / 翻頁書的 `@font-face` 也一樣。
- **做法**：匯入時在 Rust 依那個字型的表格目錄，把它用到的表格複製出來，重新組成一個標準的單一 `.ttf`（重算表格位移與檢查碼）。字形資料逐位元組不變，所以畫布、PDF、EPUB 看到的是同一份檔案，「所見即所得」照舊。之後的流程（`analyze` 檢查、Typst 檢查、存進 `assets/fonts/`）完全沿用。
- 大小：拆出來的單一字型通常接近原集合（微軟正黑體約 20 MB）。專案字型本來就這麼大（中文字型 10–30 MB）。
- 工作量：約 100 行 Rust（讀表格目錄 → 寫新的 sfnt），用現有的 `ttf-parser` 讀、手寫輸出；要測試 Typst、`ttf-parser` 與瀏覽器都讀得到拆出來的檔案。**不重新造輪子的替代**：`allsorts` / `write-fonts` 等 crate 能寫字型，但只為了「複製表格」引入大型相依不划算；第一步先做技術驗證再決定。

### 3.2 系統字型清單

- Rust 掃兩個資料夾：`%WINDIR%\Fonts`（所有使用者）與 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`（使用者自己安裝的，Windows 10 1809 起的預設位置）。登錄檔的字型清單不用讀（這兩個資料夾已涵蓋）。
- 每個字型讀出：家族名稱（中文優先）、樣式、字重、是不是集合裡的第幾個、可變字型、授權、有沒有中文字。**只讀檔頭與 `name` / `OS/2` 表格**，不讀整個檔案（系統字型合計可能超過 1 GB），並依「路徑 + 修改時間 + 大小」快取，第二次開啟很快。
- **前端不傳路徑給 Rust**（既有原則）：清單裡每個字型只給前端一個 id，加入時前端傳 id，Rust 從自己的清單找回檔案（同匯出的兩步 command）。
- 不能用的（點陣、可變、禁止嵌入、Typst 讀不了）照樣列出但停用並說明原因，使用者才知道「為什麼沒有我的字型」。

### 3.3 選字型的畫面

- 「設定 → 文件 → 字型...」多一個按鈕「從系統字型加入...」，開一個清單：搜尋、只看中文字型、依家族分組。
- **預覽不用載入檔案**：WebView2 本來就能用已安裝的系統字型名稱畫字（CSS `font-family: "微軟正黑體"`），清單每列用它畫一行範例文字。
- **一般與粗體自動配對**：選「微軟正黑體」時，自動找到同家族的 Regular（400）當一般檔、Bold（700）當粗體檔（`msjh.ttc` + `msjhbd.ttc`）；沒有粗體就照現在的規則（一般檔也登記成 700）。進階的人可以手動改。
- 加入後就是現在的專案字型（`assets/fonts/` 的檔案、`document.fonts` 一筆），檔案格式、匯出、MCP 都不用改。

### 3.4 一次匯入多個檔案 / 拖放

- 現在一次只能選一個檔案（`pickFiles(".ttf,.otf")` 只取第一個）。改成可以多選，也可以從檔案總管拖進對話框（`dragDropEnabled: false` 已經讓 HTML5 拖放可用，素材管理就是這樣做的）。小改善，順便做。

### 3.5 授權（要使用者決定）

- 微軟的系統字型多半是「可編輯」：**可以嵌入 PDF 與 EPUB**（嵌入字型的文件可以交給讀者）。目前「預覽與列印」「可編輯」只提醒、不阻擋（01 的決定）。
- **翻頁電子書**把字型檔**整個**放進資料夾（還沒做子集化），放到公開網站等於任何人都能下載那個字型檔。微軟字型的授權不允許這樣散布。建議：專案用到微軟（或其他非開放授權）的系統字型、匯出翻頁書時，**提醒**「字型檔會整個放進資料夾，請確認授權允許放到網站；開放授權的字型（例如內建四套）沒有這個問題」。之後做字型子集化可以降低但不能消除這個問題。

## 4. 方案比較

| 方案 | 解決「要複製檔案」 | 解決「字型少」 | 成本 | 風險 |
|---|---|---|---|---|
| A. 從系統字型直接加入（§3.2–3.3） | ✅ | ✅（系統裡的都能選） | 中 | 低 |
| B. 支援字型集合（§3.1） | — | ✅（微軟正黑體、新細明體…） | 低–中 | 低（要驗證三端都讀得到拆出來的檔） |
| C. 多個檔案 / 拖放（§3.4） | 部分 | — | 低 | 低 |
| D. 跨專案「我的字型庫」 | 部分 | 部分 | 中 | 和 Windows 的字型管理重複 |
| E. 增加內建字型 | — | ✅ | 每套 +10–30 MB 執行檔 | 低；但字型怎麼選都會有人覺得少 |
| F. App 內下載網路字型（Google Fonts） | — | ✅ | 高 | 要開網路與 CSP、離線不能用 |

### 4.1 為什麼 A + B 一起做

A 沒有 B 的話，清單裡最想用的微軟正黑體、新細明體都是停用的；B 沒有 A 的話，使用者還是得到 `C:\Windows\Fonts` 複製檔案。兩者一起才真正解決需求。

### 4.2 為什麼不做 D

使用者在 Windows 安裝字型（雙擊字型檔 → 安裝）之後，所有程式都能用；有了 A，本 App 也能直接選。另做一個 App 自己的字型庫，等於第二套字型管理，使用者要學兩套。

### 4.3 為什麼不做 E / F

內建四套已經 86 MB（全部內嵌進執行檔）。有了 A，使用者想要的開放授權字型（例如 jf open 粉圓、芫荽、台北黑體、思源宋體）照平常方式安裝到 Windows 就能選。可以在說明文件列一份「推薦的免費中文字型」與下載連結，代替內建（待討論）。

## 5. 一步一步（草案，確認後細化成實作計畫）

1. **技術驗證**：寫一支 Rust 測試，從 `msjh.ttc` 拆出「微軟正黑體」→ `ttf-parser` 讀得到、Typst 排得出中文、WebView2 `FontFace` 載得進來並和系統字型畫出一樣的字。不行就換做法（用 crate 寫字型）。
2. **拆字型集合**（`project/fonts.rs`）：`.ttc` 的第 N 個 → 單一 `.ttf` 的位元組，接到現有的 `analyze` / `import_font`；cargo 測試（共用表格、檢查碼、拆出來的檔再分析一次）。
3. **系統字型清單**（Rust）：掃兩個資料夾、只讀需要的表格、快取、`system_fonts_list` command（回傳 id 與中繼資料、不能用的原因）；cargo 測試用 fixture 字型。
4. **從系統加入**：`font_import_system(ids)`（一般 + 粗體），沿用 `import_font`；前端 `projectApi`。
5. **UI**：「字型」對話框的「從系統字型加入...」清單（搜尋、只看中文、分組、預覽、一般 / 粗體自動配對、停用原因）；草稿照 `font-draft.ts`，「確定」才寫入。
6. **多個檔案 / 拖放**匯入。
7. **授權提醒**（翻頁書匯出、加入非開放授權的字型時）。
8. **驗證與文件**：用微軟正黑體（一般 + 粗體）排一頁，畫布與 PDF / EPUB / 翻頁書疊圖比對；更新 `CLAUDE.md`、`fonts/README.md`、`docs/progress.md`、`01-專案字型-實作.md` 的「不做」清單。

## 6. 檢核（規劃有沒有問題）

- **所見即所得**：拆出來的單一字型字形逐位元組不變，畫布、PDF、EPUB 用的仍是同一個專案檔案。預覽清單用系統字型畫，只是預覽，不影響排版。✔
- **既有原則**：前端不傳路徑（id 換檔案）、檔案格式不變（仍是 `document.fonts` + `assets/fonts/`）、匯入的檢查照舊（可變字型、禁止嵌入、Typst 讀不了一律拒絕）。✔
- **不重複造輪子**：系統字型清單只讀表格（`ttf-parser` 已在用）；不做第二套字型庫；不做網路下載。✔
- **風險 1**：拆出來的檔案在某些字型上 Typst / 瀏覽器讀不了（例如 CFF 字型的集合）→ 步驟 1 先驗證；讀不了的照樣拒絕並說明。
- **風險 2**：掃描很慢（數百個檔）→ 只讀需要的表格、背景執行、快取；清單先顯示、預覽捲到才畫。
- **風險 3**：同名家族（例如兩個資料夾都有）→ 以使用者資料夾優先，或兩個都列出並標示來源。
- **跨平台**：只做 Windows（App 目前只支援 Windows）；macOS 的字型資料夾之後再說。
- **沒有解決的**：可變字型仍不能用（模型只有一般 / 粗體，`01` 的決定）；Noto TC 的可變版本不受影響，因為內建已有靜態版。

## 8. 使用者的決定（2026-10-21）

1. 範圍：做 **A（從系統字型加入）＋ B（支援字型集合）＋ C（多檔 / 拖放）＋ F（網路下載）**；D、E 不做。
2. 授權：翻頁書匯出時**只提醒**。
3. 選家族時**自動配對**一般與粗體。
4. 要在說明文件列「推薦的免費中文字型」。
5. F 的追加決定：
   - 來源 = **App 內建的精選清單**（名稱、授權、固定版本的官方下載網址與 SHA-256），不接 Google Fonts；第 4 項的推薦清單就是同一份。
   - 位置 = **加入目前專案（同匯入的專案字型）＋ App 資料夾的本機快取**（其他專案再用不必重新下載）；不安裝到 Windows。

F 的設計補充（原本 §4.3 建議不做，改成精選清單後的評估）：
- **下載由 Rust 做**，網址只來自內建清單，前端只傳清單 id（同「前端不傳路徑」）；前端不 fetch，CSP 不用改。
- 下載後**驗證 SHA-256**，不符就丟掉；壓縮檔（許多字型以 zip 發布）由 Rust 解出清單指定的那個檔案。
- 需要新增 Rust 相依：HTTP 用戶端（`reqwest` + rustls）與 `zip` 讀取。App 第一次需要網路（只在使用者按下載時）。
- 清單隨 App 版本更新；網址失效時顯示錯誤並建議手動下載（推薦文件有連結）。
- 授權提醒的判斷：專案字型的檔案雜湊**在精選清單或內建字型裡** = 開放授權，不提醒；其他（系統字型、使用者匯入的檔案）在翻頁書匯出時提醒。不改檔案格式。
