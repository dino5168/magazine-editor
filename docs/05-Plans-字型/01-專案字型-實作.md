# 01 專案字型：實作計畫

來源：2026-10-14 與使用者討論「加入更多字型」（沒有任務檔）。四個方案（A 維持內建、B 字型改成安裝時附帶的資料夾、C 專案字型、D 系統字型）中，使用者選 **C 專案字型**。

## 目標

使用者把自己有授權的 `.ttf` / `.otf` 匯入**專案**，文字、圖形內文字、文字樣式、頁碼都能選用；畫布、PDF、EPUB、翻頁書用**同一個檔案**，所見即所得照舊成立。內建四套字型不變。專案資料夾照樣自給自足：帶到另一台電腦開啟，版面不變。

## 現況（要改的地方）

| 位置 | 現在 | 專案字型要做的 |
|---|---|---|
| `src/index.css` | 內建字型的 `@font-face`（Vite 打包） | 專案字型改用 `FontFace` API 執行時登記 |
| `src/lib/editor/fonts.ts` | `FONT_OPTIONS` 固定四筆 | 選項 = 內建 + 文件的專案字型 |
| `use-fonts-ready.ts` | 用 `document.fonts.load` 載入內建字型 | 專案字型先登記再載入；畫布照樣等字型好才畫 |
| `export/fonts.rs` | `BUNDLED_FONTS`（`include_bytes!`） | 專案字型從專案資料夾讀 |
| `export/world.rs` | 字型在第一次匯出時解析並快取 | 每次匯出：內建（快取）+ 這份文件的專案字型 |
| `export/html/css.rs` 等 | EPUB / 翻頁書收錄用到的內建字型 | 也收錄用到的專案字型 |
| `project/format.rs`、`types.ts` | 沒有字型清單 | 文件加字型清單（schema 升級） |
| `tauri.conf.json` CSP | `font-src 'self' data:` | 視載入方式而定（見步驟 3） |

## 技術重點（已查證 / 待實測）

1. **字型名稱由我們決定，不用字型檔裡的名稱。** 內建字型遇過的問題（Typst 讀到中文家族名稱、源泉圓體每個字重各自一個家族、找不到粗體）都是 Typst 依檔案裡的 `name` 表分組造成的。Typst 0.15.1 的 `FontInfo` 欄位（`family`、`variant`）是公開的，`FontBook::push` / `from_infos` 可以自己組（已查原始碼），所以專案字型的每個檔案在 FontBook 裡登記成**我們指定的家族名稱與字重**（一般 = 400、粗體 = 700），和檔案自己的名稱無關。CSS 的 `@font-face` / `FontFace` 本來就可以隨意命名。→ 不需要像 `patch_font.py` 那樣改字型檔。（步驟 1 實測：Typst 用改過名的 `FontInfo` 能正確挑到字型。）
2. **基線（行高）**：編輯器的第一條基線由 Konva（WebView2 = DirectWrite）量出、傳給 PDF，所以 **PDF 不受影響**。EPUB / 翻頁書交給閱讀器排行：Windows 引擎讀 `OS/2` 的 win（或 typo）度量、Apple 讀 `hhea`，兩者不同的字型在 Mac 上基線會差一點（內建字型用 `patch_font.py` 修過 `hhea`）。專案字型不改檔，改在 `@font-face` 加 `ascent-override` / `descent-override` / `line-gap-override`（值 = 畫布用的那組度量，匯入時由 Rust 算好存起來），各引擎就一致。畫布的 `FontFace` 也加同樣的值，保證三邊同一組數字。
3. **粗體**：模型只有 `normal` / `bold`。每套專案字型有「一般」（必要）與「粗體」（可選，任何字重的檔案都可以指定，像霞鶩文楷用 Medium）。沒有粗體檔時，把一般的檔案也登記成 700：瀏覽器不會自己模擬加粗、Typst 也不會，三邊一致（粗體按鈕按了看起來不變，UI 提示「這套字型沒有粗體」）。
4. **只收靜態字型**：可變字型（有 `fvar` 表）拒絕，理由同 `fonts/README.md` 的規則。TTC（字型集合）、WOFF / WOFF2 第一版不收。
5. **授權（`OS/2.fsType`）**：匯入時讀出來。`0x0002`（Restricted License，不准嵌入）拒絕；`0x0004` / `0x0008`（只能預覽列印 / 可編輯嵌入）可以匯入但提醒；`0x0200`（只能嵌入點陣圖）拒絕。EPUB / 翻頁書是把**整個字型檔**放進成品交給讀者，提示文字要講清楚，責任在使用者（見「問題」）。
6. **檔案大小**：中文字型一個 5–15 MB，複製進專案；EPUB / 翻頁書只收錄用到的字型（現有的 `used_fonts`），子集化另排。

## 模型（草案）

- 檔案：`assets/fonts/<SHA-256 前 32 碼>.<ttf|otf>`（同素材，寫入後不改；同檔只存一份）。
- `EditorDocument.fonts: ProjectFont[]`（schema v13；缺少時是空陣列，舊檔不用升級步驟）：
  - `id`、`name`（選單顯示，使用者可改名，不重複）、`family`（CSS / Typst 家族名稱，建立時產生、之後不改，例如 `project-font-<id>`）、`regular: FontFile`、`bold: FontFile | null`、`generic`（`serif` / `sans-serif`，後備字型）。
  - `FontFile`：`src`（專案相對路徑）、`metrics`（ascent / descent / lineGap 的 override 值）、`fsType`、檔案裡的原始名稱（只顯示用）。
- 文字的 `fontFamily` 照舊存 CSS 字串：`"project-font-<id>", sans-serif`。畫布、量測、匯出都只看這個字串，和色票 / 文字樣式一樣「照存實際值」。
- 開檔清理沒引用的 `assets/fonts/*`（同圖片）。
- 驗證（TS / Rust 同規則）：id / 名稱 / family 不重複、`src` 在 `assets/fonts/`、名稱長度上限。

## 步驟（草案，討論後定案）

1. **實測**：Typst 用改名的 `FontInfo` 挑字型（一般 / 粗體、只有一般）；WebView2 的 `FontFace` + `ascent-override` 和 Konva 量測；一套 `hhea` 與 win 度量不同的字型（例如原始的霞鶩文楷）在畫布、PDF、EPUB 疊圖比對。
2. **檔案格式**：`format.rs` / `types.ts` / fixture、schema v13、驗證、開檔清理、`referenced_assets`。
3. **匯入**（Rust `font_import`）：檔頭檢查、`ttf-parser` 解析、拒絕可變 / 集合 / 受限授權、算 metrics、複製到 `assets/fonts/`；前端載入（`FontFace` 用 asset URL 要改 CSP 的 `font-src`，或經 IPC 取 bytes 用 `ArrayBuffer`，實測後決定）。
4. **reducer**：`font/add`、`font/rename`、`font/setBold`、`font/delete { id, replaceWith }`（把用到它的文字、圖形內文字、文字樣式、頁碼換成另一套，一筆復原）。
5. **UI**：
   - 「設定 → 文件 → 字型...」對話框：列表（名稱、預覽、一般 / 粗體檔、授權提示、使用數）、匯入、改名、指定粗體、刪除（有人用時先問替換）。
   - 字型下拉選單分「內建 / 專案字型」兩區，最下面「管理字型...」。
   - 粗體按鈕在沒有粗體檔時的提示。
6. **匯出**：PDF（`ExportWorld` 加專案字型）、EPUB / 翻頁書（收錄、`@font-face` 含 override）；疊圖比對。
7. **MCP**：`list_fonts`；`add_text` 等的 `fontFamily` 接受專案字型名稱（範圍見「問題」）。
8. **文件**：CLAUDE.md、`fonts/README.md`、`docs/progress.md`、本計畫。

## 決定

2026-10-14 使用者決定：

- 方案 **C 專案字型**（內建四套照舊）。
- **粗體**：一般必要、粗體可選（可以指定任何字重的檔案）；沒有粗體檔時一般檔也登記成 700，三邊一致，UI 提示「這套字型沒有粗體」。
- **授權（`fsType`）**：禁止嵌入（`0x0002`）與只能嵌入點陣圖（`0x0200`）拒絕；只能預覽列印（`0x0004`）/ 可編輯嵌入（`0x0008`）可以匯入但提醒；可安裝嵌入（`0x0000`）不提醒。
- **UI**：「設定 → 文件 → 字型...」對話框（同色票的做法）；字型下拉選單分「內建 / 專案字型」兩區，最下面「管理字型...」。
- **載入方式**（步驟 1 之後）：CSP `font-src` 加 asset protocol，用 URL 載入。
- **Apple 裝置的基線**（步驟 1 之後）：已知限制，匯入時提示，不改字型檔。
- **MCP**：第一版包含 `list_fonts` 與用名稱選用專案字型；匯入字型不給 MCP（要選檔案，沿用「外部不傳路徑」）。

## 進度

- **步驟 1 實測（2026-10-14 完成）**：
  - **Typst 依我們登記的名稱挑字型**（暫時的 `#[ignore]` 測試，自己組 `FontBook::from_infos`，實測後刪掉）：
    1. 一般 = Geist Regular、粗體 = Noto Serif TC Bold 登記成同一個家族 `project-font-a`（400 / 700）→ 一般字用 Geist、粗體字用 Noto Serif TC Bold。**檔案自己的家族名稱不影響**。
    2. 只有一般檔、同一個 `Font` 也登記成 700 → 粗體字用一般檔。
    3. 只登記 400 → 粗體字也用一般檔，**Typst 不會模擬加粗**（和 2 一樣；登記 700 是給瀏覽器用的）。
    4. 檔案原本的名稱（`Geist`）查不到（`unknown font family` 警告），只認登記的名稱 → 專案字型和內建字型不會互相搶名稱。
    5. 中英混排：專案字型沒有的字（中文）照 font 清單接下一個（內建黑體）。
    → 不必改字型檔；`world.rs` 的 FontBook 改成「內建（照舊）+ 專案字型（改過 `family` / `variant` 的 `FontInfo`）」。
  - **瀏覽器（headless Edge = WebView2 的 Chromium）**，用系統的 Calibri 測（`hhea` 1536 / −512 / 間距 452，Windows 度量 1950 / −550，差很多）：
    | `FontFace` 的 override | canvas `measureText` 的 ascent / descent（100 px） | DOM 行高 120 px 的基線 | 編輯器公式 |
    |---|---|---|---|
    | 沒有 | 95 / 27（= Windows 度量） | 94 | 94 |
    | Windows 度量（1950 / 550 / 0） | 95 / 27（和沒有相同） | 94 | 94 |
    | `hhea`（1536 / 512 / 0） | 75 / 25 | 85 | 85 |
    → Chromium 的 canvas 與 DOM 都照 override；**override 填 Windows 度量 = 畫布完全不變**，所以匯入時算出「Windows 用的那組」（`USE_TYPO_METRICS` 時 typo，否則 win），畫布、EPUB、翻頁書的 `@font-face` 都帶這組。
  - **CSP**：`new FontFace(name, ArrayBuffer)` 不受 `font-src` 限制（`font-src 'none'` 也載入成功）；`url(...)` 來源被擋（`NetworkError`）。→ 兩個做法都可以：IPC 取 bytes 用 `ArrayBuffer`（CSP 不變），或 CSP 的 `font-src` 加 `asset: http://asset.localhost`（和圖片的 `img-src` 一樣）用 URL。
  - **Safari / Apple Books 不支援 `ascent-override` / `descent-override`**（caniuse：Safari 穩定版到 27 都不支援，只有 Technology Preview；Safari 只支援 `size-adjust`）。所以 `hhea` 和 Windows 度量不同的字型，**在 Apple 的 EPUB 閱讀器與 Mac / iPhone 的 Safari 開翻頁書時基線會偏**：偏移 = (Windows 的 (ascent − descent) − hhea 的 (ascent − descent)) ÷ 2，Calibri 約 0.09 em（11 pt 字約 1 pt）。PDF 不受影響。內建字型沒這問題（`patch_font.py` 改過 `hhea`）。
  - 使用者決定（2026-10-14）：**CSP 的 `font-src` 加 `asset: http://asset.localhost`，畫布用 asset URL 載入**（同圖片）；Apple 裝置的基線偏移**列為已知限制**，字型對話框對 `hhea` ≠ Windows 度量的字型標示大約偏多少，不改字型檔。
