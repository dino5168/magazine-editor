# 新增文字屬性：行高與字距：實作計畫

## 1. 現況盤點

| 項目 | 現況 |
|---|---|
| 行高 | 固定常數 `TEXT_LINE_HEIGHT = 1.2`（倍數），前端 `geometry.ts` 與 Rust `render.rs` 各一份，測試守著 |
| 字距 | 沒有（Konva / Typst / CSS 都是 0） |
| 用到行高的地方 | 畫布 `canvas-elements.tsx`（`textAttrs`、圖形內文字 `ShapeLabelText`）、量測 `text-layout.ts`（分行、基線）、文字編輯框 `text-editor-overlay.tsx`、高度估算 `geometry.ts` / `shape-label.ts` / `element-factory.ts`（一處寫死 `1.2`）、頁碼外框 `page-numbers.ts`；Rust `render.rs`（`render_text`、`shape_label`、缺 layout 的保險路徑）、`template.typ`（`el.lineHeight`）、EPUB `xhtml.rs`（`line-height`） |
| 共用的入口 | `text-style.ts` 的 `konvaTextStyle()`：畫布、圖形內文字、頁碼、量測都經過它。**行高與字距放進這裡，四個地方一次生效**（不重複造輪子） |
| 文字樣式 | `TextStyle` 加欄位後，`TEXT_STYLE_KEYS`（mapped type）、覆寫比對、`restyle`、樣式對話框、MCP `list_text_styles` 都自動帶到（`TEXT_STYLE_KEY_LABELS` 漏標會編譯失敗） |

**好消息**：PDF 與 EPUB 本來就是「每一行的基線由 Rust 算好再放」（`baseline + i × lineHeight`），換成每個物件自己的行高只是把常數換成欄位。

**真正的風險在字距**：換行由 Konva 決定、Typst / CSS 只負責放，所以三者對「字距」的定義必須一致，尤其是：

1. **最後一個字後面有沒有字距**：Typst `tracking` 與 CSS `letter-spacing` 在每個字後面都加（含行尾），置中 / 靠右時整行會偏 ½ 或 1 個字距。Konva 的行寬是否含行尾字距要實測。
2. **字距 ≠ 0 時 Konva 怎麼畫**：如果逐字 `fillText`，拉丁字母的 kerning 會消失，而 Typst 預設保留 kerning → 英文行寬對不上。如果 Konva 用 Canvas 原生 `ctx.letterSpacing`（WebView2 / Chromium 支援），就和 CSS 同一套。`node_modules` 不能讀，**要在瀏覽器實測**（步驟 1）。

## 2. 設計建議

### 2.1 放進 `TextStyle`

`TextStyle` 加兩個欄位（文字物件、圖形內文字、文字樣式都有）：

```ts
interface TextStyle {
  …
  /** 行距：行與行基線的距離 ÷ 字級（倍數）。舊檔 = 1.2。 */
  readonly lineHeight: number;
  /** 字距：每個字後面多加的距離，單位 1/1000 字級（em），可為負。舊檔 = 0。 */
  readonly letterSpacing: number;
}
```

- **行距存倍數**（見問題 1）：Konva `lineHeight`、CSS 無單位 `line-height` 都是倍數；改字級時行距跟著縮放，樣式在不同字級間通用。
- **字距存 1/1000 em**（見問題 2）：InDesign / Affinity 的「追蹤（tracking）」單位；Typst `tracking: (v / 1000) * 1em`、CSS `letter-spacing: v/1000 em` 都能直接表達；Konva 要 px，`konvaTextStyle` 換算成 `fontSize × v / 1000`。改字級時字距等比例變，中文「字距 0.1 字」= 100。
- 範圍（夾住，不報錯）：行距 0.5–3.0（步進 0.05）、字距 −200 ～ 1000（步進 10）。TS / Rust 同規則，常數 `LINE_HEIGHT_MIN/MAX`、`LETTER_SPACING_MIN/MAX` 加進「前端與 Rust 共用的常數」清單。
- `TEXT_LINE_HEIGHT` 改名 / 改義為 `DEFAULT_LINE_HEIGHT`（新文字與舊檔的預設值）；畫布、量測、匯出都改讀物件的值。

### 2.2 頁碼先不加（見問題 4）

`PageNumberStyle extends Omit<TextStyle, "align">` → 改成也 Omit 這兩個欄位；`pageNumberShape` 產生圖形內文字時給預設值（1.2 / 0）。理由：左中 / 右中的直書頁碼是「每字一行」，行距由程式決定；頁碼對話框不需要更多欄位。之後要的話再加，不影響這次的格式。

### 2.3 檔案格式 v9

- Rust `format.rs`：新增 `#[serde(flatten)] spacing: TextSpacing { line_height, letter_spacing }`（同 v6 `TextDecoration` 的做法），放進 `TextElement`、`ShapeLabel`、`TextStyleDef`（**不放** `PageNumberStyle`）；缺欄位時 serde 預設 1.2 / 0，**不需要升級步驟**。驗證範圍與有限值。
- `SCHEMA_VERSION = 9`（v9 存檔後舊版 App 無法開啟）；fixture `sample.magproj` 放一個非預設值；`default-text-styles.json` 補欄位；`docs-website/types.html` 同步。

### 2.4 UI

- `TextStyleFields`（屬性面板文字分頁、圖形內文字、樣式對話框共用）在字級下方加「行距（倍）」「字距（‰）」兩個 `NumberField`（有 − / ＋）。頁碼對話框不顯示（同 `align` 的做法：用可選的 prop 控制，或頁碼的型別本來就沒有這兩個欄位）。
- 文字編輯框（textarea）套 `line-height` 與 `letter-spacing`，編輯時的換行接近畫布。
- 覆寫標示、清除覆寫、「以目前設定更新樣式」不用改（比對自動包含新欄位），只補 `TEXT_STYLE_KEY_LABELS`：「行距」「字距」。

### 2.5 匯出

- **行距**：`render.rs` 的 `line_height = size × element.line_height`；`template.typ` / `xhtml.rs` 不用改（已讀 `line_height`）。保險路徑的基線也改讀欄位。
- **字距**（依步驟 1 的實測結果修訂，見 2.6）：`RenderText` 加 `letter_spacing`（pt）與每行的起點 `line_x`。
  - **字距 ≠ 0 時，每行的起點由 Rust 用 Konva 的行寬算**（靠左 0、置中 `(框寬 − 行寬) / 2`、靠右 `框寬 − 行寬`，和 `decoration_lines` 同一個算法，抽成共用函式），PDF / EPUB 都改成「靠左放在這個 x」，不再交給 Typst / CSS 自己對齊。這樣行尾字距與 kerning 的差異都不影響起點，和畫布逐字的位置一致。字距 = 0 時照舊（不動既有路徑）。
  - PDF：~~`text(tracking: …, kerning: false, ligatures: false)`~~ **步驟 6 實測後改成**：每行拆成字元叢集（`str.clusters()`），中間放 `h(字距)`，不用 `tracking`。原因：Typst 的 `tracking` 在換字型的地方（拉丁字型 ↔ 中文字型）會少加一個字距（正負都會），「Hello世界Wave」字距 100‰ 時右緣差 5 pt。逐字放也剛好和 Konva 一樣：每個字單獨排版，沒有 kerning 與連字。
  - EPUB：`letter-spacing` + `font-kerning: none` + `font-variant-ligatures: none`，每行 `text-align: left` + `margin-left: 起點`（文字比框寬時起點是負的，padding 不能是負值，所以用 margin）。
  - 底線 / 刪除線的長度照舊用 Konva 量的 `lineWidths`，自然包含行尾字距（畫布也是這樣畫）。

### 2.6 步驟 1 實測結果（Konva 10.5.0，無頭 Edge，字級 40 px）

| 項目 | 結果 |
|---|---|
| 字距 ≠ 0 怎麼畫 | **逐字（grapheme）`fillText`**，沒有用 Canvas 原生的 `ctx.letterSpacing`。每個字的位置 = 前一個字**單獨量**的寬 + 字距，所以 **kerning 與連字消失**（Geist「AVAV」：字距 0 時 94.08 px，逐字是 106.8 px） |
| 行寬（`textArr[i].width`） | = 整行**有 kerning** 的寬 + 字數 × 字距（**含行尾字距**）。例：AVAV 字距 10 → 134.08 = 94.08 + 4 × 10；「中文字」字距 10 → 150、−5 → 105 |
| 置中 / 靠右 | 起點用上面的行寬算：置中 `(300 − 134.08) / 2 = 82.96`、靠右 `300 − 134.08 = 165.92`。所以畫出來的字比行寬寬（kerning 不見了），靠右時英文會超出框一點點；中文沒有 kerning，只差行尾的一個字距 |
| 換行 | 判斷是否放得下時也用含行尾字距的寬（框寬 125：字距 0 一行三字，字距 10 一行兩字；框寬 150 剛好三字） |
| 行高 | 基線 = `(ascent − descent) / 2 + 字級 × 行高 / 2 + i × 字級 × 行高`，1.5 與 0.8 都成立（ascent 40 / descent 12：1.5 → 44、104、164；0.8 → 30、62）。**`measureTextLayout` 的公式不用改，只把常數換成物件的值** |
| 底線 / 刪除線 | 字距 ≠ 0 時照樣一條線，長度 = 行寬（含行尾字距） |
| CSS `letter-spacing`（EPUB 參考） | 寬 = 有 kerning 的寬 + 字數 × 字距（含行尾），`0.25em` = 10 px 結果相同；CSS 保留 kerning，和 Konva 的逐字畫法不同 → 所以 EPUB 要關 kerning |

結論：
- **行高**：直接換成欄位，PDF / EPUB 的模型不用改。
- **字距**：Typst / CSS 和 Konva 有兩個差異（行尾字距、kerning）。做法改成 2.5 的「起點由 Rust 用 Konva 行寬算 + 關掉 kerning 與連字」，不再依賴各引擎自己的對齊。
- **已知限制**（畫布本身的行為，寫進 `CLAUDE.md`）：字距 ≠ 0 時英文失去 kerning，所以字距從 0 改成 1‰ 時英文會突然變寬一點；靠右對齊的英文會超出框一點點。PDF / EPUB 會照畫布的樣子輸出。

## 4. 使用者的決定（2026-10-11）

| 問題 | 決定 |
|---|---|
| 1. 行距單位 | **倍數** |
| 2. 字距單位 | **1/1000 字（‰）** |
| 3. 內建樣式的行距 | **「內文」改 1.5**，標題 / 副標題 1.2（TS `defaultTextStyles`、Rust `default_text_styles`、`default-text-styles.json` 一起改，步驟 2 / 3） |
| 4. 頁碼 | **這次不加** |

討論時列出的選項：

1. **行距的單位**：(a) 倍數（1.2、1.5…，建議）；(b) 固定 pt（InDesign 的「行距 14 pt」，改字級時不跟著變）。
2. **字距的單位**：(a) 1/1000 字（‰，InDesign / Affinity 的追蹤，建議）；(b) 字級的 %（10% = 0.1 字）；(c) pt。三者存檔都可以換算，差在 UI 顯示與改字級時要不要等比例變（a、b 會，c 不會）。
3. **內建樣式的行距**：(a)「內文」改成 1.5（中文內文常用 1.5–1.8，1.2 偏擠），標題 / 副標題維持 1.2（建議；只影響新文件與舊檔升級時加上的樣式，已存的文字不變）；(b) 全部維持 1.2（外觀完全不變）。
4. **頁碼要不要也有行距 / 字距**：(a) 這次不加（建議，見 2.2）；(b) 只加字距；(c) 兩個都加。

## 5. 計畫檢核

- **舊檔外觀不變**：缺欄位讀成 1.2 / 0，和現在的常數相同；畫布、PDF、EPUB 的既有測試應該全部照樣通過（步驟 2–4 是重構，數值不變）。
- **前端與 Rust 的常數**：`DEFAULT_LINE_HEIGHT`（取代 `TEXT_LINE_HEIGHT`，兩邊都留）與範圍上下限要一致；EPUB 測試 `tests.rs` 用到 `TEXT_LINE_HEIGHT`，一起改。
- **`konvaTextStyle` 的呼叫者**：`measureLineWidth`（頁碼寬度）目前只用 `konvaFontStyle`，頁碼沒有字距所以不受影響；若之後頁碼要字距，量寬也要帶字距。
- **復原與 reducer**：沿用 `element/update` / `textStyle/update`，不加新 action；不合法值由 `isTextStyle` 擋下回傳同一個 state。
- **字型**：行距 / 字距不換字型，不用 `loadFontFamily`。
- **文字編輯框**：textarea 的換行由瀏覽器決定，本來就只是「接近」Konva；加了字距仍是同一套字型與 `letter-spacing`，差異不會變大。
- **風險**：Konva 與 Typst 的字距細節（行尾、kerning）不一致會讓置中 / 靠右的行偏移，所以步驟 1 先量，步驟 6 / 7 用疊圖比對守著；已知限制寫進 `CLAUDE.md`。
- **不做**（之後另排）：段落間距、首行縮排、自動字距（optical kerning）、兩端對齊（justify）、標點擠壓、頁碼的行距 / 字距（若問題 4 選 a）。
