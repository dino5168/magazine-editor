# 13 文字對齊加入「首尾置中」實作計畫

任務檔：`13-文字對齊加入首尾置中.md`（不 commit）；本計畫要 commit。

## 1. 需求理解

- 參考圖「首 尾 置 中」：一行的**第一個字貼齊文字框左緣、最後一個字貼齊右緣**，中間的空隙平均分配。這就是 Word 的「分散對齊」、InDesign 的「強制齊行」、OOXML 的 `distribute`。
- 現在的對齊只有靠左 / 置中 / 靠右（`TextStyle.align`），屬性面板的三個按鈕在 `style-controls.tsx` 的 `ALIGN_OPTIONS`。
- 「首尾置中」是新的 `align` 值，和其他對齊一樣屬於 `TextStyle`：文字物件、圖形內文字、文字樣式都會有。頁碼不顯示對齊按鈕（位置決定對齊），不受影響。

## 2. 現況與可以沿用的東西（不重複造輪子）

| 需要的能力 | 已經有的 | 這次怎麼用 |
|---|---|---|
| 換行 | Konva `Text` 的 `textArr`（畫布、量測、匯出都以它為準） | 換行與對齊無關：首尾置中照「靠左」換行，**分行完全沿用 Konva** |
| 逐字放置 | 字距（v9）：Konva 有字距時逐字畫；PDF 每行拆成字元叢集、中間放 `h(字距)`；EPUB 用 `letter-spacing` + 每行 `margin-left` | 首尾置中 = **每一行各自的字距**（字距 + 這行多分到的空隙），PDF / EPUB 走同一條路，只是每行的值不同 |
| 每行起點 | `render.rs` 的 `line_start`、`RenderText.line_starts` | 首尾置中的起點 = 0（單字行置中）；`line_start` 加一個分支 |
| 底線 / 刪除線 | `decoration_lines`（長度 = 前端量到的行寬） | 首尾置中的行寬 = 文字框寬，線自然畫滿 |
| 陰影 | Konva `drawScene`（有線時 buffer canvas） | 只換繪製函式，陰影仍由 Konva 處理 |

### 唯一需要自己寫的：畫布的繪製

Konva 沒有中文可用的分散對齊：`align: "justify"` 只在**空白字元**加距離、而且最後一行不分散，中文沒有空白，等於沒效果（步驟 1 實測確認）。

做法（建議）：首尾置中的文字節點照常用 Konva `Text`（換行、量測、選取、Transformer、`bakeTransform` 都不變），只傳入自訂的 **`sceneFunc`**：
- 讀 Konva 算好的 `textArr`，每行用 `Intl.Segmenter` 切成字（和 Typst `clusters()` 同為 grapheme），量每個字的寬，算出這一行的空隙，逐字 `fillText`；底線 / 刪除線照 Konva 的公式畫。
- 其他對齊不傳 `sceneFunc`，完全是現在的 Konva 行為。
- 繪製函式與「每行空隙」的計算放在 `lib/editor/`（純函式 + 測試），畫布與 `measureTextLayout` 共用，匯出拿到的數字和畫布畫的是同一份。

考慮過但不建議：每行拆成一個 `Konva.Text`、用不同字距排在 Group 裡——文字物件變成 Group，選取、Transformer、`bakeTransform`、陰影（整段一個陰影）都要改，影響面大很多。

## 3. 規則（★ = 使用者已於 2026-10-12 確認）

1. ★ **哪些行要分散**：**每一行都分散，含段落最後一行**（= 參考圖的單行標題，也是 Word「分散對齊」）。另一種是「左右對齊」（最後一行靠左），見第 6 節設計建議。
2. ★ **英文怎麼分**：**每個字元之間都分**（和 Word 分散對齊、和現有的逐字字距同一套），不是只分在單字之間的空白。
3. **單字行**（一行只有一個字）：置中（Word / InDesign 的做法）。空行不處理。
4. **字距**：只影響換行（Konva 照字距斷行）。空隙 = 字距 + (框寬 − 字寬總和 − (字數 − 1) × 字距) ÷ (字數 − 1)，化簡後就是 (框寬 − 字寬總和) ÷ (字數 − 1)，**和字距無關**（步驟 2 實作時發現）。行尾不加字距（最後一個字的右緣貼齊框）；行尾的空白不算字（Word 也忽略），否則最後一個看得到的字貼不到右緣。字比框寬時空隙是負的（字重疊、仍剛好塞進框）。
5. **行寬**（傳給匯出、底線長度）：兩字以上 = 框寬；單字 = 該字寬。
6. **文字編輯框**（textarea）：用 CSS `text-align: justify; text-align-last: justify` 近似。Chrome 的 justify 對中文是逐字分、對英文只分在空白，所以編輯中的英文和畫布略有不同，**放開後以畫布為準**（已知限制）。
7. ★ **按鈕名稱**：tooltip「分散對齊（首尾置中）」；icon 用 lucide 的 `TextAlignJustify`（實作時以 build 確認名稱）。

## 5. 步驟（一次一步，每步停下等確認）

### 步驟 1：實測 Konva（不改程式）
無頭 Edge 實測，結果寫回本計畫：
- `align: "justify"` 對中文、英文、多段文字的實際效果（確認不能直接用）。
- `Konva.Text` 傳入自訂 `sceneFunc` 時：`textArr` 換行照舊、命中區（選取）照舊、有線 + 陰影時仍走 buffer canvas（整段一個陰影）。
- 逐字 `measureText` 的寬和 Konva 有字距時的行寬一致（確認公式用的字寬和 Konva 同源）。
- 結論：確定 `sceneFunc` 做法，或改用其他做法（若有變再和使用者討論）。

**結果（2026-10-12 完成，Konva 10.5.0，無頭 Edge，記錄 `fillText` 呼叫）**：

| 項目 | 結果 |
|---|---|
| `justify` + 中文 | **沒有效果**：「首尾置中」框寬 300、字仍在 x = 0 / 32 / 64 / 96（和靠左相同） |
| `justify` + 英文 | 只在空白處加距離；`lastInParagraph` 的行（段落最後一行，含 `\n` 前那一行）不分散。`justify` 時 Konva 也改成逐字畫 |
| `textArr` | 每行有 `text` / `width` / **`lastInParagraph`**（之後做「左右對齊」可直接用） |
| 自訂 `sceneFunc` | `getSceneFunc()` 回傳自訂的、每次繪製呼叫一次；`textArr` 換行照舊；`getIntersection` 命中照舊（命中區由 `_hitFunc` 畫外框，不受影響）；進入 `sceneFunc` 時 native context 已設好陰影（`shadowColor` / `shadowOffsetX`），逐字 `fillText` 會各自投影；有底線 + 陰影時 `_useBufferCanvas()` 仍是 true（整段一個陰影） |
| 字寬 | Konva 有字距時第 i 個字的 x = 前面每個字**單獨** `measureText` 的寬 + 字距，和預測完全相同（「首尾AVa中」字距 5：0 / 37 / 74 / 100.38 / 126.72 / 149.35）。Konva 回報的行寬則是整行（有 kerning）的寬 + 字數 × 字距（181.55，逐字加總是 186.35）→ **首尾置中要用逐字加總的寬**，不能用 `textArr.width` |
| 切字 | Konva 依 grapheme 切（`👍🏽`、`é`（e + 組合符號）各是一個字），和 `Intl.Segmenter` / Typst `clusters()` 同一種單位 |
| 基線 | 實際 `fillText` 的 y（`alphabetic`）= `measureTextLayout` 的公式（行距 1.5、32 pt：35.5；第二行 + 48 = 83.5） |

**結論**：照計畫用自訂 `sceneFunc`。繪製時每個字的寬用 native context 的 `measureText`（逐字、和 Konva 同源），切字用 `Intl.Segmenter`；基線沿用 `measureTextLayout` 的公式。步驟 4 要再確認 buffer canvas（底線 + 陰影）時畫出來的像素正確。

## 6. 設計建議

1. **之後加「左右對齊」（justify，最後一行靠左）**：雜誌內文最常用的是這個，不是分散對齊。這次做好的「每行空隙」機制可以直接重用，只差判斷「段落最後一行」（Konva `textArr` 是否有 `lastInParagraph`，步驟 1 一併查）。使用者決定：這次只做首尾置中，左右對齊另開任務。
2. **用途提醒**：分散對齊適合標題、短句、表格欄位；長段內文的最後一行字很少時會被拉得很開，這是分散對齊本來的行為。
3. **UI 名稱**：業界多稱「分散對齊」，「首尾置中」不常見，建議按鈕寫「分散對齊（首尾置中）」，使用者兩種說法都認得。

## 7. 檢核（規劃本身的風險）

- **畫布與匯出一致**：空隙由前端算一次、傳給 Rust，PDF / EPUB 不自己重算，換行一樣由 Konva 決定 → 和字距同一套保證。字寬來源不同（Typst 自己量字）可能差零點幾 pt，和字距相同的已知限制。
- **自訂 `sceneFunc` 依賴 Konva 內部行為**（`textArr`、基線公式、底線公式）：這些已經在 `measureTextLayout` 與 `render.rs` 依賴了，同樣標註「升級 Konva 時重查」。
- **舊版 App**：v10 檔案舊版會拒絕開啟（即使沒用到首尾置中），和 v9 時相同的取捨。
- **步驟 3 的過渡期**：存成 `distributed` 的文字在步驟 4 之前畫成靠左，匯出也靠左，不會壞檔。
- **英文長單字**：Konva 只在單字放不下時才逐字斷行，首尾置中不改變換行，所以不會比靠左多斷行。
- **文字編輯框只是近似**（第 3 節第 6 點），編輯結束後以畫布為準。
