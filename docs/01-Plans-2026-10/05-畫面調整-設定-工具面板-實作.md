# 05 畫面調整：工具面板提升為主選單（實作計畫）

任務檔：`05-畫面調整-設定-工具面板.md`（不 commit）。

## 任務

把「設定 → 工具面板 ▸」提到選單列，成為主選單「工具面板」；選單列順序改成 **檔案、設定、視圖、工具面板**。

```
現在：檔案(F)  視圖(V)  設定(S)
之後：檔案(F)  設定(S)  視圖(V)  工具面板(P)
```

## 現況（不重複造輪子）

選單已經是資料驅動，這次幾乎只改**資料**：

| 部分 | 位置 | 這次要不要改 |
|---|---|---|
| 選單結構與順序 | `lib/menu/menu-structure.ts` 的 `MENUS`（陣列順序 = 選單列順序） | **改**：搬移子選單、新增一個 `MenuDefinition`、調整順序 |
| 助記鍵 | `MenuDefinition.mnemonic` + `findMenuByMnemonic` | 不改程式，新選單填一個 `mnemonic` 就有 Alt+字母 |

| 測試 | `menu-structure.test.ts` | **改**：位置與順序的斷言；「每個指令恰好出現一次」「助記鍵不重複」會自動檢查新選單 |

指令的訊息標題「工具面板：圖層」、「重設工具面板版面」不受影響（`getCommandTitle` 用的是 `title`）。

## 檢核

- **快捷鍵 / 助記鍵衝突**：新選單只帶 Alt+字母助記鍵，`findMenuByMnemonic` 要求只按 Alt（不含 Ctrl / Shift），不會和 Ctrl 快捷鍵或工具鍵（V・H・T・R・O，不帶修飾鍵）衝突；測試「助記鍵不重複」守著選單之間。
- **選單內指令完整性**：搬移後每個 `panel.*` 仍恰好出現一次（既有測試）。
- **使用者的版面紀錄**：`DockLayout` 存在 localStorage，與選單位置無關，不受影響。
- **檔案格式 / Rust**：不涉及。
- **舊文件裡「設定 → 工具面板 → 屬性」這類說法**：只在歷史計畫裡，見上。

## 決定（2026-10-09 與使用者確認）

1. **工具面板的助記鍵：Alt+P**（Panel）。考慮過 Alt+W（Windows 慣例的「視窗」選單）、Alt+T（容易聯想成「工具」而不是「面板」）。
2. **選單順序照任務檔**：檔案、設定、視圖、工具面板。曾提出慣例做法「檔案、視圖、工具面板、設定」（Adobe / Affinity 把設定類放右邊），使用者選擇照任務檔。
3. **計畫檔名**：任務檔寫輸出到 `01-畫面調整-設定-工具面板-實作.md`，但同目錄已經有 `01-修改新增專案流程-實作.md`，且慣例是和任務檔同編號，所以用 `05-畫面調整-設定-工具面板-實作.md`。
