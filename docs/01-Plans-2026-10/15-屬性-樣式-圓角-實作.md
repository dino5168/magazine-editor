# 15 屬性 → 樣式 → 圓角：四個角分開設定 實作計畫

任務檔：`15-屬性-樣式-圓角.md`（不 commit）；本計畫要 commit。

## 1. 需求理解

- 現在矩形只有一個「圓角」欄位（屬性面板「樣式」分頁的「形狀」區塊），四個角一樣。
- 要可以**四個角分開**設定（左上、右上、右下、左下）。
- 保留原本「輸入一個值」的簡單操作，需要時才分開輸入四個；操作便利性要給建議。

## 2. 現況（沿用與要改的地方）

| 位置 | 現況 | 四角時 |
|---|---|---|
| 模型 `types.ts` | `{ kind: "rect"; cornerRadius: number }` | 見第 3 節 |
| 畫布 `canvas-elements.tsx` | Konva `Rect cornerRadius={number}` | **Konva 本來就收 `[左上, 右上, 右下, 左下]`**，直接傳 |
| 輸入限制 `properties.ts` | `clampCornerRadius`：0 – 短邊的一半 | 每個角各自套用（沿用） |
| PDF 有邊框 `pdf.rs` | `rect_path(w, h, r)`：自己畫路徑（虛線起點和 Konva 相同） | 改成四個半徑（同一個函式） |
| PDF 無邊框 `template.typ` | Typst `rect(radius: r)` | Typst `radius` 收 `(top-left:, top-right:, bottom-right:, bottom-left:)` |
| EPUB 有邊框 `xhtml.rs` | SVG `<rect rx ry>`（只能一個值） | 四角不同時改成 SVG `<path>`（用和 PDF 同一組路徑） |
| EPUB 無邊框 `xhtml.rs` | CSS `border-radius: r` | CSS `border-radius: 左上 右上 右下 左下` |
| 驗證 | TS `isShapeGeometry`、Rust `validate_geometry`：≥ 0 | 四個都 ≥ 0 |
| MCP | `update_element` 的 `cornerRadius`（數字） | 也收四個數字的陣列 |
| 名稱 | `describeShape`：> 0 就是「圓角矩形」 | 任一角 > 0 |

**放大縮小後的圓角**：模型存的值不會在縮放時重算，畫的時候才限制在短邊的一半（Konva、PDF 路徑、EPUB SVG 都是）。四角時**每個角各自限制在短邊的一半**，兩個角加起來就不會超過一邊，所有輸出都一樣；EPUB 的 CSS 遇到相加超過一邊時會「等比例縮小全部」，和這個規則不同，所以 Rust 先限制好再輸出（步驟 1 先實測 Konva 是不是同一個規則）。

## 3. 資料模型（使用者 2026-10-12 確認）

`cornerRadius: number | [左上, 右上, 右下, 左下]`（和 Konva 相同的寫法）：

- 四個角一樣時**仍存成一個數字**（存檔時正規化）：既有檔案、MCP、測試都不用改，舊檔不用升級。
- 只有四角不同時才存陣列。舊版 App 讀不懂陣列，所以**檔案格式升到 v11**（舊版會明確說「檔案比 App 新」）。
- Rust：`#[serde(untagged)] enum CornerRadius { Uniform(f64), Corners([f64; 4]) }`。

## 4. 操作方式（使用者 2026-10-12 選 A）

**A. 一個欄位 + 「分開設定」切換鈕（採用，Figma / Affinity 的做法）**

```
圓角  [ 12 ] pt   [⌗]        ← 收起：一個欄位，改它 = 四個角一起改
───────────────────────────
圓角               [⌗ 已按下] ← 展開：四個欄位照角的位置排
 ┌ [ 12 ] pt   [ 12 ] pt ┐
 └ [  0 ] pt   [  0 ] pt ┘
```

- 平常照舊只輸入一個值；按切換鈕才展開成 2 × 2 的四個欄位，**排列位置就是角的位置**（左上、右上 / 左下、右下），不用記順序。
- 展開時四個欄位先帶入目前的值。
- 四角不同的矩形，選取時直接展開。收起時若四角不同，一個欄位顯示「混合」，輸入數字 = 四個角一起變成這個值。
- 數字欄位（`NumberField`）要加「混合」顯示（值為 null 時顯示提示文字）。

（不採用）**B. 永遠四個欄位 + 鎖鏈（連動）按鈕**（Photoshop / CSS 編輯器）：鎖上時改一個 = 四個一起改。畫面一直比較大，最常見的「四角一樣」也要看四個欄位。

（不採用）**C. 一個欄位輸入「8 8 0 0」**（CSS 寫法）：省空間，但要記順序，不直覺。

## 5. 步驟（一次一步，每步停下等確認）

### 步驟 1：實測 Konva（不改程式）
- Konva 10.5.0 `Rect` 的 `cornerRadius` 陣列：順序、每個角超過短邊一半時怎麼限制（各自夾到一半？等比例？）、有虛線邊框時的起點和單一半徑相同嗎。結果決定 PDF / EPUB 的限制規則。

**結果（2026-10-12 完成，Konva 10.5.0，無頭 Edge，記錄 `moveTo` / `lineTo` / `arc` 呼叫）**：

| 項目 | 結果 |
|---|---|
| 順序 | `[10, 20, 30, 40]`（200 × 100）：左上 10 → 右上 20（圓心 180, 20）→ 右下 30（170, 70）→ 左下 40（40, 60）＝ **`[左上, 右上, 右下, 左下]`** |
| 超過短邊一半 | `[80, 10, 10, 10]`：只有左上變 50，其他維持 10 → **每個角各自夾到短邊的一半**（不是 CSS 的等比例縮小）。`[60, 60, 60, 60]` 和單一 80 都畫成四個 50 |
| 相加等於一邊 | 100 × 200、`[70, 70, 0, 0]` → 上兩角各 50，剛好佔滿上緣（中間直線長 0），不重疊 |
| 路徑起點與方向 | 數字和陣列都從 **(左上半徑, 0)** 開始、順時針（上緣 → 右上角 → 右緣 …）；有虛線時兩者完全相同 → PDF 的 `rect_path` 照同一個起點改成四個半徑，虛線位置不變 |
| 角的畫法 | `arc`（正圓弧）；PDF 路徑用貝茲曲線近似（`KAPPA`，既有做法） |

**結論**：照計畫。所有輸出在 Rust render model 把每個角各自限制在 `min(寬, 高) / 2`（和 Konva 相同），EPUB 的 CSS 就不會走到它自己的等比例縮小。

## 6. 設計建議

1. **用 A**：最常見的是四角一樣，所以預設只顯示一個欄位；需要時一鍵展開，而且欄位排在角的位置上，看圖就知道哪個是哪個角。
2. **之後可以加「在畫布上拖曳圓角控制點」**（Canva、Figma 有）：選取矩形時角落內側出現小圓點，拖曳直接改圓角，Alt 拖曳只改一個角。這次不做，範圍較大（Transformer 外另一組控制點）。
3. **常用組合**（只圓上兩角、只圓左兩角…）可以之後做成快捷按鈕；這次用四個欄位就能做到。

## 7. 檢核

- **舊檔相容**：四角一樣存數字，v10 以前的檔案原樣可讀；只有存了四角不同的檔案舊版打不開（提升到 v11）。
- **所見即所得**：所有輸出用同一個限制規則（步驟 1 確認 Konva 的規則），PDF 的有邊框路徑和 EPUB 的 SVG 用同一組路徑資料。
- **一筆復原**：一次輸入（一個欄位）= 一次 `element/update`。
- **圖形以外**：圓角只有矩形 geometry 有；頁碼的框（`cornerRadius: 0`）不變。
