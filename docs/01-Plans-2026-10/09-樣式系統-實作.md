## 1. 現況盤點：目前有沒有樣式系統？

**沒有。** 目前只有「建立時的初始值」，沒有「引用」：

| 項目 | 現況 | 問題 |
|---|---|---|
| 文字物件 `TextElement` | `extends TextStyle`：字型、字級、粗體、斜體 / 底線 / 刪除線、陰影、對齊、顏色**全部直接存在物件上** | 想把全書的內文從 11 pt 改成 10.5 pt，只能一個一個改 |
| 圖形內文字 `ShapeLabel` | 同上（`extends TextStyle`） | 同上 |
| 頁碼 `PageNumberRule.style` | 每段規則自己一份 `PageNumberStyle` | 已經是「一段頁碼共用一組」，暫不需要樣式 |
| 「文字」面板的標題 / 副標題 / 內文 | `element-factory.ts` 的 `TEXT_PRESETS`（寫死在程式裡） | 只是建立物件時的初始值，建立後和 preset 無關；使用者不能自訂 |
| 顏色 | 調色板只有 Tailwind 色票；物件存 hex | 沒有「文件色票」，沒有具名顏色 |

**範本需要樣式的原因**：範本 = 紙張 + 邊界 + 主頁 + **樣式表** + 色票。沒有樣式表，套用範本後使用者新加的文字仍是程式內建的 11 pt 黑體，範本的「版式」帶不過去。

## 2. 設計建議（核心決定）

### 2.1 樣式存在文件裡，物件「引用 + 保留實際值」

建議採用 **「連結 + 實際值照存」**（denormalized）：

```ts
// types.ts（示意）
interface TextStyleDef extends TextStyle {   // 文件裡的一個樣式
  readonly id: string;
  readonly name: string;                      // 「內文」「大標」…
}
interface EditorDocument { …; readonly textStyles: readonly TextStyleDef[] }
interface TextElement extends BaseElement, TextStyle { …; readonly styleId: string | null }
interface ShapeLabel extends TextStyle { …; readonly styleId: string | null }
```

- 物件**照舊存完整的字型、字級、顏色…**，另外多一個 `styleId` 記住它連到哪個樣式。
- **覆寫（override）不另外存，由比對得出**：物件某欄位 ≠ 樣式的該欄位 = 這一欄被覆寫。
- **改樣式時**（一個 action = 一筆復原）：所有連到它的物件（每一頁、每個主頁），**值和「舊樣式」相同的欄位**改成新值；不同的（被覆寫的）保留。

**為什麼這樣做（不重複造輪子）**：畫布、量測換行（`measureTextLayout`）、縮圖、`buildExportRequest`、Rust `render.rs`、PDF 模板、EPUB 都**直接讀物件上的值，完全不用改**。如果改成「物件只存覆寫、顯示時才合併」（InDesign 的內部做法），上述每個讀 `element.fontSize` 的地方都要先解析樣式，改動面很大、風險高，而且匯出端（Rust）也要懂樣式。

**代價**：「覆寫的值剛好等於樣式的值」會被當成沒覆寫（之後改樣式時會跟著變）。InDesign 也是類似行為，可以接受。

### 2.2 先只做「文字樣式」（整個文字框一種樣式）

目前一個文字框只有一種樣式（沒有富文字），所以**段落樣式與字元樣式在現在是同一件事**。建議：

- 這次只做一種，UI 上叫「文字樣式」。
- **字元樣式等到富文字（內容系統）再做**：那時一段文字裡才會有「部分文字套另一個樣式」，資料模型（文字 run）也那時才定。
- 欄位 = 現在的 `TextStyle` 全部欄位（字型、字級、粗體、斜體、底線、刪除線、陰影、對齊、顏色）。**行距、字距不加**：行距目前是前端與 Rust 共用的常數 1.2（`TEXT_LINE_HEIGHT`），改成可設定會動到量測與匯出，另排。

### 2.3 內建樣式取代 `TEXT_PRESETS`

- 新文件預設帶三個樣式：「標題」32 pt 粗、「副標題」20 pt、「內文」11 pt（= 現在的 `TEXT_PRESETS`）。
- 「文字」面板的按鈕改成**列出文件的樣式**（點了就加一個連到該樣式的文字），使用者自訂的樣式也會出現。
- 舊檔（v7 以前）升級時也加上這三個樣式，但**舊的文字物件不連結**（`styleId: null`，無法判斷它原本是哪個 preset）。

### 2.4 文件色票

色票牽涉的欄位很多（圖形填色、邊框、文字顏色、陰影、頁面背景、頁碼），如果做成「改色票 → 所有用到的地方都變」，改動面比文字樣式還大。見第 4 節問題 3。

## 5. 計畫檢核

- **匯出不用改**：物件仍存實際值；`buildExportRequest` 與 Rust `render` / PDF / EPUB 讀的欄位不變。Rust 匯出用的是 `format::Document`，新欄位要在 `format.rs` 定義（否則存檔時會被丟掉，因為只有最上層未知欄位會保留），但匯出邏輯不讀它們。
- **字型載入**：改樣式的字型時要先 `loadFontOption` 再 dispatch（和屬性面板換字型相同），否則畫布換行寬度會算錯。
- **主頁與對頁**：樣式在文件層級，主頁上的物件一樣連動；`textStyle/update` 要走過 `pages` 與 `masters`。
- **復原**：改樣式連動幾百個物件也只是一筆復原（同 `document/setPageSetup`）；沒有變化時回傳同一個 state（測試守著）。
- **MCP 的 `update_element`**：改了樣式欄位自然變成覆寫（覆寫由比對得出），不用特別處理。
- **頁碼**：這次不連到樣式（規則本身已經是一段共用一組）；之後要的話，`PageNumberStyle` 可以加 `styleId`。
- **風險**：步驟 2 改檔案格式，兩邊的驗證規則（名稱長度、id 不重複、引用存在）要一致，用共用 fixture 守著（沿用主頁 v7 的做法）。
- **範本銜接**：樣式表在 `EditorDocument` 裡，之後的範本（第 3 階段）直接複製 `textStyles` + `masters` + 紙張 / 邊界即可；也可以做「從另一個專案匯入樣式」。
