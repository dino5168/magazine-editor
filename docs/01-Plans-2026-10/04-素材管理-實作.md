## 已確認的決定（摘自可行性報告）

每個專案各自一個素材庫；大型管理視窗＋精簡面板（取代「上傳」面板）；一個素材只在一個資料夾；文字素材 = `.txt` / `.md`（放到頁面時原樣、純文字）；整理立即寫入 `library.json`、不進復原；舊的專案圖片併入（未分類）；刪除資料夾 → 素材進垃圾桶；音訊可匯入分類、不能放頁面、不試聽；在資料夾裡匯入 = 放進該資料夾；同檔只留一筆；數量含子資料夾；同層不同名；內建相片放到頁面時也加入未分類；`project.magproj` 的 `assets` 繼續同步；管理視窗不加快捷鍵。

## 設計

### 檔案

```
<專案>/library.json        立即寫入（.tmp → rename），上一版留成 library.json.bak
<專案>/assets/images/       不變
<專案>/assets/texts/        新增：<hash>.txt | <hash>.md
<專案>/assets/audio/        新增：<hash>.mp3 | .wav | .m4a | .ogg
```

`project.magproj` 的格式**不變**（不升 `schemaVersion`）。

### `library.json`（Rust `project/library.rs` 是權威定義，TS `lib/library/types.ts` 手寫對應）

```ts
interface Library {
  libraryVersion: 1;
  folders: LibraryFolder[];   // 陣列順序 = 同一層的排列順序
  items: LibraryItem[];
}
interface LibraryFolder { id: string; name: string; parentId: string | null }
interface LibraryItemBase {
  id: string; name: string; src: string; bytes: number;
  folderId: string | null;              // null = 未分類
  importedAt: string;                   // RFC 3339
  trashed: { at: string; fromFolderId: string | null; fromName: string | null } | null;
}
type LibraryItem =
  | LibraryItemBase & { kind: "image"; width: number; height: number }
  | LibraryItemBase & { kind: "text"; excerpt: string }   // 前 200 字，卡片預覽用（見檢核 4）
  | LibraryItemBase & { kind: "audio" };
```

驗證規則（TS 與 Rust 相同，共用 fixture `tests/fixtures/sample-library.json` 守著）：

- id 不重複（資料夾、素材各自）；名稱去頭尾空白後 1–100 字（素材 1–255 字），不可含換行。
- `parentId` 必須存在、不可循環、一條鏈最多 8 層（`LIBRARY_DEPTH_MAX`）；同一層不可同名。
- `folderId` 必須存在或為 null；在垃圾桶的素材 `folderId` 一律 null，原資料夾記在 `trashed`（可以指向已刪除的資料夾）。
- `src` 必須在對應種類的資料夾：image → `assets/images/`、text → `assets/texts/`、audio → `assets/audio/`；同一個 `src` 只能出現一次（「同檔只留一筆」）。
- image 的寬高 > 0。

### Rust

- `format.rs`：`validate_asset_path` 改成 `validate_asset_path_in(src, dir)`，三個資料夾共用一套檔名規則；`ImageElement.src` 仍只接受 `assets/images/`（頁面上的圖片不能指向文字或音訊）。
- `library.rs`：`read(root)`（沒有檔案 → `None`；主檔壞了改讀 `.bak`）、`write(root, &Library)`（驗證 → 原子寫入）、`from_assets(&[AssetInfo])`（舊專案升級：全部未分類，`importedAt` = 開檔時間）、`referenced(&Library)`（所有素材含垃圾桶）。
- `mod.rs` / `io.rs`：
  - `open`：讀 `library.json`，沒有就由 `assets` 建立並寫入；`OpenedProject` 加 `library`。
  - `remove_orphan_assets`：保留清單加上素材庫；清理範圍擴大到 `texts/`、`audio/`。
  - `save_as`：另外複製 `library.json` 與素材庫的所有檔案。
  - `create_untitled`：空的素材庫（第一次寫入時才產生檔案）。
- commands：
  - `library_write { projectId, library }`：`projectId` 和目前專案不同就拒絕（見檢核 1）。
  - `library_import`（raw body，header 帶 `kind`：`file` / `text` / `audio`）：image 照舊用檔頭判斷；text 必須是 UTF-8、去掉 BOM、不含 NUL、不超過 200 KB（`TEXT_ASSET_MAX_BYTES`），副檔名只能是 `txt` / `md`（由前端給，Rust 只接受這兩個）；audio 用檔頭判斷（`ID3` 或 MPEG frame sync → mp3、`RIFF…WAVE` → wav、`OggS` → ogg、`ftyp` + M4A brand → m4a）。回傳 `src`。
  - `library_read_text { src }`：放到頁面時讀全文（前端不能直接 fetch asset URL，見檢核 4）。
  - `recovery_restore` 也回傳 `library`。

## 步驟（每步完成後停下，等使用者說「繼續」）

### 步驟 1：Rust 素材庫格式（不接到任何流程，畫面不變）

- `project/library.rs`：型別、驗證、`read` / `write`（`.bak`）、`from_assets`、`referenced`；`format.rs` 泛化 `validate_asset_path_in`。
- 共用 fixture `tests/fixtures/sample-library.json`（兩層資料夾、未分類、文字、音訊、一個在垃圾桶）。
- 測試：fixture 通過；循環、太深、同層同名、src 放錯資料夾、重複 src、`../` 都被拒絕；`.bak` 備援；舊 `assets` 轉換。

### 步驟 2：Rust 接上專案生命週期（畫面不變）

- `open` 讀或建立 `library.json`，`OpenedProject.library`；`remove_orphan_assets` 保留素材庫並清 `texts/`、`audio/`；`save_as` 複製素材庫；`recovery_restore` 回傳 `library`；`library_write`（含 `projectId` 檢查）。
- 前端只加型別（`OpenedProject.library`），先不使用。
- 測試：舊專案開檔產生 `library.json` 且內容 = 專案圖片；只在素材庫的圖片開檔後不被刪；另存後新資料夾有素材庫與所有檔案；`projectId` 不符被拒。

### 步驟 3：Rust 匯入文字與音訊（畫面不變）

- `library_import`（image / text / audio）、`library_read_text`。
- 測試：UTF-8 / BOM / NUL / 大小上限；四種音訊檔頭；改副檔名的執行檔被拒；讀文字只接受 `assets/texts/`。

### 步驟 4：前端純邏輯（畫面不變）

- `lib/library/` 的 types、`parseLibrary`、reducer、selectors、`treeDropZone`、`masonryLayout`。
- vitest：讀同一份 fixture；每個 action 的正常與 no-op（回傳同一個參考）；刪除資料夾的素材進垃圾桶並記住原資料夾；還原時原資料夾不在 → 未分類；重複匯入與垃圾桶裡的重複；數量含子資料夾；拖曳區域與禁止拖進子孫；瀑布流放進最矮欄。

### 步驟 5：`LibraryProvider` 取代 `EditorState.assets`（行為不變）

- 開檔 / 新增 / 復原時載入素材庫；整理後依序寫入；換專案與關閉視窗前 `flushLibrary()`；存檔與備份的 `assets` 由素材庫算出。
- `use-library-import` 取代 `use-image-import`；「上傳」面板改讀素材庫（全部，暫時不分資料夾）；內建相片也加入素材庫。移除 `asset/add` 與 `EditorState.assets`。

- 素材（含多選）→ 資料夾 / 未分類 / 垃圾桶；資料夾 → 子資料夾 / 前後排序 / 最上層；禁止拖進子孫（游標與無提示）；Esc 取消。
- 驗證：無頭 Edge 模擬 pointer 拖曳（每種放置結果、插入線位置、取消）。

### 步驟 8：垃圾桶

- 垃圾桶畫面：還原（原資料夾不在 → 未分類，toast 說明）、永久刪除、清空（確認）；從垃圾桶拖回資料夾 = 還原到那裡。
- 永久刪除**只移除清單**，檔案在下次開檔清理（頁面還在用就不刪）。
- 驗證：無頭 Edge＋桌面版人工（永久刪除後重開專案，頁面上的圖片還在、沒用到的檔案被清掉）。

### 步驟 9：文字與音訊

- 匯入接受 `.txt` / `.md` / 音訊；文字卡顯示摘錄、音訊卡顯示檔名與格式；資訊欄的提示（Markdown 原樣、音訊不能放頁面）；文字「放到目前頁面」建立文字物件。
- 驗證：vitest（分種類、`\r\n`）；無頭 Edge；桌面版人工（真的 .md 與 .mp3）。

### 步驟 10：「素材」精簡面板

- 取代「上傳」面板（id 不變，名稱、icon 改）：資料夾下拉（含數量）、開啟管理視窗、拖放區與「匯入...」（匯入到選的資料夾）、兩欄縮圖、點選放到頁面中央；音訊卡停用。
- 驗證：無頭 Edge；舊的停靠版面紀錄載入後面板仍在原位。

### 步驟 11：從面板拖到畫布

- 面板縮圖 `startPointerDrag` → 放在畫布上時用 `pageAt(screen)` 換成那一頁的座標，以放下點為中心建立（一筆復原；雙頁時放在哪頁就建在哪頁）；放在畫布以外 = 取消。

- 驗證：無頭 Edge（單頁 / 雙頁、縮放後位置正確、放在外面不建立）。

### 步驟 12：效能實測

- 產生 300 張大圖的測試專案，量開啟管理視窗與捲動的時間；不夠快時加：虛擬捲動（`masonryLayout` 已有座標）→ 仍不夠再由 Rust 產生縮圖快取（`assets/.thumbs/`，加 `image` crate，另外和使用者確認）。

## 檢核（可能的問題）

1. **寫入跑到別的專案**：debounce 中換專案，舊素材庫可能寫進新專案。→ `library_write` 帶 `projectId`，Rust 不符就拒絕；換專案 / 關閉前 `flushLibrary()`。
2. **「不儲存」關閉**：頁面回到上次存檔，素材庫保留新整理（已確認接受）。頁面引用的圖片不會因素材庫操作消失（永久刪除只移除清單，檔案靠開檔清理）。
3. **舊版 App 開新專案**：舊版的開檔清理只看 `project.magproj` 的 `assets`。若只同步「沒在垃圾桶」的圖片，舊版會刪掉垃圾桶裡的圖片檔，新版再開時那些素材變成缺檔。→ 同步**所有圖片（含垃圾桶）**；文字與音訊在別的資料夾，舊版不會動。另外，素材的檔案不見時卡片顯示「檔案遺失」，不讓整個素材庫讀取失敗。
4. **CSP 擋住讀文字**：`connect-src` 沒有 asset protocol，前端不能 `fetch` 文字檔。→ 摘錄存在 `library.json`（`excerpt`），放到頁面時用 `library_read_text` 讀全文。**不改 CSP**。
5. **CSP 擋住音訊**：沒有 `media-src`，前端拿不到音訊長度。→ 不顯示長度（已確認），不改 CSP。
6. **未命名專案**：素材庫寫在暫存資料夾；另存時一起複製；捨棄 / 下次啟動清除時跟著消失（和頁面一樣）。
7. **開檔清理的範圍變大**：只刪 `texts/`、`audio/` 裡沒被素材庫引用的檔案（頁面不會引用文字與音訊檔）。`.tmp` 殘檔照舊清掉。
8. **管理視窗是 modal**：開著時不能拖到畫布（用「放到目前頁面」）；編輯器與選單快捷鍵在 dialog 內不觸發，Delete / Esc 由視窗自己處理。Esc 先取消拖曳 / 改名，再關視窗。
9. **大量素材**：`library.json` 每次整份寫入，5000 筆約 1 MB，可以接受；寫入在 `async` command，不卡視窗。卡片圖片用原圖，見步驟 12。
10. **瀑布流順序**：CSS `columns` 會由上往下排、和「新的在前」不一致，所以用 `masonryLayout`（已知寬高，不量測）。
11. **重複匯入**：同 `src` 已在素材庫 → 不新增並提示；在垃圾桶 → 還原到目標資料夾（提示「已從垃圾桶還原」）。
12. **兩邊的驗證規則**：TS `parseLibrary` 與 Rust `library.rs` 用同一份 fixture 測；改一邊要改兩邊（同 `format.rs` 的慣例）。
13. **`EditorState.assets` 移除的影響**：`use-autosave`、`project-context`、`document/load` 的參數都要跟著改；步驟 5 用無頭 Edge 確認上傳 / 匯入 / 自動備份的行為不變。

## 設計建議（不影響已確認的決定）

1. **瀑布流用 JS 排版而不是 CSS columns**（檢核 10）：素材的寬高本來就存在 `library.json`，不需要量測；之後要虛擬捲動也只差一步。
2. **文字摘錄存在 `library.json`**（檢核 4）：不用為了卡片預覽放寬 CSP。
3. **「檔案遺失」卡片**（檢核 3）：素材庫和實際檔案不一致時仍可開啟、可刪除。
4. **精簡面板沿用 `upload` id**：使用者記住的停靠位置不變，不需要改 `parseDockLayout`。

## 計畫階段確認的決定（2026-10-08，使用者：全部照建議）

1. **瀏覽器模式（`npm run dev`）**：素材庫只存在記憶體（重新整理就消失），功能都能操作，無頭 Edge 才驗證得到。**修正**可行性報告「僅在桌面版可用」的寫法。`library_write` / `library_read_text` 在瀏覽器模式不呼叫：文字全文在匯入時就留在記憶體。
2. **音訊長度**：不顯示，只顯示格式與檔案大小；**不改 CSP**。
3. **文字檔大小上限**：**200 KB**（`TEXT_ASSET_MAX_BYTES`，TS 與 Rust 各一份，同值）。**修正**可行性報告的 1 MB。
4. **步驟 5**：移除 `EditorState.assets` 和上傳面板改讀素材庫放在**同一步**。
