# 14 物件屬性增加「填滿寬度」「填滿高度」實作計畫

任務檔：`14-物件屬性增加填滿寬度、高度.md`（不 commit）；本計畫要 commit。任務檔寫「輸出到 14-物件屬性增加填滿寬度、高度.md」，和任務檔同名會蓋掉它，所以照慣例加 `-實作`。

## 1. 需求理解

- 屬性面板加兩個按鈕（使用者另要求一起做「對齊內容區」六個按鈕，見第 4 節）：**填滿寬度** = 物件的左右邊貼齊內容區（x = 內容區左緣、寬 = 內容區寬）；**填滿高度** = 上下邊貼齊內容區（y = 內容區上緣、高 = 內容區高）。
- 「屬於功能屬性」：**一次性的動作**（按一下改位置與大小，一筆復原），不是存進文件、之後會跟著邊界變動的「約束」（使用者確認）。
- 內容區 = 邊界以內；四邊邊界都是 0 時是整頁（和內容區對齊線相同的定義）。

## 2. 可以沿用的東西（不重複造輪子）

| 需要的 | 已經有的 |
|---|---|
| 內容區 | `geometry.ts` 的 `contentGuides(size, margins).area`（內容區對齊線也用它；邊界全 0 = 整頁） |
| 改大小（含限制寬高比、最小尺寸） | `properties.ts` 的 `resizePatch(element, { width } \| { height }, keepRatio)` |
| 哪些物件有高度 | `properties.ts` 的 `hasEditableHeight`（文字沒有：高度由內容決定） |
| 寫入 | `element/update`（一次 = 一筆復原；reducer 已驗證） |
| 頁面尺寸 | 物件所在的 sheet（`selectActivePage`，頁面或主頁）；邊界是文件的 `margins`（所有頁共用） |

## 3. 物件評估（任務第 6 點）

| 物件 | 填滿寬度 | 填滿高度 | 說明 |
|---|---|---|---|
| 圖形（矩形、橢圓、多邊形、星形） | ✔ | ✔ | 外框 = 寬高，直接設 |
| 圖片 | ✔ | ✔ | 「限制寬高比」預設開，見第 4 節 6 |
| 文字 | ✔（行寬） | ✘ | 高度由文字決定，不顯示「填滿高度」（和「高」欄位相同的處理） |
| 圖形內文字 | — | — | 跟著圖形，不另外處理 |
| 頁碼、主頁上的物件（在頁面上看到的） | — | — | 不是可選取的物件 |
| 多選 | — | — | 屬性面板多選時只顯示「已選取 N 個物件」，這次不做（設計建議 3） |

## 4. 規則（★ = 使用者 2026-10-12 確認）

1. ★ **一次性的動作**：按一下改位置 / 大小，一筆復原；不存進文件，改邊界後物件不會跟著變。
2. ★ **這次另加「對齊內容區」按鈕**：靠左 / 水平置中 / 靠右 / 靠上 / 垂直置中 / 靠下，**只移動、不改大小**。
3. ★ **按鈕位置**：屬性面板「調整」分頁新增「對齊內容區」區塊（放在「大小」之前）：第一排「填滿寬度」「填滿高度」，第二排六個對齊 icon 按鈕。
4. ★ **填滿 + 旋轉過的物件**：**先把旋轉歸零再填滿**（同一筆 patch 含 `rotation: 0`，一筆復原）。按鈕 tooltip 註明「會把旋轉歸零」。
5. ★ **對齊 + 旋轉過的物件**：**用旋轉後的外框對齊**（看到的外緣貼齊內容區），旋轉不變（Affinity / Figma 的做法）。
6. ★ **填滿 + 限制寬高比開著**（圖片預設開）：照它，另一邊等比例跟著變（和在「寬」欄位輸入內容區寬度相同），可能超出內容區；另一個方向的位置不動。
7. **文字**：填滿寬度 = 行寬；沒有「填滿高度」（停用並說明高度由內容決定）。對齊的上下用**實際的文字高度**：`measureTextLayout`（和畫布、匯出同一個 Konva 量測）的行數 × 字級 × 行距，不用 `estimateTextHeight`（只是粗估）。
8. **內容區太小**（縮小紙張後邊界合計超過頁寬，檔案仍合法）：內容區寬 / 高小於最小物件尺寸時，填滿停用；對齊照常（只是移動）。
9. **已經對齊 / 填滿時**照常可按，reducer 沒有變化就不留復原紀錄（既有行為）。
10. **雙頁模式**：物件屬於目前頁，用目前頁的內容區；編輯主頁時用主頁的尺寸。邊界是文件設定，所有頁共用。

### 步驟 1：純邏輯（畫面不變）
- `geometry.ts`：把 `getElementBounds` 裡「外框四角旋轉後取外接框」抽成 `rotatedBoxBounds(x, y, width, height, rotation)`，`getElementBounds` 改用它（行為不變）；對齊需要用量到的文字高度算外框。
- 新檔 `lib/editor/content-align.ts`：

## 6. 設計建議

1. ~~對齊內容區按鈕~~：使用者決定這次一起做（見第 4 節）。
2. **「填滿頁面（出血）」**：滿版照片通常要貼齊頁緣而不是內容區。可以之後加，或做成「填滿到：內容區 / 頁面」的選項。
3. **多選時一起填滿**：例如兩張圖片同時填滿寬度。目前屬性面板多選時沒有內容，要做的話會一併加入多選的屬性區（範圍較大，建議另開任務）。
4. **MCP**：AI 已經能用 `get_document` 的邊界算出位置，再用 `update_element` 設定，不一定需要新工具；要做的話是 `fill_content_area { id, axis }` 一個工具。

## 7. 檢核

- **不改檔案格式、不改 Rust**：只是產生 `element/update` 的 patch，匯出不受影響。
- **一筆復原**：一次按鈕 = 一個 `element/update`。
- **和既有欄位一致**：填滿寬度的結果 = 在「寬」欄位輸入內容區寬度 + 在「X」輸入內容區左緣，只是合成一次寫入；限制寬高比與最小尺寸都沿用 `resizePatch`。
- **邊界是文件設定、所有頁共用**：不同尺寸的頁面各用自己的頁寬，同一組邊界。
- **風險**：填滿會把旋轉歸零（使用者決定），按鈕 tooltip 要說清楚；復原一次就回到原本的旋轉。
- **文字高度**：對齊上下必須用 Konva 量到的行數，粗估會讓「靠下」「垂直置中」偏掉；量測要在字型載入後（屬性面板出現時畫布已等字型載入，同 `ShapeLabelText` 的做法）。
