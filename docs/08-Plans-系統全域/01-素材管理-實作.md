# 01 素材管理：新增「專案管理」主選單 — 實作計畫

需求：[01-素材管理.md](01-素材管理.md)（2026-10-19）

## 1. 現況

| 入口 | 位置 | 程式 |
|---|---|---|
| 「素材」面板右上角的「開啟素材管理」按鈕 | 工具面板 → 素材 | `components/editor/panels/library-panel.tsx`（`openLibrary(目前資料夾)`） |
| **檔案 → 素材管理...** | 主選單「檔案」 | 指令 `file.library`（`lib/menu/commands.ts`）、`MENUS`（`menu-structure.ts`）、handler（`home-page.tsx`：`openLibrary()`） |

也就是說，**素材管理其實已經有主選單入口**（「檔案」裡，夾在「另存新檔」與「匯入 ▸」之間），只是不容易注意到。這次要做的是把它搬到新的主選單「專案管理」。
之後的 `02-樣式管理-樣式範本` 也要掛在「專案管理 → 樣式範本」，所以這個選單會是兩份需求的共同基礎。

## 2. 不重複造輪子

選單系統已經是「指令單一資料來源」的設計，新增一個主選單只要改資料，不用寫新元件：

- `MENUS`（`menu-structure.ts`）加一個 `MenuDefinition` → `AppMenubar` 自動渲染、助記鍵（`findMenuByMnemonic`）自動生效。
- 指令定義在 `COMMANDS`；handler 繼續用 `useLibraryDialog().openLibrary()`（和面板按鈕同一個）。
- MCP 的 `list_commands` 由 `MENUS` 推導「選單位置」，**不用改程式**，會自動變成「專案管理 › 素材管理...」。
- 測試 `menu-structure.test.ts` 已經守著：每個指令恰好出現一次、快捷鍵不重複、助記鍵不重複、主選單順序。

## 3. 使用者的決定（2026-10-19）

| # | 問題 | 建議 | 決定 |
|---|---|---|---|
| Q1 | 「檔案 → 素材管理...」要**移走**還是**兩邊都留**？ | 移走（一個指令只出現一次，測試也這樣守；兩處入口會讓人以為是不同功能）。面板按鈕保留。 | **移走** |

## 4. 設計建議

1. **選單名稱**：需求寫「專案管理」，照用。選單列目前都是兩個字（檔案、設定、視圖）＋「工具面板」四個字，「專案管理」四個字不突兀。
2. **只有一個項目的選單**：在樣式範本（02）做好之前，「專案管理」裡只有「素材管理...」。建議先接受（02 很快會補上），**不要**先放「樣式範本...」的佔位項目（佔位項目點了只會 toast「尚未實作」）。
3. **之後可以考慮搬進來的項目**（這次不做，只記錄）：「設定 → 文件 ▸」裡的色票...、字型...都是「存在這個專案裡、可以管理的東西」，概念上更接近「專案管理」；頁面設定、頁碼管理則比較像文件設定。是否整理要等 02 的設計確定再一起討論。
4. **快捷鍵**：素材管理目前沒有快捷鍵，這次也不加（Ctrl+Shift+L 等組合可以之後再談）。

## 6. 檢核

- **不改檔案格式、Rust command、素材庫邏輯**：只有選單資料與 handler key。
- 風險點只有指令 id 改名：所有引用都由型別檢查（`CommandId`、`CommandHandlers`）與 `menu-structure.test.ts` 守著；MCP 的 `mcp-tools.json` 由 snapshot 測試守著（沒更新會失敗）。外部（Claude Code）若記住舊 id `file.library`，會收到「找不到指令」的錯誤，需要先 `list_commands`——可以接受。
- 助記鍵 F / P / S / V / W 不重複（測試 `uses unique mnemonics`）；編輯器的工具鍵 P（鉛筆）不帶修飾鍵，不衝突（Alt+P 原本就是工具面板）。Alt+W 在 WebView2 沒有預設行為（步驟 4 實測確認）。
- 使用者已習慣的 Alt+P 會從「工具面板」變成「專案管理」（使用者決定）。
