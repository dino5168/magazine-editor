# 02 文件範本（需求原名：樣式範本）— 評估計畫

參考：[04-素材管理-實作.md](../01-Plans-2026-10/04-素材管理-實作.md)、[03-系統設計優先順序建議.md](../00-需求分析/03-系統設計優先順序建議.md)、[01-素材管理-實作.md](01-素材管理-實作.md)（「專案管理」選單）

> **名稱**：使用者決定叫「**文件範本**」（2026-10-19，Q6）：內容含紙張、主頁與範例頁，比「樣式」大。選單是「專案管理 → 文件範本...」。下文的「範本」都指文件範本。

## 1. 需求整理

| # | 需求 | 解讀 |
|---|---|---|
| 1 | 建立樣式範本管理 | 一個管理視窗：列出範本、改名、刪除、看內容 |
| 2 | 畫面仿素材管理，入口「專案管理 → 樣式範本」 | 選單已有「專案管理」（01，commit `0fe7377`），加一個指令即可 |
| 3 | 把設計好的專案存成範本，相同類型的專案可以套用 | 「從目前專案建立範本」 |
| 4 | 開新專案時選範本，**全域使用** | 範本存在這台電腦、不屬於任何專案；「檔案 → 新增」的對話框可以選範本 |

## 2. 結論：可行

**可行，而且大部分可以重用既有的程式**。最關鍵的設計決定是：

> **範本 = 一個「精簡過的專案資料夾」**（`project.magproj` ＋ 用到的 `assets/fonts`、`assets/images`），存在 App 的資料夾裡，另加一個描述檔 `template.json`。

理由（不重複造輪子）：

| 需要的能力 | 重用 |
|---|---|
| 檔案格式、驗證 | Rust `project/format.rs`：樣式表、色票、字型、主頁鏈、頁碼規則的驗證都已經有（`validate_text_styles`、`validate_swatches`、`validate_master_graph`…） |
| **舊版範本的升級** | `parse_project` 的版本判斷與升級（v1 → v16）。之後加物件樣式、欄格線時，範本**自動跟著升級**，不用另寫一套 |
| 原子寫入、`.bak` | `io.rs` 的 `write_project_atomic` / `read_project` |
| 複製字型檔與主頁上的圖片 | `io.rs` 的 `copy_assets`、`referenced_assets`（已包含主頁圖片） |
| 新專案載入範本內容 | `ProjectProvider.load(...)`；素材庫沿用「舊專案由 `assets` 建立素材庫」的路徑 |
| 管理視窗的外框、卡片、確認框 | `components/library/` 的版面與 `LibraryDialogProvider` 的寫法、`AlertDialog` |
| 縮圖（主頁） | `sheet-thumbnail.tsx`（Konva 小 Stage，已用在「頁面」面板） |
| 選紙張的新增文件對話框 | `new-document-dialog.tsx`（`useNewDocumentDialog`、`PageSetupFields`） |

**另一個好處**：之後新增的文件設定（物件樣式、欄格線、基線網格……）都存在 `EditorDocument` 裡，範本存的是整份文件的一部分，**新功能不用改範本程式就會被收進去**。這也回應了 2026-10-12 的顧慮：「範本是設計系統的打包，太早做只是複製檔案」——用專案格式存，早做也不會白做。

## 3. 範本裡放什麼（要決定，Q1）

`EditorDocument` 的欄位：

| 欄位 | 建議放進範本 | 說明 |
|---|---|---|
| `textStyles` 文字樣式 | ✅ | 需求的核心 |
| `swatches` 色票 | ✅ | 文字樣式的顏色連到色票（`fillSwatchId`），**只帶樣式不帶色票會斷連結** |
| `fonts` 專案字型（含字型檔） | ✅ | 文字樣式用到專案字型時**必須一起帶**，否則字型變成後備字型。字型授權見 §6 |
| `margins`、紙張尺寸 | ✅ | 樣式（字級、行寬）和紙張是一組的 |
| `masters` 主頁（含主頁上的物件與圖片） | ✅（建議） | 頁首、頁尾、頁碼框、底圖都在主頁；雜誌「版式」的主體 |
| `pageNumberRules` 頁碼規則 | ✅（建議） | 和主頁一起構成版式 |
| `pages` 頁面 | ✅ 建立時**勾選**要哪些頁（使用者決定） | 預設都不勾；沒勾任何頁時存一頁空白頁（套用第一個主頁），因為專案格式要求至少一頁。勾的頁面連同頁面上的圖片一起複製 |
| `name` 文件名稱 | ❌ | 新專案用「未命名文件」 |
| 素材庫 `library.json` | ❌ | 素材是專案的內容，不是樣式；跨專案素材庫是另一個需求 |

**依賴關係要自動處理**：存範本時，勾了「文字樣式」就一定帶它連到的色票與字型（UI 上直接說明，不讓使用者勾出壞掉的範本）。

## 4. 操作設計（建議）

### 4.1 入口

| 入口 | 動作 |
|---|---|
| 專案管理 → 文件範本... | 開範本管理視窗 |
| 範本管理視窗的「以目前專案建立範本...」 | 輸入名稱（＋可選說明）、勾選範例頁面 → 存成新範本 |
| 範本管理視窗的「以目前專案更新」 | 選中的範本換成目前專案的內容（同一個 id、保留名稱與說明，先確認） |
| 檔案 → 新增 → 新增文件對話框 | 左邊多一個「範本」分頁（或區塊）：空白（照現在選紙張）/ 我的範本 |

### 4.2 範本管理視窗：建議**兩欄**，不照抄素材管理的三欄

素材管理是三欄（資料夾樹｜瀑布流｜資訊），因為素材可能上千個、需要分類。範本通常是個位數到幾十個：

```
┌ 文件範本 ───────────────────────────────────────────────┐
│ [以目前專案建立範本...]                    [搜尋 ____ ] │
├──────────────────────────────┬──────────────────────────┤
│ ┌──────┐ ┌──────┐ ┌──────┐   │ ┌────────────────┐       │
│ │主頁縮圖│ │      │ │      │   │ │  主頁縮圖（大） │       │
│ │■■■■■ │ │      │ │      │   │ └────────────────┘       │
│ └──────┘ └──────┘ └──────┘   │ 名稱：校刊 2026（可改）    │
│ 校刊 2026  週報     型錄     │ 說明：……                  │
│ A4・3 主頁 B5・1    A4・2    │ 紙張 A4 直式、邊界 15 mm   │
│                              │ 文字樣式 8：標題、副標… │
│                              │ 色票 ■■■■■■（6）         │
│                              │ 字型：霞鶩文楷、自訂 1 套 │
│                              │ 主頁 3、頁碼規則 1、範例頁 2 │
│                              │ 建立 / 更新時間           │
│                              │ [用這個範本新增專案]       │
│                              │ [以目前專案更新] [刪除]   │
└──────────────────────────────┴──────────────────────────┘
```

- 卡片：第一個主頁的縮圖（沒有主頁 → 色票色條＋樣式名稱的 HTML 預覽，不用產生圖片）、名稱、紙張與主頁數。
- **不做資料夾、垃圾桶**（第一版）：刪除前確認即可，數量少時資料夾是負擔。之後範本多了再加（可重用 `library-tree.ts`）。
- **縮圖不存檔**：開視窗時讀範本內容用 `SheetThumbnail` 現場畫（同「頁面」面板），省掉縮圖產生與失效的問題。範本內容不大（不含頁面），讀得起；若實測太慢再改成存 PNG。

### 4.3 新增專案時套用

- 選了範本：紙張與邊界**照範本**（`PageSetupFields` 顯示範本的值）。要不要允許改紙張見 Q4。
- 結果：新的未命名專案，內容 = 範本的文件（樣式、色票、字型、主頁、頁碼規則＋範例頁面；沒有範例頁時一頁套用第一個主頁的空白頁），字型檔與主頁 / 範例頁的圖片複製進新專案的 `assets/`（素材庫沿用「由 `assets` 建立」，圖片進未分類）。
- 復原歷史是空的、標記未存檔（和現在新增一樣）。

## 5. 架構（建議）

```
%APPDATA%\com.mycompany.magazineeditor\templates\
  <範本 id（UUID）>\
    template.json        # templateVersion、name、description、createdAt、updatedAt
    project.magproj      # 專案格式（同 schemaVersion），pages = 勾選的範例頁（或一頁空白頁）
    assets\fonts\…       # 範本用到的專案字型檔
    assets\images\…      # 主頁與範例頁用到的圖片
```

- **Rust 是權威**（同專案檔）：新增 `project/templates.rs`（讀寫、列出、驗證、改名、刪除），`commands/templates.rs`：
  - `template_list` → 每個範本的描述 + 摘要（紙張、數量、名稱清單）
  - `template_read(id)` → 文件內容（管理視窗畫縮圖、詳細資訊用）
  - `template_create(name, description, document)` → 由前端傳「已經篩好的文件」（同 `project_save` 傳文件的方式），Rust 驗證、從**目前專案**複製用到的字型與圖片
  - `template_replace(id, document)`：以目前專案更新（同 `template_create` 的檢查與複製，先寫到暫存資料夾再換掉，失敗時舊範本不變）
  - `template_update_info(id, name, description)`、`template_delete(id)`
  - `project_new_from_template(id)` → 建立未命名專案資料夾、複製範本的 assets、回傳文件（前端照 `createNew` 載入）
- **前端不傳路徑**（沿用原則）：範本都以 id 指定，資料夾位置只有 Rust 知道。
- **前端**：`lib/templates/`（純邏輯：從文件取出範本內容 `templateDocument(document, options)`、依賴關係（樣式 → 色票 / 字型）、摘要）＋ `components/templates/`（管理視窗）＋新增文件對話框加範本選擇。
- **立即寫入、不進復原、不算未存檔**（同素材庫）：範本是 App 層級的資料，不是文件的一部分。
- 瀏覽器模式（`npm run dev`）：沒有檔案系統，選單顯示「僅在桌面版可用」（同其他檔案指令）。

## 6. 風險與檢核

| 風險 | 處理 |
|---|---|
| **字型授權**：使用者匯入的字型若是「預覽與列印」「可編輯」（不可安裝），複製進全域範本、再帶到別的專案，可能超出授權 | 建立範本時列出這類字型並提醒（對話框已有授權資訊 `embedding`）；是否直接排除見 Q1 補充 |
| 範本比 App 新（新版 App 建的範本給舊版用） | 沿用 `schemaVersion`：比 App 新的範本在列表標示「需要新版 App」、不能套用 |
| 範本檔損壞 | 列表標示「無法讀取」、可以刪除；不影響其他範本 |
| 主頁的圖片 / 字型檔在目前專案裡已經不見 | 建立範本時略過並提示（同匯出的 `skippedImages`） |
| 範本與目前專案的 id 衝突（套用到**現有**專案時） | 只有「套用到現有專案」才會遇到，見 Q2 |
| 範本的空白頁 | 專案格式要求至少一頁；新專案本來也有一頁，行為一致 |
| `project-font-<id>` 家族名稱 | 字型 id 隨範本一起複製，新專案的家族名稱不變，文字樣式的字串不用改 |
| 測試 | Rust：範本讀寫 / 驗證 / 複製（`tempfile`，沿用 fixture `sample.magproj`）；vitest：`templateDocument` 的篩選與依賴 |

## 7. 使用者的決定（2026-10-19）

| # | 問題 | 決定 |
|---|---|---|
| Q1 | 範本放哪些內容？ | 文字樣式、色票、專案字型、紙張與邊界、主頁（含物件與圖片）、頁碼規則，**加上範例頁面**；範例頁在建立時勾選（預設不勾） |
| Q2 | 只在新增專案時套用，還是也套用到目前專案？ | **只做新增專案**；套用到現有專案（衝突處理）另排 |
| Q3 | 管理視窗版面 | **兩欄**（列表＋資訊），不做資料夾與垃圾桶 |
| Q4 | 用範本新增時能不能改紙張？ | **紙張照範本，邊界可以改** |
| Q5 | 現有的「範本」工具面板（佔位） | **這次不動**；之後可讓它列出文件範本的主頁 / 範例頁 |
| Q6 | 名稱 | **文件範本** |
| Q7 | 以目前專案更新範本 | **要**（第一版） |

## 8. 建議的實作順序（確認後展開成實作計畫）

1. **Rust 範本儲存**：`templates.rs` 讀寫 / 列出 / 刪除 / 改名、驗證與升級（重用 `format.rs`），測試。
2. **前端純邏輯**：`templateDocument`（篩選＋依賴）、摘要，測試。
3. **建立範本**：`template_create`（複製字型與圖片）＋「以目前專案建立範本...」的對話框（名稱、說明、勾選範例頁、字型授權提醒）。
4. **管理視窗**：專案管理 → 文件範本...（列表、縮圖、資訊、改名、刪除）。
5. **新增專案套用**：`project_new_from_template` ＋ 新增文件對話框的範本選擇。
6. 以目前專案更新範本（`template_replace`）。
7. 驗證（無頭 Edge＋桌面版人工）與文件（`CLAUDE.md`、`docs/01`、`docs-website` 若需要）。
8. （另排）套用到現有專案、MCP（`list_templates`、`new_from_template`）、範本資料夾 / 匯出匯入範本檔（分享給別台電腦）。

每一步都可以單獨驗證；1–2 不動 UI，3 之後才看得到。
