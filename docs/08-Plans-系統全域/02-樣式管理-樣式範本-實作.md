# 02 文件範本 — 實作計畫

需求：[02-樣式管理-樣式範本.md](02-樣式管理-樣式範本.md)；評估與使用者的決定：[02-樣式管理-樣式範本-評估計畫.md](02-樣式管理-樣式範本-評估計畫.md)（§7）。

## 0. 範圍（照評估 §7 的決定）

- 名稱「**文件範本**」，入口「專案管理 → 文件範本...」（指令 `project.templates`）。
- 範本內容 = 目前文件的**文字樣式、色票、專案字型（含檔案）、紙張與邊界、主頁（含物件與圖片）、頁碼規則**，加上建立時**勾選的範例頁面**（預設不勾；都不勾時存一頁空白頁）。
- 只在「檔案 → 新增」時套用；紙張照範本、邊界可以改。
- 管理視窗兩欄（列表＋資訊）：改名 / 說明、刪除、以目前專案建立、以目前專案更新、用這個範本新增專案。
- 「範本」佔位面板不動；不做：套用到現有專案、資料夾、匯出 / 匯入範本檔、MCP 工具（`run_command project.templates` 會自動有）。

## 1. 資料與架構

### 1.1 存放位置（Rust 才知道，前端只用 id）

```
%APPDATA%\com.mycompany.magazineeditor\templates\
  <id>\                 # id = UUID
    template.json       # TemplateMeta
    project.magproj     # 專案格式（ProjectFile，同 schemaVersion）；.bak 照 write_project_atomic
    assets\fonts\…      # document.fonts 的檔案
    assets\images\…     # 主頁與範例頁用到的圖片
  .<id>.<uuid>.tmp\     # 建立 / 更新時的暫存資料夾（完成才 rename，失敗刪掉；啟動時清掉殘留）
```

`TemplateMeta`（`template.json`，Rust 是權威，TS 手寫對應）：

```jsonc
{
  "templateVersion": 1,        // 比 App 新 → 列表標示「需要新版 App」，不能用
  "name": "校刊 2026",          // 去頭尾空白、1–50 字、範本之間不重複（同色票名稱的規則）
  "description": "",           // 0–200 字
  "createdAt": "…", "updatedAt": "…"   // RFC 3339（同 project::now）
}
```

### 1.2 範本的 `project.magproj`

就是一份 `ProjectFile`（重用 `format.rs` 的 `validate_content`、`parse_project` 的升級、`io::write_project_atomic` / `read_project`）：

- `document`：目前文件，但 `pages` = 勾選的範例頁（依原順序），都不勾 → 一頁空白頁（`createPage`，紙張 = 第一頁、背景 = 白、`masterId` = 第一頁的主頁）；`name` = `"未命名文件"`（新專案的名稱）。其他欄位（`margins`、`pageNumberRules`、`textStyles`、`swatches`、`fonts`、`masters`）原樣。之後新增的文件欄位**自動跟著**。
- `assets`：範本裡用到的圖片的 `AssetInfo`（從素材庫取名稱與尺寸，`projectAssets` 的子集）。新專案的素材庫由它建立（`library::load_or_create` 的「沒有 `library.json`」路徑，圖片進未分類）。

### 1.3 commands（`commands/templates.rs`，邏輯在 `project/templates.rs`）

| command | 做什麼 |
|---|---|
| `template_list` | 每個範本：`id`、`meta`、`document`（讀得到時）或 `problem`（`unsupportedVersion` / `damaged`）、`root`（畫縮圖的 asset URL 用）。依 `updatedAt` 新到舊 |
| `template_create(meta, content)` | 驗證 → 暫存資料夾寫 `project.magproj`、`template.json`，從**目前專案資料夾**複製 `referenced_assets` → rename。缺的檔案略過並回報數量 |
| `template_replace(id, content)` | 同上，但保留 `name` / `description` / `createdAt`；寫好暫存資料夾後換掉舊的（舊的先改名、成功才刪），失敗時舊範本不變 |
| `template_update_info(id, name, description)` | 只改 `template.json` |
| `template_delete(id)` | 刪整個資料夾 |
| `project_new_from_template(id)` | `create_untitled` → 複製範本的 assets → `library::load_or_create` → `activate`；回傳 `OpenedProject`（前端照開檔載入） |

- 名稱重複、空白、太長 → `InvalidInput`（中文訊息）；id 只接受 UUID 字元（同 recovery 的檢查）。
- **asset protocol scope**：`template_list` 時 `allow_directory(templates_base)`，管理視窗的縮圖才讀得到範本裡的圖片。
- 會做檔案 I/O 的都是 `async fn`。

### 1.4 前端

```
src/lib/templates/
  types.ts               # TemplateMeta / TemplateEntry / TemplateProblem（對應 Rust）、TEMPLATE_NAME_MAX_LENGTH 等常數
  template-api.ts        # invoke 包裝（回傳 Result，同 project-api.ts）
  template-content.ts    # templateContent(document, library, pageIds) → ProjectContent；templateSummary(document)；templateNameError
  __tests__/
src/components/templates/
  templates-dialog.tsx   # TemplatesDialogProvider / useTemplatesDialog().openTemplates()；兩欄
  template-card.tsx      # 卡片：第一個主頁（或第一頁）的 SheetThumbnail、名稱、紙張・主頁數
  template-info.tsx      # 右欄：大縮圖、名稱 / 說明（InlineNameInput）、摘要、按鈕
  save-template-dialog.tsx  # 建立 / 更新：名稱、說明、勾選範例頁（縮圖列表）、字型授權提醒
```

- 範本**不進復原歷史、不算未存檔**（同素材庫）；建立範本讀的是編輯中的文件（`getSnapshot()`，含未存檔的修改）。
- 瀏覽器模式（`npm run dev`）：選單顯示「僅在桌面版可用」。

## 2. 步驟（一次一步，每步完成後跑測試、更新進度、等使用者確認）

### 步驟 1：Rust 範本儲存（不接 command、不動 UI）

- `project/templates.rs`：`TemplateMeta`、`templates_base`、`list` / `create` / `replace` / `update_info` / `delete` / `new_project_from`，全部以路徑為參數（方便測試）。
  - `create` / `replace`：`format::validate_content` → 暫存資料夾 → `write_project_atomic` → 寫 `template.json`（同樣原子寫入）→ `io::copy_assets(source_root, tmp, referenced_assets(...))` → rename。
  - `list`：逐一 `read_project`（升級舊版、驗證）；`UnsupportedVersion` / 壞檔 → `problem`，不影響其他範本。
  - 名稱規則：`validate_template_name`（同 `validate_swatches` 的名稱規則與上限）。
  - 啟動時的清理 `clean_up`：刪掉 `.*.tmp`；`replace` 中途當機留下的 `.<id>.<uuid>.old` 在新的沒放上去時搬回來，否則刪掉（`lib.rs` 的呼叫在步驟 2 接上）。
- 測試（`tempfile`、fixture `sample.magproj`）：建立後讀回相同、字型與主頁圖片有複製、缺檔略過、名稱重複 / 空白拒絕、`replace` 失敗時舊範本不變、比 App 新的版本標示 problem、壞的 JSON 不影響其他、`new_project_from` 產生素材庫且圖片進未分類。
- 驗證：`cargo test`。

### 步驟 2：commands 與前端 API

- `commands/templates.rs` 六個 command、`commands/mod.rs`、`lib.rs` 的 `generate_handler!`；asset scope。
- `lib/templates/types.ts`、`template-api.ts`。
- 驗證：`cargo check`、`npm run build`（型別對得上）。

### 步驟 3：前端純邏輯 `template-content.ts`

- `templateContent(document, library, pageIds)`：篩出範例頁（沒勾 → 空白頁）、`name` 重設、`assets` = 範本用到的圖片（從素材庫取 `AssetInfo`）。
- `templateSummary(document)`：紙張（`findPageSizePreset`）、邊界、樣式 / 色票 / 字型 / 主頁 / 頁碼規則 / 範例頁數量、色票顏色、樣式名稱。
- `restrictedFonts(document)`：授權是「預覽與列印」/「可編輯」的專案字型（提醒用）。
- `templateNameError(name, others)`：中文訊息（同 `swatchNameError`）。
- 測試（fixture `sample.magproj`）：範例頁篩選與順序、空白頁的主頁、主頁圖片與範例頁圖片都進 `assets`、沒勾的頁上的圖片不進、名稱規則。
- 驗證：`npm test`。

### 步驟 4：管理視窗與選單

- `COMMANDS` 加 `project.templates`「文件範本...」，放進 `MENUS` 的「專案管理」（素材管理之後）；handler 開 `TemplatesDialogProvider`（包在 `home-page.tsx`，同 `LibraryDialogProvider`）。
- 兩欄：左邊卡片格（搜尋名稱；空的時候說明怎麼建立）、右邊資訊（大縮圖、可改名稱 / 說明、摘要、「用這個範本新增專案」（步驟 6 才接）、「刪除」（確認））。有 problem 的範本：灰卡、只能刪除。
- 縮圖：`SheetThumbnail`，圖片的 URL 用範本的 `root`；**字型**：範本的專案字型不另外登記，用後備字型畫（已知限制，縮圖夠用）。
- `menu-structure.test.ts` 更新；`npx vitest run mcp-tools -u`（`run_command` 多 `project.templates`）。
- 驗證：無頭 Edge（瀏覽器模式只能看到「僅在桌面版可用」）＋ 桌面版人工：開視窗、空狀態。

### 步驟 5：建立與更新範本

- 管理視窗上方「以目前專案建立範本...」→ `SaveTemplateDialog`：名稱（預設 = 文件名稱，重複時錯誤）、說明、範例頁勾選（頁面縮圖列表，全選 / 全不選）、受限授權字型的提醒 → `template_create`。缺檔時 toast 提示數量。
- 右欄「以目前專案更新」→ 同一個對話框（名稱 / 說明唯讀、範例頁重新勾選）→ 確認「會取代『xxx』的內容」→ `template_replace`。
- 先 `flush()` 素材庫？不需要（只讀圖片檔案，不讀 `library.json`）。
- 驗證：桌面版人工（建立含主頁圖片、專案字型、範例頁的範本；檔案總管看資料夾；更新後內容變了、名稱不變）。

### 步驟 6：新增專案時選範本

- 新增文件對話框（`new-document-dialog.tsx`）左邊加切換「空白 / 文件範本」：
  - 空白：照現在（紙張卡片）。
  - 文件範本：範本卡片（同 `TemplateCard`），選了之後右邊 `PageSetupFields` 的紙張 / 方向停用、顯示範本的值，邊界可以改（`validatePageSetup` 照樣檢查）。
- `ChooseNewSetup` 回傳改成 `{ kind: "blank"; setup } | { kind: "template"; id; margins } | null`；`use-project-commands.ts` 的 `newImpl` 依 kind 呼叫 `createNew(setup)` 或新的 `createFromTemplate(id, margins)`（`ProjectProvider`：`project_new_from_template` → 換掉 `margins` → `load(..., saved: true)`，和空白新專案一樣不算未存檔）。
- 管理視窗的「用這個範本新增專案」：走同一個 `newProject`，對話框直接選在那個範本。
- 驗證：無頭 Edge 看不到（桌面版限定）→ 桌面版人工：新專案的樣式、色票、字型、主頁、頁碼、範例頁、圖片都在；字型的畫面正確；存檔後重開正常；素材庫有範本的圖片。

## 3. 檢核

| 項目 | 結論 |
|---|---|
| 檔案格式 | **專案檔不變**（不提升 `SCHEMA_VERSION`）。新的只有 `template.json`（自己的 `templateVersion`） |
| 重用 | 驗證 / 升級（`format.rs`）、原子寫入（`io.rs`）、複製檔案（`copy_assets` + `referenced_assets`，已含主頁與字型）、未命名專案（`create_untitled` / `activate`）、素材庫建立（`load_or_create`）、縮圖（`SheetThumbnail`）、對話框外框（`SettingsDialog`）、名稱輸入（`InlineNameInput`） |
| 一致性 | 範本裡的東西本來就互相一致（整份文件的樣式 / 色票 / 字型 / 主頁原樣帶走），**沒有「樣式連到不存在的色票」的情況**；範例頁的 `masterId` 一定在 |
| 字型家族 `project-font-<id>` | id 跟著範本走，新專案的文字樣式字串不用改 |
| 頁碼規則 | 依頁序，範例頁變少時規則照存（`to` 可以超過頁數，本來就合法） |
| 失敗時 | 建立 / 更新都先寫暫存資料夾，不會留下半個範本；壞掉的範本只影響自己 |
| 未存檔的修改 | 建立範本用編輯中的內容；圖片 / 字型匯入時就已寫進專案資料夾，複製得到 |
| 已知限制 | 管理視窗縮圖不用範本的專案字型；範本只在這台電腦（換電腦要另做匯出 / 匯入）；受限授權字型只提醒不阻擋 |
