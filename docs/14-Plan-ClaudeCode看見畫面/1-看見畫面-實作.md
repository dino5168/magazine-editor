# 01 讓 Claude Code「看見」頁面 — 實作計畫

來源：`App-開發建議事項.md`（web-magazine 工作區用 MCP 編文件時發現的需求，2026-10-31）。本檔是評估之後的修正版：保留兩個工具的目標，但改用這個專案已有的量測與匯出程式。

## 0. 問題

MCP 工具只回傳 JSON，Claude 看不到排出來的樣子，只能用座標推算：

- 圖形內的文字超出圖形（表格儲存格的長字）。
- 改了文字以後，下方物件被壓到。
- 線條上的文字標籤和其他物件重疊。

結果每一頁都要使用者自己翻頁檢查。

## 1. 現況（評估時確認的事實）

| 事實 | 位置 | 影響 |
|---|---|---|
| 文字物件**沒有存高度**（只有 `width`，高度跟著文字長） | `types.ts` `TextElement` | `list_elements` / `get_element` 回傳文字物件時**刻意省略 `height`**（`queries.ts:84`），Claude 只能估行距 |
| `getElementBounds` 的文字高度是**估計值**（`estimateTextHeight`：全形字 1 em、半形字固定寬度） | `lib/editor/geometry.ts` | 檢查版面不能直接用它，要換成量測值 |
| 匯出時已經用和畫布同一套方法量測文字 | `lib/export/text-layout.ts` `measureTextLayout`；圖形內文字用 `labelAsText` + `labelFrame` | `check_layout` 直接重用，不另外估算 |
| `buildExportRequest` 把主頁內容、跨頁物件、頁碼、文字變數都展開進每一頁 | `lib/export/export-request.ts` `exportedPage` / `withPageNumbers` | 檢查與渲染都看展開後的頁面，和匯出結果相同 |
| 封面已經用 typst-render 把一頁畫成 PNG / JPEG | `src-tauri/src/export/cover.rs` `render_cover` → `pptx/raster.rs` `rasterize_at` | `render_page` 一般化這段，不用 Konva |
| Konva 的 `toDataURL` 在不在 DOM 的 canvas 上重畫時，**全形標點會被擠壓** | `progress.md` 已知問題、`editor-text.md` | `render_page` **不用** Konva 截圖 |
| pipe 回應只有 `Ok { data }`（JSON），橋接程式一律包成文字回傳 | `mcp/protocol.rs`、`bin/magazine-mcp.rs` | 要加圖片的回應類型 |
| 橋接程式讀回應的上限是 `MAX_LINE_BYTES` = 1 MiB | `mcp/client.rs` | 有照片的頁面轉 base64 後可能超過 |
| 線條**沒有**連接圖形的資料 | `types.ts` `LineElement` | 建議書的「線條和它連接的圖形」不存在，第一版重疊檢查跳過線條 |
| rmcp 3.5.1 有 `ContentBlock::image(data, mime_type)` | rmcp `model/content.rs` | 橋接程式可以直接回圖片 |
| Python SDK 只讀 `content[0]["text"]` | `sdk/python/magazine/client.py:106` | 回傳圖片時 SDK 要跟著改 |

## 3. 步驟 1：回傳文字的量測高度

### 3.1 `ToolContext` 加量測函式

```ts
// run-tool.ts
export interface ToolContext {
  ...
  /** Lays out one text element like the canvas (`measureTextLayout` in the app; a fake in tests). */
  readonly measure: (element: TextElement) => TextLayout;
  /** Measures one unwrapped line (`measureLineWidth`; page numbers). */
  readonly measureWidth: MeasureTextWidth;
}
```

- App：`use-mcp-bridge.ts` 建 context 時傳 `measureTextLayout` / `measureLineWidth`（和匯出同一組）。
- 測試：`__tests__/tool-session.ts` 給假的量測（每字 1 em、`lines = ceil(寬 / width)`），結果可預期。
- 字型：MCP 呼叫時編輯器已經顯示，字型已載入（和匯出的前提相同）。

### 3.2 高度的算法

- 新函式 `measuredTextHeight(element, measure)`（放 `lib/automation/layout.ts` 或 `lib/editor/geometry.ts` 旁）：`textBlockHeight(layout.lines.length, fontSize, lineHeight)`（`shape-label.ts` 已有，和畫布的 Konva 高度同公式）。
- 新函式 `measuredBounds(element, measure)`：和 `getElementBounds` 相同，只是文字的本地高度用量測值（旋轉一樣套 `rotatedBoxBounds`）。

### 3.3 工具輸出

- `list_elements`、`get_element` 的文字物件加上 `height`（四捨五入到 0.1 pt）。
- 說明改成「文字物件的 height 是依目前字型與換行量出來的高度（不能修改；改 width 或文字會變）」；`update_element` 收到文字的 `height` 仍然拒絕（維持現狀）。
- `queries.ts:84` 的註解與型別跟著改。

### 3.4 測試

- `run-tool.test.ts`：文字物件有 `height`，值 = 假量測的行數 × 字級 × 行高。
- `mcp-tools.test.ts` 更新快照（說明文字變了）。

## 4. 步驟 2：`check_layout`

### 4.1 參數與回傳

| 參數 | 型別 | 說明 |
|---|---|---|
| `pageId` | string，選填 | 頁面或主頁；省略 = 使用者正在看的頁面（和其他工具相同） |

```json
{
  "pageId": "...",
  "pageName": "3",
  "checked": 18,
  "issues": [
    { "type": "textOverflow", "severity": "error", "id": "<圖形 id>", "summary": "「每月營收…」", "overflowPt": 6.5, "direction": "height" },
    { "type": "overlap", "severity": "error", "ids": ["<文字 id>", "<圖形 id>"], "areaPt2": 120.4, "summary": "「目錄…」蓋到圖形" },
    { "type": "outOfPage", "severity": "error", "id": "...", "overflowPt": { "right": 12 } },
    { "type": "outOfMargin", "severity": "warning", "id": "...", "overflowPt": { "bottom": 4 } }
  ],
  "truncated": false
}
```

- `readOnly: true`，不 dispatch，不產生復原紀錄，不切換頁面。
- **可以放進 `batch`**（同步、只讀 state）：看到的是批次進行到那一步的文件。
- 問題最多回 50 筆（`LAYOUT_ISSUES_MAX`），超過時 `truncated: true`。
- 主頁帶來的物件或頁碼出現在問題裡時，加 `"source": "master"`（id 是主頁上的原物件）或 `"source": "pageNumber"`，讓 Claude 知道要改的是主頁還是本頁。

### 4.2 檢查的對象

- 純函式 `checkLayout(document, pageId, measure, measureWidth)`，放 `src/lib/automation/layout-check.ts`（vitest 測）。
- 一般頁面：用和匯出相同的展開結果（主頁內容、跨頁物件、頁碼、文字變數）。`export-request.ts` 抽出一個 export 的 `exportedSheet(document, pageIndex, measureWidth)`，給 `buildExportRequest` 和 `checkLayout` 共用，**不另寫一份展開邏輯**。複本 id（`masterCopyId` / `spilloverCopyId`）對回原物件 id。
- 主頁：只檢查主頁自己的物件（沒有頁碼）。
- 外框一律用 §3.2 的 `measuredBounds`。

### 4.3 各項規則

| 類型 | 規則 | 等級 |
|---|---|---|
| `textOverflow`（圖形內文字） | 量出的文字高度（`textBlockHeight`）> `labelFrame(shape).height` + 0.5 pt → `overflowPt` = 差值、`direction: "height"`；任一行寬 > 文字框寬 + 0.5 pt → `direction: "width"` | error |
| `textOverflow`（文字物件） | 任一行寬 > 換行寬度（扣掉左右縮排）+ 0.5 pt（放不下的長英文單字）；高度不會超出（文字框跟著長） | error |
| `overlap` | 見 §4.4 | error |
| `outOfPage` | 外框超出頁面 > 0.5 pt。跨頁的雙頁（`spreadOf`）改用 `spreadBounds`：越過中縫是刻意的跨頁物件，不算。蓋滿整頁再出血的背景（外框包住整頁）不算 | error |
| `outOfMargin` | 在頁面內、但超出 `marginBounds` > 0.5 pt；跳過主頁物件、頁碼、已經 `outOfPage` 的物件、蓋滿整頁的背景 | warning |

### 4.4 重疊的排除規則（第一版從簡單做起）

只檢查**至少一方是文字**的組合（文字物件，或有文字的圖形的文字區）：

1. 交集面積 ≤ 1 pt² → 不算（相鄰的表格儲存格面積是 0，不會誤報）。
2. 有一方是線條 → 跳過（沒有連接資料，線條外框又很大，第一版不判斷）。
3. 文字**完全在**圖形 / 圖片的外框內 → 不算（刻意放在色塊或照片上的文字）。
4. 圖形自己的文字區和自己 → 不算。
5. 其他（文字和文字、文字一部分壓到圖形 / 圖片、文字壓到頁碼）→ 回報。

旋轉的物件用旋轉後的軸對齊外框，可能多報；說明裡寫清楚。

### 4.5 測試（`layout-check.test.ts`，對應建議書的驗收 1、2）

- 30 pt 高的矩形塞三行 9 pt 文字（行高 1.4 → 37.8 pt，文字區 30 − 2 × `LABEL_PADDING_PT` = 22 pt）→ `textOverflow`。
- 兩個文字框部分重疊 → `overlap`；3×3 相鄰的矩形加文字（表格）→ 沒有問題。
- 文字完全在色塊內 → 沒有 `overlap`；文字一半壓到色塊 → 有。
- 雙頁跨中縫的物件 → 沒有 `outOfPage`；超出外側 → 有。
- 主頁物件壓到本頁文字 → `source: "master"`、id 是主頁原物件。
- 多於 50 筆 → `truncated`。
- 放進 `batch`：前一個操作新增的文字被檢查到。

## 5. 步驟 3：`render_page` 的 Rust 端

### 5.1 一般化 `cover.rs`

新檔 `src-tauri/src/export/page_image.rs`：

```rust
pub struct PageImageOptions {
    /// Longest edge of the picture in px (clamped to 200..=2000).
    pub max_px: u32,
    /// Part of the page to draw, in pt; None = the whole page.
    pub region: Option<Rect>,
}

/// Draws one page of the request (the same layout as the PDF) as a PNG, or a JPEG when it has a photo.
pub fn render_page_image(root: &Path, request: ExportRequest, page_index: usize, options: &PageImageOptions, fonts: Vec<Font>) -> AppResult<PageImage>;
```

- 只保留那一頁再排版（和封面一樣：200 頁的文件也只排一頁）。頁碼與主頁內容已經由前端展開進那一頁，不受影響。
- 比例：`pixel_per_pt = max_px / max(區域寬, 區域高)`，上限 6 px/pt（避免 `region` 很小時整頁畫得非常大）；有 `region` 時先畫整頁再用 `image` crate 裁切。
- 格式：沒照片 PNG；有照片 JPEG（沿用 `has_raster_photo`）。
- `render_cover` 改成呼叫它（`max_px` = 600、寬度為準），封面的測試不變。
- 回傳 `PageImage { bytes, format, width_px, height_px, page_width_pt, page_height_pt }`。

### 5.2 pipe 協定加圖片

- `protocol.rs`：`ToolResponse` 加 `Image { data: String /* base64 */, mime_type: String, text: String }`。
- `client.rs`：讀回應的上限分開：`MAX_RESPONSE_BYTES` = 16 MiB（2000 px 的 JPEG 遠小於此；請求仍是 1 MiB）。
- base64：`Cargo.toml` 加 `base64`（Cargo.lock 已經間接有，鎖同一版）。

### 5.3 在 App 的 Rust 端畫圖（`bridge.rs`）

前端**只交出匯出請求**，圖片不經過 WebView：

1. 前端的 `render_page` handler 回 `{ "render": { "request": <ExportRequest>, "pageIndex": 0, "maxPx": 1200, "region": null, "pageId": "...", "pageName": "3" } }`。
2. `call_frontend` 收到 `tool == "render_page"` 的 `Ok` 回應時，反序列化成 `RenderJob`，用 `app.state::<ProjectState>()` 的專案資料夾與 `ExportState::fonts()`，在 `spawn_blocking` 裡呼叫 `render_page_image`，回 `ToolResponse::Image`（`text` = 「頁面 3，595.28×841.89 pt，輸出 1200×1697 px」）。
3. 失敗（排版錯誤、反序列化錯誤）回 `ToolResponse::Error` 的中文說明。

時間：前端 30 秒逾時在畫圖之前就結束了；畫圖要在橋接程式的 40 秒 `CALL_TIMEOUT` 內完成（只排一頁再點陣化，和封面相同；還沒量過，步驟 6 量一次）。

### 5.4 測試（`cargo test`）

- `page_image`：整頁的尺寸與 `max_px` 一致；`region` 裁切後尺寸與比例正確、取到的像素是那一塊的顏色；有照片時是 JPEG；比例上限生效。
- `cover`：原有測試照樣通過。
- `protocol`：`Image` 的 JSON 往返；`client`：超過 1 MiB 的回應讀得到。
- `bridge`：`RenderJob` 的反序列化（含 `region`）。

## 6. 步驟 4：`render_page` 的前端、橋接程式、SDK

### 6.1 工具定義

| 參數 | 型別 | 說明 |
|---|---|---|
| `pageId` | string，選填 | 一般頁面；省略 = 使用者正在看的頁面。主頁回錯誤（「主頁請預覽套用它的頁面」） |
| `maxWidth` | number，選填 | 圖片長邊（px），預設 1200，範圍 200–2000 |
| `region` | `{ x, y, width, height }`，選填 | pt；只畫這一塊，同樣用 `maxWidth` 放大 |

- `readOnly: true`，不 dispatch。
- 加進 `NOT_IN_BATCH`（結果要經 Rust 畫圖，批次裡拿不到圖片）。
- 說明寫：圖片會占 context，先用 `check_layout`；看小字細節用 `region`；長邊超過約 1 568 px 的圖會被 Claude 縮小，沒有必要更大。

### 6.2 前端只量一頁

`buildExportRequest` 加選項 `{ pageIndexes?: readonly number[] }`：頁碼與主頁仍依整份文件展開（頁碼要知道是第幾頁），但**只量測、只保留**指定的頁。200 頁的文件不會為了看一頁量 200 頁的文字。

### 6.3 橋接程式

`magazine-mcp.rs` 的 `call_tool`：`ToolResponse::Image` → `CallToolResult::success(vec![ContentBlock::image(data, mime_type), ContentBlock::text(text)])`。

### 6.4 Python SDK

- `client.py`：結果的 `content` 有 `type: "image"` 時回 `{"image": <bytes>, "mimeType": ..., "info": <text>}`，不再只讀 `content[0]["text"]`。
- `generate.py` 重新產生 `_tools.py`；`sdk/python` 的測試加一個圖片回應的案例。
- `tools/` 的腳本可以加一個 `--render` 選項把頁面存成 PNG（選做）。

### 6.5 測試（vitest）

- `render_page` handler：回 `render.request` 只含指定的那一頁、`textLayouts` 只有那一頁的物件；頁碼正確（第 3 頁的頁碼是 3）。
- 主頁 id → 錯誤；`region` 超出頁面 → 錯誤；放進 `batch` → `NOT_IN_BATCH` 錯誤。
- 使用者的 `activePageId`、縮放、捲動不變，沒有新的復原紀錄。

## 8. 步驟 6：驗證

無頭 Edge 的瀏覽器模式沒有 MCP，這一步要在 `npm run tauri dev` + Claude Code 進行：

1. `cargo build --bin magazine-mcp`，在 Claude Code `/mcp` 重新連線。
2. 建議書的驗收標準 1–5：塞滿文字的 30 pt 圖形、兩個重疊的文字框、表格不誤報、`render_page` 的圖片在 Claude Code 看得到且沒有選取框、`region` 放大、使用者的頁面與復原紀錄不變。

5. 量一次 `render_page` 的時間（A4、有照片 / 沒照片），記在本檔。
