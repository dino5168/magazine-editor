# 大檔拆分（專案重構迭代 7）— 實作計畫

來源：`1-專案重構-實作.md` §5「迭代 7」（使用者決定另開任務，2026-10-29 開始）。工作規則同重構計畫：**一步 = 一個檔案**，每步完成後跑測試、更新本文件的「狀態」，等使用者說「繼續」再做下一步；commit 等使用者指示。

## 1. 為什麼

Claude 讀檔是整份進 context。大檔裡常常只需要一小段（改一個驗證、加一個 action），卻要付整個檔案的 token；搜尋結果也比較難判斷要讀哪一段。拆成**依主題分開的小檔**後，只讀需要的那一份。

## 2. 原則

1. **不改行為**：只搬程式碼（原文搬，不順手重構、不改名、不改註解）。唯一允許的修改：`mod` / `use` / `import` / `export`、可見度（Rust 的 `pub(super)` / `pub(crate)`）。
2. **對外路徑不變**：原本的檔案保留成入口，外部的 `import` / `use` 不用改（`format::X` 在 Rust 有 86 處、`editor-reducer` 有 34 處 import）。
   - Rust：`format.rs` → `format/mod.rs`，子模組用 `pub use` 匯出原本的公開項目。
   - TS：`editor-reducer.ts` 留著型別、selectors、`editorReducer`；handlers 搬到子資料夾再組回 `HANDLERS`。
3. **驗證**（每步都做）：
   - 測試**數量**與拆分前相同、全部通過（`cargo test` / `npm test`）。
   - `npx tsc --noEmit -p tsconfig.json`；`cargo clippy` 警告數不變（目前 1 個）。
   - **程式碼沒遺失**：一次性腳本比對「拆分前的非空白行」與「拆分後所有新檔的非空白行」（扣掉 `mod` / `use` / `import` / `export` 行），兩邊的多重集合相同。
4. 拆完後同步：規則檔的 `paths:` glob、規則檔與 skills 裡的檔名、根 `CLAUDE.md` 的指令範例、`docs/02-architecture.md`。

測試仍是一個檔（約 900 行）：讀測試的機會少，再拆要決定分組，留到之後。

### 步驟 2：`src-tauri/src/export/render.rs`（1 185 行）→ 測試搬出去

`#[cfg(test)] mod tests;` + `export/render/tests.rs`（707–1185，約 480 行），和 `export/epub/tests.rs` 同一個做法。`render.rs` 剩約 710 行。

### 步驟 3：`src/lib/editor/editor-reducer.ts`（1 095 行）→ `src/lib/editor/reducer/`

| 檔案 | 內容 | 約 |
|---|---|---:|
| `editor-reducer.ts`（入口，路徑不變） | 型別（`EditorState`、`EditorAction`…）、`isBatchableAction`、`createInitialState`、selectors、組合 `HANDLERS`、`editorReducer`、`rememberPage` | 400 |
| `reducer/helpers.ts` | `commit`、`updateSheet`、`duplicateIn`、`reconcileSelection`、patch 驗證、`updateElements`、`linkElements`…（384–589） | 210 |
| `reducer/element-handlers.ts` | `element/*`（含 `element/applyTextStyle`） | 130 |
| `reducer/page-handlers.ts` | `page/*`、`master/*` | 150 |
| `reducer/style-handlers.ts` | `textStyle/*`、`swatch/*`、`font/*` | 80 |
| `reducer/document-handlers.ts` | `document/*`、`history/*`、`selection/*`、`view/*`、`tool/set` | 150 |

`HANDLERS` 仍是 mapped type `{ [T in EditorAction["type"]]: ActionHandler<T> }`，各檔匯出 `Pick<>` 的部分，入口用展開組回去：**漏掉任何一個 action 仍會編譯失敗**（保留這個保護）。
`history/batch` 會呼叫 `editorReducer`，形成循環 import；只在函式裡用、模組載入時不用，ES module 可以處理，但要在測試確認。

### 步驟 4：`src/lib/editor/__tests__/editor-reducer.test.ts`（1 388 行）→ 依 `describe` 分檔

共用的 `blankState` / `run` 搬到 `__tests__/reducer-helpers.ts`；16 個 `describe` 依步驟 3 的領域分成約 5 個檔：`reducer-elements.test.ts`（elements、pageId、duplicate、multi-selection、tools）、`reducer-pages.test.ts`（pages、master pages、spine）、`reducer-styles.test.ts`（text styles、swatches）、`reducer-document.test.ts`（document、page setup、page numbering、project）、`reducer-history.test.ts`（history、history/batch）。

### 步驟 5（選做）：`src/lib/automation/edits.ts`（789 行）

`edits.ts` 留共用的解析函式（`findFont`、`findSwatch`、`resolveColor`…）並 re-export；`edits-elements.ts`（文字 / 圖形 / 線條 / 更新 / 刪除）、`edits-pages.ts`（頁面、主頁、文件、歷史）、`edits-styles.ts`（文字樣式、色票）。

### 步驟 6：同步文件

規則檔 `paths:`（`editor-model.md` 的 `editor-reducer.ts`、`format.rs` → 加上 `reducer/**`、`format/**`）、`cross-language.md` 等提到 `format.rs` 的地方（指到具體子檔）、`bump-file-format` / `add-mcp-tool` skills、根 `CLAUDE.md` 的單一測試檔範例、`docs/02-architecture.md`（`HANDLERS` 位置）、`progress.md`。

## 4. 不拆的（理由）

- `element-factory.ts`（750）、`shape-presets.ts`（659，多半是資料表）、`validation.ts`（651）、`pdf.rs`（847）：主題單一，或拆了要跨檔才讀得懂。
- 元件（`editor-canvas.tsx` 696 等）：拆 React 元件會動到 props 與 render 結構，風險比效益大。

## 5. 使用者的決定（2026-10-29）

- 範圍：**步驟 1–4 + 步驟 6**；步驟 5（`edits.ts`）不做。
- **每步一個 commit**（驗證通過後）。
- **連續做完**，全部完成再回報。
