# 專案重構（降低 Claude Code 的 token 與 context 用量）— 實作計畫

任務檔：`1-專案重構.md`。工作規則：**一個迭代 = 一個工作階段**；完成後更新 `docs/progress.md` 與本文件的「迭代狀態」，再 `/clear`。

## 1. 現況量測（2026-10-28）

| 檔案 | 字元 | 其中中日韓字元 | 估計 token* | 什麼時候進 context |
|---|---:|---:|---:|---|
| `CLAUDE.md` | 132 588 | 46 640 | ≈ 70 000 | **每個工作階段、每次 /clear 後自動載入** |
| `docs/progress.md` | 83 326 | 30 155 | ≈ 45 000 | CLAUDE.md 要求「開始工作前先讀」 |
| 使用者全域 `~/.claude/CLAUDE.md` | 小 | | < 1 000 | 自動 |
| MEMORY.md（索引） | 小 | | < 500 | 自動 |

\* 粗估：中文約 1 token / 字、其他約 3.5 字元 / token。**準確值以 Claude Code 的 `/context` 為準**（迭代 0 由使用者執行並記錄）。

**`/context` 實測基準（2026-10-28，`5d546a5`）**：Memory files 合計 **103.4k**＝根 `CLAUDE.md` **102.5k**、`~/.claude/CLAUDE.md` 715、MEMORY.md 158。粗估少算了約 46%（≈ 0.77 token / 字元）；照同一個比例，progress.md 讀進來約 64k。所以每個工作階段開始時的實際成本約 **16–17 萬 token**。（參考：系統工具 24.4k、Skills 4.9k、MCP 說明 2.4k，這些不在本計畫範圍。）

**迭代 2 之後的 `/context`（2026-10-28，`8959b47`，迭代 3 的工作階段開頭）**：Memory files 合計 **7.0k**＝根 `CLAUDE.md` **6.1k**、`~/.claude/CLAUDE.md` 715、MEMORY.md 158（基準 103.4k → 7.0k，−93%）；加上讀 progress.md（約 6 000 字元）仍在目標 ≤ 15 000 token 內。

結論（基準時）：**還沒讀任何程式碼，一個工作階段就先花掉約 11 萬 token**。這是主要成本；程式碼本身反而不是（最大的 `format.rs` 103 KB，只在需要時才讀）。

CLAUDE.md 各段大小（字元）：目錄結構 26 763（最大）、匯出 PDF 8 774、MCP 6 906、文件模型 5 566、檔案系統 5 519、偏好設定 4 943、工具面板 4 513、開頭的變更紀錄 4 485、素材管理 4 341、匯出翻頁書 4 013……其餘每段 1–3.5 K。

內容性質（抽樣）：
- **規則 / 不變量**（「改一邊要改兩邊」、「不可移除」、「不要用 X」）：真正需要隨時知道的，估計 20–30%。
- **歷史與理由**（日期、「使用者決定」、實測數字、計畫連結）：計畫文件裡已有，CLAUDE.md 只需要一個連結。
- **目錄清單**：Claude 可以用 Glob / Grep 自己查，逐檔說明幾乎都能刪。

progress.md：「目前階段」一段就 ~218 行，大多是**已完成**工作的逐步紀錄（每一步也已記在各自的計畫文件）。

## 2. 目標

1. 開新工作階段（或 /clear）時自動載入的內容 **≤ 15 000 token**（根 CLAUDE.md + 開始時要讀的 progress.md）。
2. 細節**依需要載入**：只有在碰到相關檔案時才進 context。
3. **不遺失資訊**：搬走的內容都有固定位置，根 CLAUDE.md 有索引；每個迭代結束時專案狀態一致（沒有「搬了一半」）。
4. 不改程式行為（迭代 7 的程式拆檔除外，另外決定）。

## 3. 可用的機制（迭代 0 實測確認）

| 機制 | 載入時機 | 適合放 |
|---|---|---|
| 根 `CLAUDE.md` | 每次 | 專案概要、指令、工作規則、索引、全域慣例 |
| 子目錄的 `CLAUDE.md`（例如 `src-tauri/src/export/CLAUDE.md`） | Claude **讀到那個目錄的檔案時**才載入 | 一個目錄 = 一個領域的規則（export、mcp、project） |
| `.claude/rules/*.md` 加 `paths:` frontmatter（glob） | 碰到符合 glob 的檔案時才載入 | 檔案散在同一個扁平目錄的主題（`lib/editor/` 裡的文字、線條、主頁…），以及跨 TS / Rust 兩端的規則（一份檔案、兩邊的 glob） |
| Skills（`.claude/skills/<name>/SKILL.md`） | 只有描述常駐；呼叫時才載入全文 | 重複的多步驟流程（新增 MCP 工具、升級檔案格式、結束迭代） |
| `docs/` 的文件 | 只在被要求或被連結時讀 | 「為什麼」、歷史、實測紀錄（給人看） |

**建議**：`lib/editor/` 是扁平目錄、內容最多，用 `.claude/rules/`（細到主題）；`src-tauri/src/export`、`src/lib/automation` 這類「一個目錄一個領域」用子目錄 `CLAUDE.md` 或 rules 皆可——統一用 `.claude/rules/` 比較好維護（全部在一處、一眼看到所有規則）。迭代 0 實測後定案。

## 4. 新的文件配置（提案）

```
CLAUDE.md                     # ≤ 10 000 字元：概要、目前方向、Tech Stack（精簡）、Commands、工作規則、慣例、規則索引
docs/progress.md              # ≤ 6 000 字元：目前在做什麼、待辦、未驗證 / 已知問題、最近 5 個 commit 的一行摘要
docs/progress-archive/2026-10.md   # 從 progress.md 搬出的已完成紀錄（原文，不改寫）
.claude/rules/
  editor-model.md             # paths: src/lib/editor/types.ts, editor-reducer.ts, validation.ts, element-factory.ts …（文件模型、狀態、新增物件 / geometry 要改的地方）
  editor-text.md              # text-*.ts, distributed-text.ts, indented-text.ts, style-sheet.ts, style-controls.tsx …（文字裝飾、行距字距、首尾置中、縮排、文字樣式）
  editor-shapes-lines.md      # shape-*.ts, line-*.ts, corner-radius.ts …（圖形庫、圖片框、線條）
  editor-pages.md             # master-pages.ts, spreads.ts, page-*.ts, variables.ts, pages-panel.tsx …（主頁、跨頁、頁碼、排序）
  editor-color-fonts.md       # swatches.ts, palette.ts, fonts.ts, project-fonts.ts, settings/fonts-dialog.tsx …
  canvas-ui.md                # components/editor/editor-canvas.tsx, canvas-*.tsx, use-canvas-*.ts …（捲動縮放、多選、右鍵、工具、尺規）
  app-shell.md                # lib/menu, lib/dock, components/dock, lib/preferences, components/app/settings …
  project-files.md            # lib/project, lib/library, lib/templates, src-tauri/src/project/** …（檔案系統、素材庫、範本）
  export.md                   # lib/export, src-tauri/src/export/** …（PDF / 翻頁書 / PPTX / EPUB）
  mcp.md                      # lib/automation, src-tauri/src/mcp, src/bin, sdk/python …
  cross-language.md           # TS ↔ Rust 必須一致的常數與規則（兩端的 glob 都列）
  ipc.md                      # src-tauri/src/commands/**, lib.rs, error.rs, capabilities …（IPC、CSP、DB）
.claude/skills/               # 迭代 6，使用者同意的才建
```

**寫法原則**（每個規則檔）：
- 只寫**規則與陷阱**（會做錯的事）。每條一到兩行，附「為什麼」的一個短語。
- 日期、「使用者決定」、實測數字 → 刪掉，改成一行「計畫：`docs/…-實作.md`」。
- 檔案清單只留「不看檔名猜不到的」（例如 `library-panel` 的 id 是 `upload`）。
- 目標每檔 ≤ 5 000 字元。

根 CLAUDE.md 另加一段「**規則索引**」：主題 → 規則檔 → 對應的計畫文件，讓 Claude 在還沒碰到檔案前也知道去哪裡找。

## 5. 迭代

每個迭代的驗證都包含：
- `npm run build` / `npm test` 不受影響（文件迭代只確認沒有誤改程式檔：`git diff --stat` 只有 .md 與 .claude/）。
- **資訊沒遺失檢查**：搬移前後以腳本比對「舊 CLAUDE.md 的每個 `反引號識別字`（檔名、函式名、常數）」在新配置（根 + rules + archive）裡都還找得到；找不到的列出來，逐條決定刪或補。
- 下一個工作階段開頭由使用者執行 `/context`，記錄 Memory files 的 token。

### 迭代 0：基準與機制實測（小）
1. 使用者執行 `/context`，把「Memory files」那幾行貼回來 → 記到本文件 §1。
2. 建一個測試規則 `.claude/rules/_probe.md`（`paths: src-tauri/src/export/**`，內容：「回答時先說 PROBE-OK」），新工作階段讀一個 export 檔案，確認有載入、讀 `src/` 其他檔案時沒載入。同樣測一個子目錄 `CLAUDE.md`。
3. 決定採用 rules / 子目錄 CLAUDE.md（§3），刪掉測試檔。
4. 寫好「資訊沒遺失檢查」腳本（放 scratchpad，見 §7）。

### 迭代 1：progress.md 瘦身（風險低、效益大）
1. 「目前階段」裡**已完成並 commit** 的項目、「已完成」整段 → 原文搬到 `docs/progress-archive/2026-10.md`。
2. progress.md 只留：目前在做什麼（含未 commit 的）、待辦（使用者 / Claude）、尚未驗證 / 已知問題、已做的決定裡**仍有效的全域決定**（其他的屬於計畫文件）。
3. 檔頭加上維護規則：完成的項目留一行摘要 + 計畫連結，詳細搬到 archive；上限 6 000 字元。
4. 把 CLAUDE.md「開始工作前先讀 progress.md」改成「讀 progress.md（不讀 archive，除非需要）」。

### 迭代 2：拆 CLAUDE.md（機械式搬移，不改寫）
1. 依 §4 把每一段**原文**搬到對應的規則檔（加 `paths:`）。
2. 根 CLAUDE.md 只剩：概要（開頭的變更紀錄改成三行方向 + 「歷史見 progress-archive」）、Tech Stack、Commands、工作規則、慣例、CSP 的兩條「不可移除」、規則索引。
3. 「目錄結構」：根只留頂層地圖（約 20 行）；逐檔說明裡有規則的句子搬進對應規則檔，純描述的刪掉（Glob 查得到）。
4. 跑「資訊沒遺失檢查」。
→ 這一步之後總量還沒變少多少，但**每次自動載入的只剩根檔**，效益已經出現。

### 迭代 3–5：精簡規則檔（每次 3–4 個檔）
- 迭代 3：editor-model、editor-text、editor-shapes-lines、editor-pages
- 迭代 4：editor-color-fonts、canvas-ui、app-shell、project-files
- 迭代 5：export、mcp、cross-language、ipc
每個檔依「寫法原則」改寫到 ≤ 5 000 字元；被刪的理由 / 實測確認在計畫文件裡（沒有就補一行到該計畫文件，不留在規則檔）。跑「資訊沒遺失檢查」。

### 迭代 6：Skills（需使用者同意，見 Q3）
候選（都是 CLAUDE.md / 記憶裡已經寫成步驟清單、反覆出現的流程）：
| skill | 內容 | 取代 |
|---|---|---|

讀一個大檔就要整份進 context。候選：`format.rs`（2 235 行：型別 / 驗證 / 升級 / 測試可拆成子模組）、`editor-reducer.ts`（1 095 行：依 action 領域拆 handler）、`editor-reducer.test.ts`（1 388 行）、`edits.ts`。會改程式（要跑全部測試），建議另開任務檔，不在這次範圍。

## 6. 風險

- **規則沒被載入**：Claude 改了 A 卻沒讀到 B 的規則（例如只改 TS 沒碰 Rust）。對策：`cross-language.md` 兩端 glob 都列；根檔的規則索引列出所有主題；迭代 0 實測載入行為。
- **精簡時刪掉仍需要的陷阱**：對策：迭代 3–5 只刪「計畫文件裡已有」的內容；識別字比對腳本。
- **規則檔再次膨脹**：對策：`iteration-end` 檢查大小上限；新功能的歷史寫進計畫文件，規則檔只加規則。

- Q2 `docs/progress-archive/` **要 commit**（同 progress.md，不寫本機路徑與個人資訊）。
- Q3 迭代 6 建 **四個 skills**：`iteration-end`、`add-mcp-tool`、`bump-file-format`、`ui-verify`（`export-overlay` 不建）。
