# 01 文字框屬性：縮排與首行突排 實作計畫

任務檔：`01-新增文字框屬性.md`（不 commit）；本計畫要 commit。

## 1. 需求理解

- 目前文字沒有**段落縮排**：不能讓每段第一行內縮（中文內文「首行縮排兩字」），也不能做**首行突排**（hanging indent / exdent：第一行比其他行靠左，常用在條列「1. ……」「• ……」、參考文獻）。
- 「段落」= 文字裡以換行（`\n`）分開的每一段；Konva 自動換行產生的行不是新段落。
- 縮排和對齊、行距一樣屬於整個文字框（現在沒有富文字），所以是 `TextStyle` 的欄位：文字物件、圖形內文字、文字樣式都有；**頁碼沒有**（直書每字一行、位置由規則決定，同行距 / 字距的做法）。

### 名詞（業界對照）

| 本計畫 | InDesign | Word |
|---|---|---|
| 左縮排 | Left Indent | 縮排 → 左 |
| 右縮排 | Right Indent | 縮排 → 右 |
| 首行縮排（正值） | First Line Left Indent | 指定方式 → 第一行 |
| 首行突排（負值） | First Line Left Indent < 0 | 指定方式 → 凸排 |

**建議的模型（InDesign）**：三個數字。每段第一行的左緣 = 左縮排 + 首行縮排，其他行 = 左縮排，所有行的右緣 = 框寬 − 右縮排。首行突排 = 左縮排 X、首行 −X（第一行貼框、其他行內縮 X）。首行不可以比文字框左緣更左（首行 ≥ −左縮排，InDesign 同規則），文字不會跑出框外。

## 2. 現況與可以沿用的東西（不重複造輪子）

| 需要的能力 | 已經有的 | 這次怎麼用 |
|---|---|---|
| 換行 | Konva `Text._setTextData`（以單一 `maxWidth` 逐段換行：先試整段、再二分搜尋放得下的字、`word` 模式退回最後一個空白或 `-`） | **Konva 沒有每行不同的寬度**。不自己寫一套斷行：每段用 Konva 換兩次（第一行用「框寬 − 首行左緣 − 右縮排」，其餘用「框寬 − 左縮排 − 右縮排」），規則與字寬完全是 Konva 的（步驟 1 驗證） |
| 每行的起點 | 匯出的 `RenderText.line_starts`（字距、首尾置中已經在用）：PDF 每行 `place(dx: 起點)`、`box` 不讓 Typst 再斷行；EPUB 每行 `margin-left` + `nowrap` | 有縮排時一律帶 `line_starts`，起點 = 這行的左縮排 + 在「這行的寬度」裡的對齊位移。**PDF 模板與 EPUB 標記幾乎不用改** |
| 每行的寬度 | `TextLayout.lineWidths`（底線長度、對齊用） | 不變；另外加每行的行框 `lineBoxes`（起點與寬度，步驟 4 定名） |
| 首尾置中 | `distributeText(line, measure, boxWidth)` | 傳入這一行的寬度（框寬 − 左右縮排），不是框寬 |
| 自訂繪製 | `drawDistributedText`（自訂 `sceneFunc`，逐字 `_partialText`） | 有縮排時也用自訂 `sceneFunc`：每行平移到自己的起點（其他繪製照 Konva） |
| 欄位的單一資料來源 | `TEXT_STYLE_KEYS`（mapped type）、`TEXT_STYLE_KEY_LABELS`、`mapFontFamilies` 等 | 新欄位加進 `TextStyle`，漏改的地方編譯失敗 |
| 檔案格式 | Rust `#[serde(flatten)] spacing: TextSpacing`（v9 的行距 / 字距，缺少時預設值、不需要升級步驟） | 同樣做一個 `TextIndent` flatten 進三個結構，缺少時全 0 |

### 唯一要自己處理的：畫布怎麼拿到「每行不同寬」的換行

候選做法（步驟 1 實測後定案）：

- **A（建議）預先換好行**：純邏輯 `layoutIndentedText`（`lib/editor/`）用注入的「Konva 換一段」函式算出每行的文字與左縮排；畫布的 `Konva.Text` 收**已經換好的文字**（行之間用 `\n` 接起來）與 `wrap: "none"`，再用自訂 `sceneFunc` 把每行平移。Konva 的 `textArr` 就等於我們的行，命中區、高度、陰影、buffer canvas、Transformer 都照舊；`measureTextLayout` 也用同一份結果，畫布和匯出拿到的行一定一樣。
- B 繼承 `Konva.Text` 改寫 `_setTextData`：更依賴 Konva 內部，文字物件的節點類型也要換。
- C 自己寫一套斷行：要重做 Konva 的二分搜尋、字快取、`word` / `char` 規則，和畫布不同步的風險最大。不建議。

縮排全部為 0 時**完全不走新路徑**（和現在逐位元組相同），舊文件不受影響。

## 3. 規則（★ = 使用者已於 2026-10-19 確認）

1. ★ **欄位**：左縮排、右縮排、首行縮排（可負 = 首行突排）三個（InDesign 模型）。
2. ★ **單位**：「字」（字級的倍數，跟著字級縮放；中文排版說「縮兩字」）。存檔也存字級的倍數，匯出前由前端換成 pt。
   - ★ **UI**：Word 式——左縮排、右縮排兩欄 +「指定方式：無 / 首行縮排 / 首行突排」與位移量（字）；存檔仍是三個數字（首行突排 X 和左縮排、首行欄位的換算由 UI 負責，步驟 5 定清楚）。
   - ★ **段前 / 段後距**：這次不做，另開任務（第 7 節第 4 點）。
3. **範圍**（暫定）：左 / 右 0–20 字；首行 −左縮排 – 20 字；左 + 右（以及首行左緣 + 右）不得讓一行的寬度 < 1 個字級，否則夾值（避免每個字一行或寬度 ≤ 0）。數值實際定在步驟 2。
4. **段落**：每個 `\n` 開始一段；空段落（連續換行）沒有字，縮排沒有影響。第一段的第一行也算首行。
5. **對齊**：在「這一行的寬度」裡對齊：置中 = 在左右縮排之間置中、靠右 = 貼右縮排、首尾置中 = 貼齊左右縮排（首行貼首行左緣）。
6. **字距**：照 Konva 原本的方式（字距 ≠ 0 時逐字畫、行寬含字距），不受縮排影響。
7. **圖形內文字**：縮排從文字框（圖形外框內縮 4 pt）算起，和文字物件一樣。
8. **文字樣式**：三個欄位是樣式的一部分（`TEXT_STYLE_KEYS`），可以覆寫、覆寫提示的名稱「左縮排」「右縮排」「首行縮排」。內建三個樣式**預設 0**（不改既有文件的外觀；要不要讓「內文」首行縮排兩字見第 7 節）。
9. **文字編輯框**（textarea）：CSS 的 `padding-left` / `padding-right` 做左右縮排，`text-indent` 做首行。步驟 1 實測：**textarea 不支援 `each-line`**，編輯中只有第一段的首行縮排 / 突排，**放開後以畫布為準**（已知限制，同首尾置中）。

- 同步：`tests/fixtures/sample.magproj`（一個文字首行縮排、一個連到樣式的文字首行突排）、`tests/fixtures/default-text-styles.json`（內建樣式加三個 0）、`docs-website/types.html`。

## 5. 步驟（一次一步，每步停下等確認）

### 步驟 1：實測（不改程式）
無頭 Edge（Konva 10.5.0），結果寫回本計畫：
- **Konva 一段換兩次等於一次換行**：縮排 0 時，「第一行用寬 W、剩下的文字再用寬 W 換」和 Konva 直接換整段的每一行完全相同（中文、英文長單字、中英混排、行尾空白、字距 ±、`-` 斷字）。確認 Konva 對剩下的文字會不會去掉行首空白（決定「剩下的文字」從哪裡切）。
- **做法 A**：預先換好的文字 + `wrap: "none"` + 自訂 `sceneFunc` 平移每行：`textArr` 等於輸入的行、高度、命中區、底線 + 陰影的 buffer canvas、旋轉、Transformer 縮放（只改寬度後重新換行）都正常。
- **文字編輯框**：WebView2 / Edge 的 `text-indent` 支不支援 `each-line`、`hanging`。
- 結論：定案做法（有變再和使用者討論）。

**結果（2026-10-19 完成，Konva 10.5.0，無頭 Edge 155；字型 Geist + Noto Sans TC 16 pt）**：

測試文字：中文長段、英文（長單字、`-` 連字）、中英混排（標點、數字、連續空白）、全是「單字 + 四個空白」、多段（含空段落）；寬度 60 / 97 / 150 / 233 / 301；變化：無、字距 +3 / −1.5、粗體、`wrap: "char"`。

| 項目 | 結果 |
|---|---|
| 整份文字 = 每段各自換行接起來 | **125 / 125 相同** → 段落可以自己切（`\n`），每段分開換行 |
| 一段換兩次 = 整段換行 | 第一行一定是段落的前綴（Konva 只去掉行尾空白）；剩下的文字**去掉行首空白**（`trimStart`）再換：**156 / 156 相同**。不去行首空白時 94 個不同（第二行多出開頭的空白，或多一個空行）→ Konva 會吃掉換行處的空白，「剩下的文字」= `段落.slice(第一行.length).trimStart()` |
| 預先換好的文字 + `wrap: "none"` | `textArr` 的每行文字、每行寬度、節點高度都和原本的 Konva 換行**完全相同（125 / 125）** |
| 每行平移的繪製 | 自訂 `sceneFunc`：每行 `context.translate(位移, 第 i 行 × 行高)`、`textArr` 暫時只留這一行，呼叫 Konva 自己的 `Text.prototype._sceneFunc`。位移 0 時和 Konva 原本的畫法**逐像素相同**（靠左、字距 +2、底線 + 刪除線 + 陰影、置中、靠右 + 字距 −1、旋轉 15°，差異 0 byte）；有線 + 陰影時仍走 buffer canvas（整段一個陰影）。位移 32 / 16 時每行墨跡左緣剛好移動 32 / 16 px |
| 命中區 | 照 Konva 的 `_hitFunc`（整個外框）：縮排的空白處也點得到；高度和原本相同 |
| CSS `text-indent` | `CSS.supports` 說 `each-line`、`hanging` 都支援；一般 `div`（`white-space: pre-wrap`）每段都縮排。**但 `textarea` 不認 `each-line`**：只有整個文字框的第一行縮排，之後的段落不縮（截圖確認） |

**結論**：
- 照計畫用**做法 A**：每段用 Konva 換兩次（第一行用首行寬度，剩下的去掉行首空白後用其他行寬度），畫布節點收預先換好的文字 + `wrap: "none"`。
- 繪製**不自己重寫**：每行平移後交給 Konva 的 `_sceneFunc`（底線、字距、陰影、buffer canvas 都是 Konva 的）。節點一律 `align: "left"`，對齊位移由我們算（= 縮排 + 在這行寬度裡的對齊，和 Rust `line_start` 同公式）；首尾置中的 `drawDistributedText` 改成每行用自己的寬度與起點。
- 縮排全為 0 時不走這條路（不傳 `sceneFunc`、不改文字）。
- **文字編輯框（已知限制）**：`padding-left` / `padding-right` 做左右縮排，`text-indent`（不帶 `each-line`）只讓**第一段**的首行縮排 / 突排；第二段之後的首行在編輯中不縮排，換行位置可能和畫布不同，放開後以畫布為準（同首尾置中編輯框的限制）。要完全一致得把 textarea 換成 contenteditable（輸入法、復原都要重做），不建議為這個改。

## 6. 檢核（規劃本身的風險）

- **換行和畫布一致**：換行仍由 Konva 決定（只是每段分兩次），畫布、量測、匯出共用 `layoutIndentedText` 的結果，Typst / 閱讀器不再斷行（已有 `no-wrap-width` / `nowrap`）→ 和字距、首尾置中同一套保證。
- **「換兩次」等於 Konva 的換行**：這是做法 A 的前提，步驟 1 先驗證；不成立時（例如行首空白的處理）改用 B，再和使用者討論。
- **依賴 Konva 內部**（`textArr`、`_partialText`、基線公式）：已經在依賴，同樣標註「升級 Konva 時重測」。
- **效能**：有縮排的文字每段多換一次行；200 頁壓力測試的文字量不大，步驟 4 量一次（開發版與 release）。縮排 0 不多做事。
- **畫布節點的 `text` 和文件的 `text` 不同**（做法 A 多了換行字元）：文字編輯框編輯的是文件的原文（`page.elements`），`bakeTransform` 只回寫位置與尺寸，不會把換行寫回；步驟 4 要搜尋有沒有其他地方讀 `node.text()`。
- **動態變數**：畫布顯示的是換過變數的副本，縮排換行用副本的文字（和現在一樣）。
- **過渡期**（步驟 3–4 之間）：存了縮排的文字畫成沒有縮排，匯出也沒有，不會壞檔。
- **舊版 App**：v16 檔案舊版會拒絕開啟（即使沒用到縮排），和以前每次升版相同。

## 7. 設計建議

1. **單位用「字」**：中文排版習慣「首行縮排兩字」，改字級時縮排跟著變，不用重算；和字距（字級的 1/1000）、行距（字級的倍數）同一類，都跟著字級縮放。缺點：同一份文件不同字級的文字，縮排的實際長度不同（這通常正是想要的）。
2. **UI 用 Word 的「指定方式：無 / 首行縮排 / 首行突排」+ 位移量**，加上左、右縮排兩欄；存檔用 InDesign 的三個數字（首行可負）。使用者熟悉 Word 的說法，模型則簡單、和匯出好對應。
3. **內建「內文」樣式維持 0**：改了會讓所有既有文件連到「內文」的文字跟著縮排。想要的話之後在新文件的預設裡加（`newDocumentStyles`），不動舊檔。
4. **之後的任務可以接在這次的機制上**：
   - **段前 / 段後距**：需要每行自己的 y（現在匯出是「第一行基線 + 第 i 行 × 行距」），這次把 `layoutIndentedText` 的結果設計成以段落為單位，之後加 `lineYs` 即可。建議另開任務。
   - **左右對齊**（justify，最後一行靠左）：首尾置中計畫第 6 節已建議；有了每段的資訊就知道哪一行是段落最後一行。
   - **項目符號 / 編號清單**：建在首行突排上（符號放在突排的位置）。
