4.3 紙張尺寸

  • 下拉選單：PAGE_SIZE_PRESETS（A4 / B5 / Letter）＋「自訂」。選 preset 時寬高欄位自動填入；手動改寬高時，符合 preset 就顯示該名稱，否則顯示「自訂」（用既有的 findPageSizePreset）。
  • 直式 / 橫式：交換寬高。
  • 限制：寬、高各 10–2000 mm（UI 與 reducer 檢查；Rust 目前只檢查 > 0，不收緊，以免舊檔開不了）。
  • 文件裡各頁尺寸不一樣時（舊檔可能有），對話框顯示目前頁的尺寸並註明「套用後所有頁面都會改成這個尺寸」。
  • 物件位置不動、不縮放；縮小紙張時超出的物件照常顯示（本來就允許超出頁面）。
  • 「新增」文件仍是 A4（新文件的預設尺寸不在這次範圍）。

4.4 邊界（文件模型變更）

// types.ts
export interface Margins {
  readonly top: number;    // pt
  readonly right: number;
  readonly bottom: number;
  readonly left: number;
}

export interface EditorDocument {
  readonly name: string;
  /** Guides only; not exported. Same for every page. */
  readonly margins: Margins;
  readonly pages: readonly Page[];
}
  • 單位 pt（文件模型的規則），對話框顯示 mm。
  • Rust：format.rs 的 Document 加 #[serde(default)] margins: Margins；SCHEMA_VERSION 升為 4。v1–v3 檔案與沒有版本號的備份檔沒有這個欄位 → 預設全 0（= 不畫參考線，和現在的畫面相同），不需要升級步驟。升版本的原因：舊版 App 讀到 v4 檔案存檔時會把 margins 默默丟掉（只保留最上層未知欄位），升版讓舊版直接拒絕開啟。
  • 驗證：每一邊是有限值、≥ 0、≤ 2000 mm（TS validation.ts 與 Rust validate_content 規則一致）。「左 + 右 < 頁寬」只在對話框檢查，不寫進檔案驗證（改紙張尺寸時不應該讓檔案變成不合法）。
  • 新文件（createBlankDocument / createSampleDocument）預設四邊 15 mm。
  • 匯出（render.rs / PDF / EPUB）不讀 margins，輸出不變。
  • 同步：tests/fixtures/sample.magproj（加 margins、版本 4；sample-v2.magproj 不動，用來測舊檔預設 0）、docs-website/types.html（圖、說明卡、頁首 commit）。

4.7 畫布顯示

  • 格線：一個 Konva Shape（sceneFunc 一次畫完所有線，不建立上百個 Line 節點），只畫在頁面範圍內，位於頁面背景之上、物件之下，listening=false，線寬 1 / zoom。縮小到格子小於 6 px 時改成每 N 格畫一條，避免整片變灰。
  • 邊界參考線：粉紅虛線矩形，畫在物件上方（和頁緣線同一層），listening=false。邊界全 0 或「顯示邊界參考線」關閉時不畫。
  • 兩者都不進 getContentBounds、不影響框選（listening=false，和頁緣線相同）、不會出現在匯出結果。

4.8 吸附格線

操作吸附什麼做法
拖曳物件（含多選整組）被拖曳物件的 x / y（外框左上角）節點 dragmove 時把位置四捨五入到格線；多選時 Konva Transformer 依被拖曳節點的位移帶動其他節點，整組一起對齊
縮放（Transformer 控制點）被拖曳的控制點Transformer 的 anchorDragBoundFunc：螢幕座標 → 頁面座標 → 四捨五入 → 換回螢幕座標。只在旋轉 0° 時吸附（旋轉後的外框邊不在格線方向上）
文字 / 圖形工具建立點擊點、拖曳框的兩個角use-canvas-create.ts 換算頁面座標之後套用
方向鍵、屬性面板輸入不吸附方向鍵是微調；輸入的數字照使用者給的值
  • 吸附函式 snapToGrid(value, spacing) 放在 lib/editor/geometry.ts（純函式、補測試）。
  • 格線原點 = 頁面左上角。
  • 風險：多選拖曳時「我們的 dragmove 先改位置，Transformer 再帶動其他節點」的事件順序要實測；不成立時改成在 Transformer 的 dragmove 裡校正整組。

  • 拖曳（單選 / 多選）、縮放（旋轉 0°）、文字 / 圖形工具建立（4.8）。
  • 驗證：吸附開 / 關各拖一次，比對 dragend 後的 x / y 是否為間距的整數倍；多選整組一起對齊；旋轉過的物件縮放不吸附；Ctrl+Z 一次回去。
  • 結果：
    • 拖曳用 Konva 的 dragBoundFunc（在 dragmove 之前套用），由 editor-canvas 的 dragBound 計算，ElementNode 只轉接。
    • 實測發現（和 4.8 的風險不同）：多選拖曳時 Konva 會讓每個節點各自呼叫 dragBoundFunc，而且 Transformer 在主拖曳節點第一次 dragmove 之後才讓其他節點開始拖曳，它們的滑鼠偏移已含主節點第一次的吸附修正。第一版讓每個節點各自吸附，結果整組相對位置跑掉。改成：第一個呼叫的節點是 lead，記錄它的起點與滑鼠偏移；每次從滑鼠位置推回 lead 的原始位置、吸附，所有節點都用「自己的起點 + lead 的位移」。dragend 時清空這份記錄。
    • 縮放用 Transformer 的 anchorDragBoundFunc，只在單選且旋轉為 0° 時設定。座標換算共用 canvas-elements.tsx 的 snapAbsoluteToGrid。
    • 建立：拖曳框的兩個角先吸附（吸附後寬或高變成 0 時當成點擊）；點擊建立的物件把外框左上角吸附。三角形 / 星形維持比例置中在框內，所以它們自己的左上角不一定在格線上。預覽框沒有吸附（只顯示滑鼠拖出的範圍）。
    vitest 226 個通過；無頭 Edge 驗證 9 項（吸附關閉時跟著滑鼠、單一拖曳、一次復原、整組拖曳 A 帶頭與 B 帶頭都保持相對位置、縮放右下角、拖曳建立、點擊建立）。未在瀏覽器驗證：旋轉過的物件縮放不吸附（只是條件判斷）。
