    • page/reorder { order: PageId[] }：給完整的新順序，必須剛好是現有頁面的排列，否則 no-op；沒變回傳同一個 state。這次沿用。
    • 目前頁面選單加「向左 / 向右移動」；「頁面排序」對話框（拖曳 + 上 / 下移）；之後的「頁面」工具面板（縮圖、拖曳排序）可以取代排序對話框。
  • 頁碼規則跟著頁序（頁碼管理）：頁面換位置後，頁碼會依新位置重新計算；這是預期行為，但要讓使用者知道。

3. 可行的做法

做法操作適合工作量建議
A. 拖曳頁籤 在頁籤列按住頁籤左右拖，放開就換位置；拖曳時頁籤間出現插入線，拖到頁籤列左右邊緣會自動捲動；Esc 取消 附近幾頁的調整，最直覺（draw.io、瀏覽器分頁都這樣） 中 建議
B. 頁面選單的移動項目 目前頁籤的 ˅ 選單加「向左移動 / 向右移動 / 移到最前 / 移到最後」 鍵盤與精確操作；頁面多時一步到頭尾 小 建議
C. 快捷鍵 Ctrl+Shift+PageUp / PageDown 把目前頁面往前 / 往後移一格（Chrome、VS Code 移動分頁的慣例；換頁已是 PageUp / PageDown） 常用鍵盤的人 小（和 B 共用動作） 可選
D. 頁面排序對話框 清單裡拖曳或上 / 下移，按「確定」才套用 一次大幅調整 中 有 A + B 時可省略
E. 「頁面」工具面板 縮圖清單，直向拖曳排序，可多選一起搬 幾十頁以上的雜誌；最完整 大（縮圖要快取、清單要虛擬化） 建議另開任務

拖曳「內文 2」：游標旁跟著頁籤名稱，插入線出現在「目錄」與「內文 1」之間，放開後「內文 2」變成第 3 頁。

4. 設計（A + B 的情況）

4.1 資料與 reducer（不含 UI，先寫、可測）

  • page/reorder { order: readonly PageId[] }：照 2026-10-01 的決定。一次 = 一筆復原；activePageId 不變（移動的頁面仍是目前頁）；順序沒變、不是排列時回傳同一個 state。
  • lib/editor/page-order.ts 純函式：movePage(order, id, toIndex)（拖曳放下）、shiftPage(order, id, "left" | "right" | "first" | "last")（選單與快捷鍵）、拖曳時依游標位置算插入位置。都補 vitest。
  • 不改檔案格式（頁面本來就是陣列，順序即存檔順序）。

4.2 拖曳頁籤（不重複造輪子）

  • 照工具面板拖曳（use-dock-drag.ts）已驗證的做法：pointer events（不用 HTML5 drag & drop：它在可捲動的頁籤列裡不好控制捲動、拖曳影像也無法自訂）、按下後移動 4 px 才算拖曳（點擊、雙擊改名照舊）、結束後吞掉下一次 click、Esc 取消、React state 只在插入位置改變時更新、跟著游標的標籤直接改 style。
  • 新增 use-page-tab-drag.ts；插入線畫在頁籤之間；靠近頁籤列左右邊緣時自動捲動（頁面多時才拖得到遠處）。
  • 放下時 dispatch 一次 page/reorder；位置沒變不 dispatch。

4.3 頁面選單

  • 只在目前頁籤的 ˅ 選單（作用在目前頁）加一段：向左移動、向右移動、移到最前、移到最後；第一頁 / 最後一頁時對應項目停用。≡ 選單維持「插入頁面 + 頁面清單」。
  • PageMenu 加一個 prop 決定是否顯示目前頁的動作，兩個入口仍用同一個元件。
使用者決定（2026-10-06）：做 A 拖曳頁籤、B 頁面選單移動項目、C 快捷鍵（Ctrl+Shift+PageUp / PageDown）；D 排序對話框不做；E「頁面」工具面板不要（不是延後）。見第 6 節。
