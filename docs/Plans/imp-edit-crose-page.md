## 1. 問題

- **目前**（參考圖一）：雙頁模式下，左頁的圖片拖過書背，**跨到右頁的那一段看不見**（右頁的背景是後畫的，把它蓋住），選取框卻延伸到右頁；匯出時那一段也會被左頁的紙張裁掉，右頁不會出現。
- **Affinity**（參考圖二）：物件可以橫跨兩頁，兩頁都看得到；輸出單頁時，跨過去的部分出現在另一頁（各自被紙張裁切），印出來接得起來。

## 2. 兩種做法（見 Q1）

### 做法 A：跨頁物件（建議，Affinity 的做法）

物件仍只屬於**一頁**（資料模型不變），但「跨過書背的部分」在**對頁也畫出來、也輸出**：

- 對頁上畫一個**位移後的靜態複本**（右頁的位移 = 左頁寬；左頁的位移 = −左頁寬），被對頁的紙張自然裁切。
- 匯出時一樣在對頁加上這個複本（和頁碼、主頁內容同一種「只在匯出副本加」的做法），所以 **PDF / EPUB 兩頁接得起來**，Rust 不用改。
- 物件還是一個：移動、縮放、改顏色、改文字都只改一次，兩頁同步。

### 做法 B：用書背切成兩個物件（任務檔提到的方式）

物件放開時如果跨過書背，就在書背處**切成兩個物件**，左半屬左頁、右半屬右頁，之後各自獨立。

需要先解決的問題：

| 物件 | 切開要什麼 |
|---|---|
| 圖片 | 模型沒有「裁切」欄位，切開的兩半要能各自只顯示圖片的一部分 → 新增裁切欄位（檔案格式 v8，畫布 / PDF / EPUB 都要支援） |
| 圖形 | 圓角矩形、橢圓、星形切一半已經不是原本的形狀 → 需要「裁切遮罩」或任意路徑圖形（目前沒有） |
| 文字 | 無法有意義地切成兩半（字會被切斷，或一行字分到兩個物件後換行就亂了） |
| 之後修改 | 切開後是兩個物件：改顏色、移動要改兩次，位置對不齊就會在書背處露縫 |

→ B 的工作量大很多（模型、三個輸出端都要加裁切），而且文字做不到；**建議採用 A**。如果您想要的是「切開後可以各自移動」，可以在 A 之後再加一個「在書背切開」的指令，只用在圖片上。

## 3. 做法 A 的設計（待第 6 節確認）

### 3.1 純邏輯（`lib/editor/spreads.ts`）

- `spilloverOf(spread)`：跨頁裡每一頁有哪些物件跨過**書背那一側**（左頁看右緣、右頁看左緣；用含旋轉的外框 `getElementBounds`），以及在對頁要畫的位移。只看書背那一側：跨出外側（頁面外緣）的部分照舊被裁掉，不會跑到別頁。
- 只有在跨頁裡**真的有對頁**時才算（封面、偶數頁數的最後一頁單獨一頁時沒有對頁）。
- 配對固定是雜誌順序（第 1 頁在右，之後 2–3…），和 `spreadsOf` 相同。

### 3.2 畫布

- 對頁上畫跨過來的物件的**靜態複本**（`StaticElement`，位移後），畫在對頁**自己的物件之下**、主頁內容之上；匯出用同一個順序，所以畫面和輸出一致。
- 物件所在的那一頁：在書背處**裁切**它自己的物件（Konva Group 的 clip，只裁書背那一側，外側不裁，維持「物件可以超出頁面、不裁切」的既有規則），所以跨過去的那段只由對頁的複本顯示，疊放順序才和輸出一樣。
  - 例外：**拖曳 / 縮放中**不裁切，讓使用者看到完整的物件；放開後才回到裁切 + 複本。
- 對頁上的複本可以點：按下 = 切到物件所在的那一頁並選取它（沿用步驟 5 的「切頁＋選取」）。
- 單頁模式不變（沒有對頁可畫；匯出則見 Q2）。

### 3.3 匯出

- `buildExportRequest` 逐頁加上「對頁跨過來的物件」複本（在主頁內容之後、頁面自己的物件之前），id 用短格式 `spill:<頁序>:<第幾個>`（Rust 限制 64 字）；變數換成**物件所在頁**的值（頁尾的 `{頁碼}` 不會因為跨頁而變成另一頁的數字）。
- 是否套用見 Q2。

### 3.4 換頁（見 Q3）

- 物件整個（或大部分）拖到另一頁時，要不要改成屬於那一頁。

## 4. 步驟（做法 A）

每一步做完停下來，等使用者說「繼續」。

| 步驟 | 內容 | 畫面變化 | 驗證 |
|---|---|---|---|
| **1. 純邏輯** | `spilloverOf`（哪些物件跨過書背、在對頁的位移），含旋轉、單獨一頁、跨出外側不算 | 無 | vitest |
| **2. 匯出** | `buildExportRequest` 在對頁加複本（id `spill:…`、變數用所在頁的值、疊放順序） | PDF / EPUB 兩頁接得起來 | vitest ＋ 用真實匯出內容跑 `export_preview` 疊圖（左右兩頁拼起來看接縫） |
| **3. 畫布顯示** | 對頁畫靜態複本；所在頁在書背側裁切；拖曳 / 縮放中暫不裁切 | 有 | 無頭 Edge（兩頁都看得到、和匯出的位置一致） |
| **4. 對頁複本可點選** | 按複本 = 切到所在頁並選取 | 有 | 無頭 Edge |
| **5. （依 Q3）換頁** | 放開時物件的中心在另一頁就移到那一頁（座標換算，一筆復原） | 有 | vitest ＋ 無頭 Edge |
| **6. 文件同步** | `CLAUDE.md`（跨頁物件、匯出複本）、`docs/01`、`progress.md` | 無 | — |

匯出排在畫布前面：先確定「輸出長什麼樣子」，畫布再照同一個規則顯示。

## 5. 規劃檢核

1. **畫面與輸出一致**：複本的疊放位置（對頁主頁內容之上、對頁物件之下）在畫布與匯出用同一份純函式算，避免畫面和 PDF 不同。
2. **書背側裁切不能影響「物件可超出頁面」**：只裁書背那一側；頁面上、下、外側照舊不裁。單頁模式完全不裁。
3. **拖曳時的回饋**：如果拖曳中也裁切，物件跨過書背的那段會在拖的時候消失 → 拖曳 / 縮放中暫停裁切。
4. **變數**：複本的 `{頁碼}` 等用物件所在頁的值（跨頁的大標題通常不含變數，但頁尾若跨頁不應變號）。
5. **id 長度**：匯出的複本 id 用短格式（同主頁物件的 `master:` 做法），不會超過 Rust 的 64 字。
6. **主頁內容不跨頁**：主頁沒有左右頁，這次只處理頁面自己的物件。
7. **單頁模式的匯出**（Q2）：如果「一律套用」，以前在單頁模式放在頁面外、剛好跨過內側的物件，匯出時會出現在隔壁頁——這是行為改變，要先確認。
8. **不重複造輪子**：複本沿用 `StaticElement` 與「對頁按下＝切頁＋選取」；匯出沿用 `withMasterContent` 的副本做法；裁切用 Konva Group 的 `clip`；外框用既有的 `getElementBounds`（含旋轉）。

## 7. 進度

### 步驟 1（2026-10-07，完成）

- `lib/editor/spreads.ts`：`spilloverInto(pages, pageIndex)` → 對頁上跨過書背、要畫進這一頁的物件（`SpilloverItem`：物件、它所屬的頁序 `sourceIndex`、換到這一頁座標要加的 `dx`）。
  - 左頁收到右頁「左緣超出 0」的物件，`dx = +左頁寬`；右頁收到左頁「右緣超出左頁寬」的物件，`dx = −左頁寬`。用含旋轉的外框（`getElementBounds`）；剛好貼齊書背不算。
  - 只看書背那一側；單獨一頁（封面、偶數頁數的最後一頁）收不到任何東西。配對沿用 `spreadOf`（雜誌順序）。
  - 回傳順序是物件在所屬頁的圖層順序（下面的先）。
- **和計畫不同**：計畫寫的是 `spilloverOf(spread)`（一次算整個跨頁），實作成「某一頁收到哪些」的 `spilloverInto(pages, pageIndex)`：匯出逐頁組副本、畫布逐頁畫，兩邊都是以「收到的那一頁」為單位，用起來更直接。
