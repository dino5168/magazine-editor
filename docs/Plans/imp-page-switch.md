## 3. 設計（建議案，待第 6 節確認）

### 3.1 跨頁怎麼配對（`lib/editor/spreads.ts`，純函式）

- 雜誌慣例：**第 1 頁（封面）單獨放右邊**，之後 2–3、4–5…兩兩一組；頁數是偶數時最後一頁單獨在左邊（見 Q2）。
- 函式：`spreadsOf(pages)`（全部跨頁）、`spreadOf(pages, pageId)`（某頁所在的跨頁與左右位置）、`spreadLayout(spread)`（每頁在跨頁裡的 x 位移：左頁 0、右頁 = 左頁寬；單獨一頁放在它該在的那一側）、`spreadBounds`。頁面尺寸不同（舊檔）時上緣對齊。
- 頁碼的奇偶與這個配對一致：第 1 頁是奇數頁＝右頁。

### 3.2 模式存哪裡

- 建議放進既有的 `Preferences`（新欄位 `pageView: "single" | "spread"`，`parsePreferences` 驗證，壞值回 `"single"`）：重用 `PreferencesProvider` 與 localStorage，不改檔案格式、不進復原歷史（見 Q4）。

### 3.3 畫布（雙頁模式）

- 畫**目前頁所在的跨頁**：兩頁並排，各自畫背景、格線、主頁內容、物件、頁碼、邊界參考線；中間畫一條書背線。換頁（頁籤、PageUp…）時跨頁跟著換。
- **Layer 的座標改成「跨頁座標」**，每一頁放在一個位移後的 Konva Group 裡，Group 裡仍是頁面座標 → 物件模型、`bakeTransform`、匯出都不用改。
- 編輯（見 Q3）：建議**兩頁都可以直接編輯**——點另一頁的物件或背景，就切成那一頁並選取（`page/select` 再 `selection/set`）；選取、Transformer、框選仍只在目前頁（`selectedIds` 的規則不變）。建立工具在游標下的那一頁建立。
- 物件拖過書背仍屬於原本的頁面（超出照常顯示，匯出時被紙張裁掉），**這一版不自動換頁**（見 Q3）。
- 捲動範圍、符合畫面、捲到選取物件改用整個跨頁的範圍。
- 編輯主頁時一律單頁（主頁沒有左右頁之分，這次不做雙頁主頁）。

### 3.4 「頁面」面板

- 「頁面」標題列中間放切換（兩個圖示按鈕的分段控制，`aria-pressed`，tooltip「單頁」「雙頁」）。按在上面不會觸發拖曳調高度（按鈕已排除）。
- 雙頁模式時頁面縮圖兩兩一列（第 1 頁在右欄、左欄留空），看得出跨頁；單頁模式維持現在的格子。

## 5. 規劃檢核

1. **畫布是風險最高的部分**：現在很多地方假設「Layer 座標＝頁面座標」。所以步驟 3 先只重構、不改行為，用單頁模式的回歸測試確認沒壞，步驟 4、5 才加雙頁。
2. **格線吸附**：`snapAbsoluteToGrid` 用 Layer 當參考座標；右頁的 Group 有位移，必須改用物件所在的頁面 Group，否則右頁的物件會吸到錯的位置。步驟 3 處理。
3. **選取只屬於目前頁**：維持既有規則，跨頁時點另一頁 = 先切頁。`page/select` 會清空選取，所以「切頁 + 選取」是兩個 action；都是 UI 狀態，不進復原歷史。
4. **整組拖曳**：Transformer 只掛目前頁的節點，不會出現「兩頁物件一起拖」。
5. **頁碼 / 動態變數**：每一頁用自己的頁序算（既有的 `pageNumberShape`、`variableValues` 都以頁為單位），兩頁並排不影響。
6. **編輯主頁**：一律單頁，避免「主頁的左右頁」這個新概念（Affinity 有雙頁主頁，這次不做）。
7. **匯出**：不受影響（仍是一頁一頁）。
8. **不重複造輪子**：模式存既有的 `Preferences`；頁面位移用 Konva Group，不自己換算每個物件；切換按鈕用既有的 `IconButton` 樣式（或 `Button` + `aria-pressed`，和頁面設定的直式 / 橫式按鈕同一種做法）。
