1. 任務

  1. 位置：「設定 → 工具面板 → 屬性」面板的文字設定（文字物件的「文字」分頁、圖形的「文字」分頁）。
  2. 目前只有粗體，新增斜體、底線。
  3. 依參考設計圖（draw.io 的文字面板）新增需要的屬性。
  4. 列出候選項目，讓使用者選擇是否新增。

2. 現況

  • 文字樣式是 types.ts 的 TextStyle（fontSize / fontFamily / fontStyle: "normal" | "bold" / align / fill），由三處共用：
    • TextElement（文字物件）
    • ShapeLabel（圖形內文字，另有 verticalAlign）
    • PageNumberStyle（頁碼，Omit<TextStyle, "align">）
  • 控制項在 components/editor/style-controls.tsx 的 TextStyleFields，屬性面板與「頁碼管理」對話框共用。改它，兩邊都會出現新按鈕。
  • 字型只內嵌 Regular + Bold，沒有斜體字型檔（中文字型本來就沒有斜體）。
  • 文字要在三個地方畫出一樣的結果：畫布（Konva）、PDF（Typst template.typ）、EPUB（epub/xhtml.rs 的 CSS）。

5. 設計

5.1 資料模型

/** Hard text shadow: the text drawn again, offset, without blur. */
export interface TextShadow {
  /** `#rrggbb` or `#rrggbbaa`. */
  readonly color: string;
  /** pt; positive = right / down. */
  readonly offsetX: number;
  readonly offsetY: number;
}

export interface TextStyle {
  readonly fontSize: number;
  readonly fontFamily: string;
  readonly fontStyle: "normal" | "bold";   // 不動：粗體仍是字重
  readonly italic: boolean;                // 新增
  readonly underline: boolean;             // 新增
  readonly strikethrough: boolean;         // 新增
  readonly shadow: TextShadow | null;      // 新增；null = 沒有陰影
  readonly align: "left" | "center" | "right";
  readonly fill: string;
}
  • 斜體用獨立的 boolean，不擴充 fontStyle：粗體是換字型檔（字重），斜體是同一個字型檔斜切，兩者性質不同；而且舊檔的 fontStyle 完全不用改寫。畫 Konva 時再組成 "italic bold" 之類的字串。
  • 底線、刪除線各用一個 boolean（不照 Konva 存 "underline line-through" 字串），驗證與按鈕切換都比較單純。
  • 陰影照 Stroke 的慣例：物件或 null，element/update 的 patch 整個取代。開啟時的預設：#00000080（黑色 50%）、偏移 2 pt / 2 pt；偏移限制 −50～50 pt（TS / Rust 同一個上限常數）。沒有模糊：Typst（PDF）畫不出模糊，做了也只有畫布看得到。
  • 加在 TextStyle，所以文字物件、圖形內文字、頁碼同時具備。
  • 檔案格式：Rust 欄位加 #[serde(default)]，v5 檔讀成 false，不需要升級步驟；照慣例 SCHEMA_VERSION 升到 6（舊版 App 會拒絕開 v6，而不是悄悄丟掉斜體與底線）。

5.2 三邊怎麼畫成一樣

畫布（Konva）PDF（Typst）EPUB（CSS）
斜體 fontStyle="italic"：字型沒有斜體時，瀏覽器以固定斜率斜切（synthetic italic） Typst 不會模擬斜體（沒有斜體字型時只會畫正體），所以每行用 skew(ax: …) 以基線為軸斜切，角度和瀏覽器相同 font-style: italic（閱讀器同樣模擬斜切）；若實測角度和畫布不同，改用 transform: skewX()
底線 textDecoration="underline" 不用 Typst 的 underline()（位置由字型決定，和 Konva 不同），照 Konva 的公式自己畫線：位置、線粗由字級算出、長度 = 該行寬度、顏色 = 文字顏色 text-decoration: underline + text-decoration-thickness / text-underline-offset 指定成和 Konva 相同的數字
刪除線 textDecoration="line-through"（可和底線同時："underline line-through"） 同底線，照 Konva 公式自己畫 CSS 的 line-through 位置由字型決定、無法指定位移，所以刪除線改成每行一條絕對定位的線（底線若也實測對不上，同樣改用這個做法）
硬陰影 shadowColor / shadowOffset、shadowBlur=0 先用陰影色在偏移處畫一次同樣的文字（含斜切與線），再畫本體 text-shadow: Xpx Ypx 0 color（CSS 的 text-shadow 也會套在底線 / 刪除線上）
  • 斜切角度與底線公式會成為新的「前端與 Rust 各一份、改一邊要改兩邊」常數，寫進 CLAUDE.md 的清單，兩邊測試用同一組數字守著。實際數字在步驟 4 從 Konva 原始碼確認，並用 export_preview 疊圖比對。
  • 斜體、底線、刪除線、陰影都不改變字寬，所以換行（measureTextLayout）結果不變；量測時仍傳相同屬性，維持「量測節點和畫布節點完全相同」的原則。
  • 陰影在畫布上要確認兩件事（步驟 2 實測）：Konva 的陰影是否也套在底線 / 刪除線上（要和 CSS 一致）；以及文字物件的陰影不能撐大選取框（Transformer 只看文字框）。
  • 陰影方向固定朝頁面的右下（像固定的光源），不跟著物件旋轉：Canvas 2D 的 shadow offset 本來就不受旋轉影響（Konva 只換算縮放），畫布不用額外處理。PDF / EPUB 是在旋轉後的框裡畫，所以匯出時把偏移量反向旋轉成物件內的座標（Rust render.rs 算一次，PDF 與 EPUB 共用），三邊才會一致。步驟 4 用旋轉 30° 的文字疊圖驗證。
  • 文字編輯中的 textarea（text-editor-overlay.tsx）也要套 font-style / text-decoration，輸入時看到的樣子才一致。
  • 斜體的右上角會略為超出文字框（字形往右傾）；畫布、PDF、EPUB 都不裁切，和現在「超出照常顯示」一致。

步驟 4：匯出 PDF 完成 2026-10-05

確認的數字（Konva 10.5.0 原始碼 Text._sceneFunc；斜率以瀏覽器實測）：

  • 底線中心 = 基線 + round(字級 / 4)；刪除線 = 基線 − round(字級 / 4)；線粗 字級 / 15；長度 round(該行寬)，起點是該行的對齊位移；butt 端點。
  • 每行順序：底線 → 文字 → 刪除線。
  • 有線又有陰影時 Konva 改用 buffer canvas：整段文字畫好後投一個陰影在最下面；沒有線時每行各自投陰影、緊接在該行之前。
  • 模擬斜體：以基線為軸，每升高 1 往右 0.25（Skia 的 −1/4 斜切），五種字型、一般 / 粗體實測都是 0.25。
  • 陰影透明度 = 陰影色的透明度 × 文字顏色的透明度（canvas 陰影取被畫內容的 alpha）。

實作：TextLayout 加 lineWidths（Konva 量的行寬；TS 必填、Rust #[serde(default)]，舊的 request 沒有時線畫滿文字框，長度不符就拒絕）；render.rs 的 RenderText 加 italic、decorations（decoration_lines 照上面的公式算）、decoration_thickness、shadow（RenderShadow：偏移反向旋轉成文字框座標、alpha 相乘、whole_block），文字物件與圖形內文字共用 render_text；SYNTHETIC_ITALIC_SLANT = 0.25；template.typ 的 text-line（skew）/ decoration / line-parts。

驗證：Rust 96 個通過（新增：線的位置與長度、陰影方向與 alpha、圖形內文字、行寬驗證；Typst 點陣圖量斜體斜率、線的位置、陰影位置）。畫布與 export_preview 疊圖（2 px/pt，四個物件：粗斜體 + 兩種線 + 半透明陰影、明體斜體旋轉 30°、楷體底線靠右三行以上、圓體刪除線旋轉 −15° 負偏移陰影）：文字、線、陰影的墨跡外框都相差 ≤ 0.5 pt。

已知限制：半透明陰影在「有線」的文字上，線的陰影和字的陰影重疊處 PDF 會比畫布深（Konva 把整段陰影當一層畫；Typst 沒有群組透明度）。測試頁約 4% 的陰影像素。不透明陰影完全一致。

  • 從 Konva 原始碼確認斜切比例、底線 / 刪除線的位置與線粗，前後端各定義一份常數並加測試。
  • 驗證：export_preview 點陣圖與畫布疊圖比對（目標和現在一樣 ≤ 0.5 pt），含旋轉 30° 的陰影文字。

步驟 5：匯出 EPUB 完成 2026-10-05

做法（和計畫不同處）：三種效果都不交給閱讀器自己決定，畫法和 PDF 用同一份 render model。

  • 斜體：每一行 transform: skewX(-14.0362deg)，transform-origin 在基線（第一行基線距離 = Konva 量的 baseline，和 CSS 行框的基線公式相同）。不用 font-style: italic：模擬斜體的斜率由閱讀引擎決定，不保證是 0.25。
  • 底線 / 刪除線：絕對定位的 <span class="d">，位置與長度直接用 RenderText.decorations（CSS text-decoration 的位置由字型決定、刪除線無法指定位移）。
  • 陰影：文字用 text-shadow（不複製文字，搜尋、選取、朗讀不會出現兩次），偏移用文字框座標；線的陰影是 .d.s，z-index: -1 畫在這段文字底下（.t 加 z-index: 0 自成一層，不影響物件之間的順序）。

驗證：Rust 97 個通過（新增 EPUB 標記測試：text-shadow、skewX 與 origin、8 個線 / 線陰影的位置、文字只有原本兩行）。用步驟 4 的同一頁做 EPUB，無頭 Edge 以 2 px/pt 截圖和畫布比對：四個物件的文字 / 線 / 陰影墨跡外框相差 ≤ 0.5 pt（明體旋轉的一個邊 1 pt）；粗字的重疊率 0.8–0.9，細筆畫（明體、楷體）0.45，是 HTML 文字和 canvas 文字反鋸齒不同造成的次像素差，疊圖看不出位移。

已知限制：和 PDF 相同，半透明陰影在有線的文字上，重疊處會較深；行與行的陰影若重疊（負的垂直偏移），HTML 是逐行畫陰影，和畫布「整段一層」的順序可能不同。

  • epub/xhtml.rs 的 text()：font-style、底線 / 刪除線、text-shadow（8 位 hex 照既有規則轉 rgba()）；css.rs 的 .t { font-style: normal } 要讓斜體能覆寫。
  • 驗證：epub_preview 用無頭 Edge 開啟，和 PDF 點陣圖比對。
