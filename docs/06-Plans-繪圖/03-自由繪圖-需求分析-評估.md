# 自由繪圖（線條與箭頭）可行性評估

> 任務檔：`03-自由繪圖-需求分析。.md`（2026-10-15）。本文件只做評估與分步規劃，**還沒有改程式**。
> 前一份評估：`01-繪圖-評估.md`（圖形庫；當時決定「線條 / 箭頭物件之後另開任務；連接線不做」，本文件就是那個任務）。
>
> 結論先講：**可行**。需要新增一種物件類型 `line`（以端點定義，不是外框），但**匯出端幾乎不用新寫**：圖形庫已經做好「前端算路徑 → Rust 只畫」的管線，線條在匯出時展開成「虛擬圖形」（和頁碼同一招），Rust 的 render / Typst 模板 / EPUB 標記都不用認識線條。主要的新工作在**畫布的編輯行為**（端點把手、建立工具）。

---

## 1. 需求理解

任務檔的「參考文件」列了三組東西，對應到軟體功能：

| 參考文件 | 項目 | 對應的功能 |
|---|---|---|
| 1. 幾何與方向 | 水平線、垂直線、斜線 | **直線**（兩個端點）；Shift 限制 0° / 45° / 90° |
| | 曲線 | **曲線**（有控制點的線） |
| | 折線 / 鋸齒線 | **折線**（多個端點）；「鋸齒線」可以是使用者自己點出來的折線，或是一種「線的花樣」（見 Q5） |
| 2. 線型 | 實線、虛線、點線 | 已有（`Stroke.dash` 的 `solid` / `dashed` / `dotted`） |
| | 點劃線 | **新的虛線樣式** `dashDot` |
| | 雙實線 | **新的線型**：兩條平行線（見 R6） |
| 3. 箭頭 | 單向 / 雙向 | 線的**起點 / 終點**各自選箭頭 |
| | 開放式（`>`）/ 閉合實心 | **箭頭樣式**：開放、實心三角（另可加圓點、菱形、短橫） |
| | 彎曲 / 循環箭頭 | 曲線 + 箭頭（循環 = 接近整圈的曲線） |
| | 分支 / 分叉箭頭 | 不是一條線：建議做成圖形庫的框型圖形，或用兩條箭頭組合（見 Q7） |

**目標**：使用者能在畫布上畫出上面這些線條，設定線型、粗細、顏色與兩端的箭頭，並且 PDF / EPUB / 翻頁書輸出和畫面一致。

任務檔標題是「自由繪圖」，但內容全是線條與箭頭；**用鉛筆隨手畫（freehand）**沒有出現在參考文件裡，是否納入見 Q1。

## 3. 建議的設計

### 3.1 文件模型：新增物件類型 `line`（檔案格式 v15）

線不是「外框裡的圖形」：兩端可以自由拖、外框可以是 0 高（水平線），所以**不能**塞進 `ShapeGeometry`（圖形庫評估 §7-3 已經做過這個判斷）。

```ts
export type LineArrowhead = "none" | "open" | "triangle";   // 第一批；之後可加 "circle" / "diamond" / "bar"

export interface LineEnd {
  readonly arrowhead: LineArrowhead;
  /** 箭頭大小 = 線寬 × size（PowerPoint 的小 / 中 / 大），跟著線寬變。 */
  readonly size: number;
}

export interface LineElement extends BaseElement {
  readonly type: "line";
  /** 端點，相對於 (x, y)；(x, y) = 外接框左上角（和其他物件同一個慣例）。 */
  readonly points: readonly LinePoint[];
  /** straight = 依序連直線（2 點 = 直線，3 點以上 = 折線）；curve = 平滑曲線（見 Q2）。 */
  readonly curve: "straight" | "curve";
  readonly stroke: Stroke;           // 線一定有線型（不可 null）
  readonly start: LineEnd;
  readonly end: LineEnd;
}
```

- **(x, y) 仍是外接框左上角**：圖層、框選、捲動範圍、跨頁、尺規都靠外框運作，維持同一個慣例就不用改它們。端點改變時由 reducer（或建立 patch 的純函式）重新正規化：外框左上角移到 `(x, y)`、`points` 平移。
- `rotation`：模型保留（`BaseElement`），**UI 不提供旋轉**（直線的角度由端點決定）；畫布與匯出照常套用，MCP 給的旋轉也畫得對。
- 檔案驗證（TS / Rust 同規則）：2–N 個點（上限例如 500）、座標有限、`stroke` 照既有規則、`size` 範圍、`arrowhead` 列舉。

### 3.2 線與箭頭的路徑：一個純函式，三端共用

`lib/editor/line-path.ts`：

```ts
linePath(line) → {
  stroke: PathCommand[];   // 線本身（開放路徑；有實心箭頭的一端縮短到箭頭底邊，線頭才不會從尖端冒出來）
  heads:  PathCommand[];   // 實心箭頭（封閉，填線的顏色，不描邊）
  openHeads: PathCommand[];// 開放箭頭 ">"（只描邊，實線，不跟著虛線）
}
```

- 箭頭**尖端剛好在端點上**（PowerPoint 的做法），方向取線段在端點的切線（曲線用控制點方向）。
- **箭頭永遠是實線**：線是虛線時，頭部不能被切斷。
- 曲線：`curve` 模式用 Catmull-Rom → 三次貝茲（只輸出 C），所以三端只看到 M / L / C / Z（圖形庫已驗證過這四種三端一致）。
- 外接框：`pathBounds`（曲線的真正極值），**不含**線寬與箭頭（和圖形「邊框不算進外框」一致）。

### 3.3 畫布

- 用 `Konva.Path`（`data = pathData(...)`）畫 `stroke` / `heads` / `openHeads` 三個節點，包在一個 Group 裡。**不用 `Konva.Arrow` / `Konva.Line` 的 `tension`**：它們的箭頭形狀與曲線公式在 Rust 端要再寫一份，而且畫布和輸出就不一定一樣——重用「同一份路徑」比重用 Konva 現成元件更重要。
- **命中**：細線很難點到，`hitStrokeWidth` 至少 8 螢幕 px（÷ zoom）。
- **單選一條線**：不用 Transformer 的八個控制點，改畫**端點把手**（每個點一個圓點；曲線另有控制點）。拖把手 = `startPointerDrag`，放開才一次 `element/update`（一筆復原）；Shift 限制 0° / 45° / 90°；開吸附時端點吸附格線。
- **拖整條線**：照既有的節點拖曳（`handleMoveEnd`、多選整組移動、跨書背換頁都不用改）。多選時 Transformer 本來就只能移動。
- 雙頁跨書背：`spilloverInto` 用外框判斷，線條自動有複本。

### 3.4 建立工具與 UI

- **底部工具列**加「線條」工具（快捷鍵建議 `L`），旁邊的選單選「直線 / 箭頭 / 雙向箭頭 / 折線 / 曲線」（同「圖形」的最近用過）。直線：按下 = 起點、放開 = 終點（點一下 = 預設長度的水平線）；折線 / 曲線：逐點點擊，雙擊或 Enter 結束、Esc 取消。
- **屬性面板**「線條」分頁：顏色、粗細、線型（實線 / 虛線 / 點線 / 點劃線 / 雙線）、起點箭頭、終點箭頭、箭頭大小；「調整」分頁：X / Y、直線多一組「長度 / 角度」。對齊內容區：水平線的「填滿寬度」= 內容區寬的分隔線（雜誌最常用的一種線），「填滿高度」只給垂直線。
- **「繪圖」面板**（目前是佔位卡片）：放常用組合（實線、虛線、點劃線、雙線、單向 / 雙向箭頭、開放 / 實心箭頭、曲線箭頭…），點一下放到頁面中央，圖示由 `linePath` 畫。
- 圖層面板 icon、`describeElement`、MCP（`add_line` / `update_element` 支援線條）。

### 3.5 匯出：線條 → 虛擬圖形（Rust render 不改）

`buildExportRequest` 在展開主頁 / 跨頁之後，把每條線換成：

1. 線本身：`shape`（`geometry: preset`、保留的 id，例如 `x-line`；填色透明；`stroke` = 線的 stroke；`shapePaths` 的 `outline` = 開放的線路徑、`details` = 開放箭頭、`detailStroke` = 同色同寬的實線）。
2. 實心箭頭（有的話）：另一個 `shape`，填色 = 線的顏色、沒有邊框、`outline` = 頭部路徑。

和頁碼一樣只在匯出的副本，不寫回文件。PDF / EPUB / 翻頁書都經過既有的 `render_path`，**不用改 `template.typ` 與 `markup.rs`**。Rust 端只需要：`format.rs` 認得 `line`（存檔 / 開檔驗證、`SCHEMA_VERSION` 15），`build_render` 的 `Element::Line` 分支（匯出請求裡不會出現，回報錯誤即可）。

## 4. 規劃檢核：可能出問題的地方

| # | 風險 | 影響 | 對策 |
|---|---|---|---|
| R1 | 新物件類型要改的地方很多（CLAUDE.md「新增物件類型」清單：union、`localBounds`、renderer、`StaticElement`、`bakeTransform`、`TRANSFORMER_OPTIONS`、`describeElement`、圖層 icon、屬性面板 `tabsOf` / `elementName`；Rust `format.rs`、`build_render`） | 漏改 | 都是 exhaustive switch / mapped type，**漏改會編譯失敗**；`template.typ` / `markup.rs` 因為走虛擬圖形，不用改（這正是不會「靜默不畫」的原因）。 |
| R2 | 水平 / 垂直線的外框寬或高是 0 | `MIN_ELEMENT_SIZE_PT`、除以寬高的地方（content-align 的比例、縮圖縮放）、Rust 圖形尺寸驗證可能拒絕 0 | 線條不經過 Transformer（不受最小尺寸限制）；逐一檢查 `geometry.ts` / `content-align.ts`；**虛擬圖形的外框給線的外接框各邊外擴（例如半個線寬 + 箭頭），一定大於 0**，路徑座標照舊相對於 (x, y)。 |
| R3 | 虛擬圖形用了「圖形庫裡不存在的 preset id」 | `skippedShapeCount` 會把它算成「不認得的圖形」而提示略過 | 保留 id（`x-line` / `x-line-head`）不放進 `SHAPE_LIBRARY`。`skippedShapeCount` 本來就只數「`shapePaths` 裡沒有的」preset（已確認），虛擬圖形一定帶路徑，不會被算進去；補一個測試守著。 |
| R4 | 線帽（line cap）：圖形邊框固定 butt（點線是 round） | 粗線的端點是平的；有些人想要圓頭 | 第一批照既有規則（三端已一致）；線帽選項另排（要改 Rust stroke、Typst、SVG 三處）。 |
| R5 | 折線的尖角（miter）：圖形庫踩過「原路折返的尖角 miter 無限長、三端截斷不同」 | 鋸齒很尖或使用者折回原路時，三端不同 | miter limit 已在三端統一為 10；超過時三端都換成 bevel，**一般角度一致**；在測試與疊圖加一個很尖的折線案例，必要時把線條的 join 固定成 round（只影響線條）。 |
| R6 | **雙線**：兩條平行線 = 路徑的偏移（offset） | 直線、折線的偏移容易（每段平移 + 角點交會）；**曲線的精確偏移很難** | 建議雙線只給直線 / 折線（曲線選雙線時停用並提示）；或 Q4 決定先不做雙線。不要用「粗線再疊一條背景色細線」的假雙線：背景不是單色時會穿幫，透明度也錯。 |
| R7 | 點劃線要改 `Stroke.dash` 的列舉 | 圖形邊框也會多一個選項；Rust `dash_pattern`、驗證、MCP schema、TS `dashPattern` 一起改 | 是小改動，而且圖形也受益。放在最前面（步驟 0），順便驗證三端虛線位置。 |
| R8 | 選取外框不含箭頭與線寬 | 框選要包住線的端點而不是箭頭外緣；粗線對齊內容區時線寬會凸出半個 | 和圖形「邊框畫在外框中心」同一個規則，先接受並寫進文件；若使用者在意，對齊時再加半個線寬。 |
| R9 | 端點把手和現有的 Transformer / 框選 / 平移 / 右鍵選單的事件互動 | 點把手時誤觸框選或拖整條線 | 把手在 Konva 層 `cancelBubble`；建立 / 手形工具照舊在 capture 階段攔下；用無頭 Edge 腳本驗證（同之前的做法）。 |
| R10 | 文字樣式、色票、字型的「走過所有欄位」函式 | 線的顏色沒被色票改色 | `mapColorSlots` 加線的 `stroke`（fixture 的連結數測試會提醒）；線條沒有文字與字型。 |
| R11 | 曲線的編輯方式 UX 不容易一次做好 | 返工 | 分步：直線 → 折線 → 曲線，曲線放最後並先和使用者確認操作（Q2）。 |

| R12 | 鉛筆筆觸點很多 | 檔案變大、拖把手時把手太多、畫布變慢 | 存檔前一定先簡化（RDP），並設點數上限；鉛筆線單選時只畫頭尾把手（中間點不畫），要細修就重畫。 |

沒有發現「做不到」的地方。最大的工作量在畫布編輯（R9、R11），不是輸出。

## 5. 分步規劃（一步一步，不一步到位）

每一步都能單獨驗收、可以停下來。

| 步驟 | 內容 | 驗收 |
|---|---|---|
| 0 | **點劃線**：`Stroke.dash` 加 `dashDot`（TS `stroke.ts` / `validation.ts`、Rust `format.rs` / `render.rs`、Typst / SVG dash、`StrokeFields`、MCP schema）。圖形邊框立刻可用 | vitest、cargo test；`export_preview` 疊圖：點劃線矩形三端 ≤ 0.5 pt |
| 1 | **模型**：`LineElement`（先只有 `straight`）、`LineEnd`；TS 驗證、Rust `format.rs`、`SCHEMA_VERSION` 15、fixture 加一條箭頭線、`mapColorSlots`、`docs-website/types.html`；所有 exhaustive switch 先放最小實作 | vitest + cargo test 讀同一份 fixture |
| 2 | **路徑**：`line-path.ts`（直線、三種箭頭、實心箭頭縮線、外接框） | 純函式測試（尖端在端點、虛線時頭部是實線、0 高外框） |
| 3 | **畫布顯示與選取**：Group + `Konva.Path`、`hitStrokeWidth`、選取 / 框選 / 拖整條、圖層 icon、主頁 / 縮圖 / 跨頁複本 | 無頭 Edge：點選細線、框選、拖曳、復原 |
| 4 | **端點編輯**：端點把手、Shift 角度限制、吸附格線 | 無頭 Edge：拖端點、一筆復原、0° / 45° / 90° |
| 5 | **建立工具**：底部工具列「線條」、`L` 鍵、拖曳建立、點一下 = 預設長度 | 人工 + 無頭 Edge |
| 6 | **屬性面板**：線條分頁（顏色、粗細、線型、兩端箭頭、大小）、長度 / 角度、對齊內容區（填滿寬度 = 分隔線） | 測試 + 人工 |
| 7 | **匯出**：`buildExportRequest` 展開成虛擬圖形 | `export_preview` / `epub_preview` 疊圖 ≤ 0.5 pt（含虛線、箭頭、旋轉、跨頁） |
| 8 | **折線**：逐點建立、每個端點把手、加 / 刪點 | 同步驟 3–7 的驗收補折線案例 |
| 9 | **曲線**：`curve` 模式（Catmull-Rom → 貝茲）、建立與控制方式（依 Q2 決定） | 同上補曲線案例；曲線箭頭的方向 |
| 9.5 | **鉛筆**（Q1 決定這次做）：鉛筆工具記錄滑鼠軌跡 → 以螢幕 px 為容差簡化點（Ramer–Douglas–Peucker，純函式）→ 存成 `curve` 模式的 `line`（預設沒有箭頭）；點數上限內才存，超過時加大容差再簡化。編輯照折線 / 曲線的端點把手 | 純函式測試（簡化後點數、端點保留）；無頭 Edge 畫一筆、復原；疊圖 |
| 10 | **「繪圖」面板**：常用線條 / 箭頭組合 | 人工 |
| 11 | **MCP**：`add_line`、`update_element` 支援線條、`list_elements` 回報 | `mcp-tools.json` 快照、MCP 實測、更新 `MCP-工具清單.md` |

## 6. 設計建議

1. **線條是新物件類型，不是圖形庫的圖形**。圖形庫已經有「粗箭頭 / 雙向粗箭頭 / 五邊形箭頭」這類**填色的框型箭頭**（適合當標題裝飾），和這次的「線 + 箭頭頭部」是兩種東西，兩者並存。
2. **畫布與輸出用同一份路徑**（`line-path.ts`），不用 `Konva.Arrow`：這是本專案「所見即所得」的核心，比省下幾十行 Konva 程式重要。
3. **匯出走虛擬圖形**（頁碼的做法），Rust 的 render、Typst 模板、EPUB 標記都不用改，日後加箭頭樣式也只改 TS。
4. **雜誌最常用的是「分隔線」**：水平線 + 屬性面板「填滿寬度」= 一鍵畫出內容區寬的分隔線，建議放進「繪圖」面板的第一個。
5. **分叉箭頭**做成圖形庫的框型圖形（一筆定義，像現有的粗箭頭），比做「會分叉的線」簡單且好看；流程圖的分支用兩條箭頭線即可。
6. **雙線不要用假雙線**（粗線疊背景色細線），背景是圖片或漸層時會穿幫；做就做真正的兩條偏移線。
7. 參考對象：**PowerPoint 的線條**（端點把手、箭頭大小 = 線寬倍數、尖端在端點）與 **Affinity 的線條樣式面板**，比 draw.io 的連接線更貼近排版需求。
